# 网站与 443 入口

在「域名与证书 → 网站与 443 入口」配置同一节点上的网站、管理后台、订阅和 CDN 节点。使用现有 Agent Caddy 统一回源，公网 HTTPS 443 由一个 Caddy 实例监听。

## 配置

1. 同时更新面板和目标 Agent。节点需上报 `unified-web-entry-v1`；旧 Agent 会拒绝含网站的新配置，保留原运行配置，不会静默忽略网站。
2. 准备覆盖网站域名的证书，在证书页面导入或通过 ACME 签发。选择目标节点、域名、证书和网站路径（默认 `/`）。
3. 选择网站托管方式：
   - **静态网站**：上传 ZIP，根目录包含 `index.html`。最多上传 4 MiB，解压后最多 8 MiB、2048 个文件。支持 HTML、CSS、JS、图片等静态资源，不执行 PHP 等服务端程序。拒绝越界路径、隐藏文件、符号链接、重复文件、目录冲突和超限解压。
   - **本机服务**：填写目标节点上的 HTTP 回环地址，如 `http://127.0.0.1:3000` 或 `http://[::1]:3000`。不接受 DNS 名称、内网其他机器或入口自身的端口。Docker 服务需要将端口发布到宿主机回环地址。
4. 若面板与节点同机，可填写面板的 HTTP 回环地址，例如 `http://127.0.0.1:8080`。选择要转发的后台、订阅和用户中心路径。后台路径必须与系统「面板访问」设置一致，根路径后台需先改为私密路径；订阅 `/sub` 和用户中心 `/u` 保留实际路径，避免破坏页面资源和接口。开启后台时会同时转发安装脚本、入网和下载路径；开启用户中心时会同时转发商店、支付回调和状态页依赖，预览会列出这些路径，服务本身仍遵循原有开关和权限。面板在其他服务器时留空。
5. 要共用节点入口，先在入站中绑定同域名的 HTTPS CDN 配置档，并开启「Agent 内置 Caddy 统一回源」。预览自动列出该节点、域名和 443 的有效入站，支持修改节点路径。保存会同步更新入站及已有路径覆盖，模板入站的相应字段会标记为手动修改；客户端需更新订阅。
6. 点击「检查冲突并预览」，检查完整路由，再「保存并发布」。修改表单后必须重新预览。

路径不能相同或互相包含；网站根路径 `/` 作为最终兜底，其他入口优先匹配。网站放到 `/blog` 时，访问 `/blog` 会跳转到 `/blog/`，转发本机博客时移除 `/blog` 前缀，程序生成的资源地址仍需支持此部署方式。

## 应用与端口

预览检查证书域名、有效期、路由重叠、443 入站/转发占用，并在节点在线时查询系统端口。端口检查是当前快照，不能保证保存后无人抢占；最终由 Agent 在变更服务前检查实际占用，Caddy 校验通过后再应用。离线节点显示待确认，升级后上线领取配置。

已有 Nginx、宝塔、面板独立 Caddy 或 REALITY TCP 443 不能同时绑定该端口，应先统一入口。此功能不自动接管或停止外部服务，不修改 Cloudflare DNS，也不改变 Agent 的独立 mTLS 接入。

静态文件使用内容摘要目录，先写完整新版本，再供 Caddy 校验和加载。失败沿用现有 Agent 配置回滚机制，旧文件版本保留以支持回滚；这些历史静态目录不会自动清理。网站文件随数据库逻辑备份导出和恢复。列表接口不返回文件内容，证书私钥只在现有加密存储和节点认证配置通道中流转。

列表显示节点配置应用状态；「已应用」代表节点配置已落地，不代表 DNS、Cloudflare 或完整代理业务已验收。部署后应分别访问网站、后台、订阅和真实节点客户端。

停用或删除网站入口会移除其网站、后台、订阅转发规则，已有 CDN 入站继续按原来的统一回源配置运行。证书续期会通知使用它的网站节点；仍被网站引用的证书不能删除。
