# CDN 固定优选 IP 与域名

进入「链路与路由 → CDN 配置档」，选择配置档，在「优选地址与订阅预览」卡片点击「维护地址」。一行填写一个公网 IPv4、IPv6 或完整域名，例如 `104.16.1.1`、`2606:4700::1111`、`best.example.com`，不带 `https://`、端口、路径或通配符。保存时自动去掉首尾空白，域名去掉末尾句点并转为小写；IP 按标准格式归一化，IPv4 映射的 IPv6 转为 IPv4，然后去重。带方括号的纯 IPv6 地址也可填写，但不能附带端口。回环、内网、链路本地、带接口区域的 IPv6、组播和未指定 IP 会被拒绝。新建和编辑配置档也有独立的同名输入框。

固定地址只属于当前配置档，不会随着 Cloudflare 共用测速点传播到其他配置档。测速点上报和来源 URL 刷新会保留这些地址；即使 URL 拉取过程中修改了固定列表，拉取完成后也会使用最新固定列表。维护地址只提交固定列表，不会提交浏览器中可能已过时的测速结果或其他配置。

需要在配置档的「编辑」中开启「订阅按优选 IP 展开（一个 IP 一个节点）」，固定 IP 和域名才会作为订阅连接地址使用。若「订阅取前 N 个」大于 0，固定地址追加到前 N 个自动地址后，不占用 N 的名额；TLS SNI 和 HTTP Host 仍使用对应入口的回源域名。入口显式指定了连接地址时保留原有行为，不按优选列表展开。开启节点检测时，固定地址也遵循现有的可达性筛选。

从列表删除或清空后保存即可取消手动保留。如果该地址仍出现在来源 URL 中，下次自动刷新可能再次带入，但不会自动变成手动保留项。测速点、来源 URL、固定地址和禁用项统一显示在地址表中；「临时优选地址」输入框内的内容仍可能被自动更新替换。

## API

管理员可调用 `PUT /cdn-profiles/:id/pinned-hosts`：

```json
{"pinnedHosts":["104.16.1.1","2606:4700::1111","best.example.com"]}
```

传 `{"pinnedHosts":[]}` 清空固定列表。省略字段、传 `null` 或非法地址会返回 400，不修改原列表。只有原有配置管理权限的管理员可维护；仅有 `cdn:ips:write` 权限的测速令牌不能修改固定地址。

新建或完整编辑配置档也接受显式的 `pinnedHosts` 数组。未提供该字段的旧客户端仍按原有混合列表规则识别新手填域名；已固定的 IP 保持固定，但不会把旧临时 IP 自动升级为固定地址，无需新增数据库迁移或更新 Agent。`pinnedHosts` 字段及 `/pinned-hosts` 路径沿用原名以兼容现有 API 和备份，内容现在同时接受公网 IP 和域名。固定地址也遵循当前端口的可达性筛选；固定仅保证不被自动来源覆盖，不保证地址永远可用。

## 重复测速结果

同一次测速上报中，同一 IP 的不同文本形式归一化后去重，保留丢包率最低的一条；丢包率相同时优先下载速度更高，再比较延迟。最终排序使用相同规则，避免上报顺序使较差结果覆盖较好结果。完全相同的评分保留先上报的一条，机房代码随被选中的完整结果保留。


## 地址策略与订阅预览

选择当前配置档关联的启用入口和运营商，预览会调用与真实订阅相同的入口展开逻辑，展示实际客户端端口、SNI、Host、路径及选用地址。预览不使用用户凭据。固定地址仍受当前端口的节点检测筛选；全体不可达时保留候选，但禁用项永远不会因这种保留机制恢复。关闭订阅展开或入口显式指定连接地址时，预览按相同规则显示。

地址表显示 IPv4 / IPv6 / 域名、固定或自动来源、匹配端口的测速点、最新上报时间、延迟、丢包和速度。该端口没有匹配测量时不冒用其他端口的成绩。运营商分流未开启时，选择运营商仍使用合并列表。

点击「禁用」或在「地址策略」内维护禁用列表。支持精确 IP / 域名，域名大小写和末尾句点归一化，等价 IP 格式统一匹配；不是通配符、CIDR 或解析后 IP 封禁。为兼容旧来源，可禁用私有地址。**禁用优先于固定地址、自动测速、来源 URL、显式入口地址和全体不可达保留**。这只影响当前配置档的 CDN 入口；直接入口和其他配置档不受影响。恢复后重新参与正常选择，不能保证一定入选。

测速结果超过配置档的上报告警小时数（默认 24 小时）后，可选择：

- `source`：默认。没有新鲜测速结果时，自动维护尝试来源 URL；拉取失败保留旧列表并显示错误。没有 URL 时继续保留旧列表。首次过期检查每小时执行，来源维护每 6 小时重试。
- `keep`：已有测速报告时保留旧结果，包括各端口、各运营商的最后列表，等待测速恢复；不自动用来源 URL 替换。只有来源 URL、尚无测速报告的配置仍按原计划刷新。

新的测速上报会优先恢复选用，清除过期告警状态。备用 URL 请求期间收到的新鲜报告、固定地址或策略变更会受到事务保护；旧的自动拉取结果不能覆盖新的测速结果。手动「刷新」是明确的来源 URL 覆盖操作，仍保留固定地址和禁用规则。

## 分阶段地址检测

每个地址可使用所选入口的真实协议、端口、SNI、HTTP Host 和路径检测。结果区分入口域名解析、优选域名解析、TCP、TLS、HTTP 响应和传输握手，展示解析得到的 A / AAAA 和实际连接对端。使用 IP 时跳过地址解析，HTTP 跳过 TLS；未执行阶段明确标为未测试。DNS 列表是解析快照，不表示逐个测试了所有解析结果。

检测来自**面板网络**，不是节点或用户网络。WebSocket / HTTPUpgrade 的 101 必须通过握手头校验；gRPC / XHTTP 的普通响应只产生部分结果。检测不包含代理认证、HTTPS 业务、上下行或 UDP，不会扣用户配额，明确检测失败的地址会从对应入口的订阅排除，重新检测通过后恢复；未检测或只完成部分检测的结果不视作明确失败。

每个配置档保存最多 64 条最近详细结果。明确失败另存精简状态，不会因详细结果被挤出历史或超过 30 分钟而重新进入订阅。入口协议、安全配置、端口、SNI、Host 或路径变化后不复用旧结论；超过 30 分钟在页面标注结果较旧。需要时手动重新检测。

## 管理 API 补充

- `GET /cdn-profiles/:id/address-tools?endpoint=<入口 ID>&carrier=ct|cu|cm`：候选元信息、真实订阅选用预览和匹配入口的历史检测。两个查询参数均可省略。
- `POST /cdn-profiles/:id/check-address`：`{"endpointId":"入口 ID","address":"已保存的候选地址"}`。仅能检测本配置档保存的候选或入口目标，返回 `viewpoint: "panel"`、`businessVerified: false` 与分阶段结果。
- `PUT /cdn-profiles/:id/address-policy`：`{"blockedHosts":["104.16.1.1","bad.example.com"],"stalePolicy":"keep"}`。必须明确提供数组和 `keep` / `source`；空数组清空禁用规则。完整配置编辑也接受这两个可选字段，旧客户端省略时保留当前策略。

这些接口使用配置管理权限，仅有 `cdn:ips:write` 的测速令牌不能读取诊断、发起检测或修改策略。新增字段随备份恢复保留；旧备份默认没有禁用项并使用来源回退策略。此功能更新面板和测速插件即可，不需要更新 Agent。

## 用户自选省份／运营商与个人优选地址

用户不需要自行部署测速程序。打开用户中心 `/u`，展开 **「维护个人优选 IP／域名」**，选择本人有权限使用的 CDN 配置，一行填写一个公网 IPv4 / IPv6 或完整域名，最多 32 个。保存后更新客户端订阅即可；留空保存恢复共享选择。个人列表按用户与配置档分别保存，不修改公共测速结果、管理员固定地址或其他用户的订阅。

个人列表替代本人该配置的公共优选候选，保留填写顺序，不受公共自动列表 Top N 限制；仍遵循配置档的禁用、可达性与入口规则。管理员未开启订阅展开、入口显式指定连接地址时，个人列表不生效。个人地址不在面板上主动测速，也不改变代理账号、访问权限、端口、SNI 或 Host。

共享结果分配在 CDN 配置编辑中的 **「优选地址分配」** 选择：合并列表、按运营商、按省份／地区＋运营商。旧配置保持原模式。地区模式下，用户中心可以选择省份和运营商，也可选择自动识别：

1. 用户有个人列表时，先用个人列表。
2. 已知省份与运营商时，先用相同省份、相同运营商的测速点结果。
3. 本省没有匹配结果时，回退到该运营商其他地区的结果；仍无结果则用合并或保留列表。
4. 仅地区已知时可使用该地区各运营商的合并结果；两者都未知则使用总合并列表。

筛选始终先隔离 HTTP / HTTPS 和实际客户端端口，再应用地区和运营商、禁用及 Top N 规则。固定公共地址按原规则追加；启用个人列表时使用个人候选。过期结果是否可用，继续遵循配置档的失效策略。

自动省份识别复用已启用的离线城市 MMDB，运营商识别复用 ASN 数据库。没有数据库、IP 未匹配，或经代理更新订阅时，可能无法识别用户实际网络；可在用户中心手动选择。中国大陆按省份匹配，其他国家／地区按两位代码匹配，不猜测城市。管理页的订阅预览显示地区匹配及回退状态；用户中心按配置显示默认端口的选择说明。

测速点上报增加 `region`，例如 `{"source":"上海电信-443","region":"CN-31","carrier":"ct","scheme":"https","port":443,"ips":[{"ip":"104.16.1.1"}]}`。可填写省份中文／英文名称，面板统一成代码。旧报告省略地区时从「上海电信」等测点名称前缀识别；不能识别的继续参与全国合并。专用配对令牌绑定地区，旧程序省略字段时继承绑定地区，不能显式上报其他地区。名称不代表 CDN 机房所在地，地区指**进行测量的用户侧线路所在地**。

`cf-ip-probe -region CN-31 -carrier ct` 或安装脚本 `--region CN-31 --carrier ct` 设置该测点的地区与线路。先发布新版插件与安装脚本，再运行新面板生成的命令；原服务需重新配对或修改配置后重启。只维护个人地址的用户无需安装插件。

接口：

- `POST /u/region`：`{"region":"CN-31"}`；空字符串恢复自动识别，登录后调用，必须带 `X-Polaris-Portal: 1`。
- `POST /u/cdn-preferences`：`{"profileId":"配置档 ID","addresses":["104.16.1.1","best.example.com"]}`；显式空数组清空，只允许本人有权限使用的配置。
- 订阅链接 `?region=CN-31&carrier=ct` 可临时覆盖地区／运营商；已有查询参数使用 `&`。个人列表仍优先。`auto` 强制自动识别，`all` 不按该维度区分。
- 管理预览 `/cdn-profiles/:id/address-tools` 增加 `region` 查询参数与 `matchMode`；`GET /cdn-regions` 提供规范地区选项。

显式查询选择在浏览器导入链接中保留；外部转换器的短期回调固定原请求已解析的地区和运营商，避免误用转换服务器所在地。个人列表及地区元信息随备份恢复保留，旧备份没有个人列表时沿用共享模式。

## 明确失败的地址不下发

在地址表点击「检测」后，明确失败的地址显示「检测失败，已排除」，不再被对应入口的订阅选用。这一规则同时作用于自动候选、固定地址和用户个人列表，并在 Top N 截取之前执行，失败地址不占名额。所有候选都因此被排除时，不输出该 CDN 入口；不会通过“全体不可达保留”或默认域名兜底把失败候选加回来。显式指定地址、只用回源域名的入口也遵循相同检测规则。

结果精确对应入口 ID、HTTP/HTTPS、实际端口、SNI、Host、路径和入站安全配置。其他入口或端口不受影响；目标设置变化后旧结论不应用于新设置。未检测和只完成部分检测不作为明确失败；已经失败的地址必须重新检测通过才恢复，新的部分结果不足以清除失败状态。

来源刷新、地区／运营商切换、服务重启和详细历史裁剪都不会清除匹配当前入口的失败状态。升级前已保存的明确失败也会用于筛选。检测仍来自面板网络，传输握手成功不代表代理认证或业务请求通过。
