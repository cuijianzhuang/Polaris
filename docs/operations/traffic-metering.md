# 流量计量方式与采集状态

节点详情和内核列表展示计量方式、最后成功采集时间及采集状态。未上报、暂停、近期失败、结果较旧与正常分别显示；心跳在线不代表采集成功。旧 Agent 没有此元数据时保留「未上报」，不能把旧数据或缺失时间当成零流量。

## mihomo：活动连接采样

mihomo v1.19.15 的 `/connections` 只包含活动连接。上游在连接关闭时删除记录，没有可供面板追溯的逐用户关闭计数；全局总量也不能可靠分配给不同用户。

Agent 现在在内核运行期间每秒读取一次活动连接快照，将观察到的增量暂存，按原有流量批次交给持久队列。相比只在默认 10 秒结算周期读取，可覆盖更多在两个结算批次之间已关闭的连接。即使下一次 API 读取失败，已观察到的增量也可交付一次，不会被丢弃或重复结算。异常负值、重复连接 ID 和下降的计数不会产生负扣量或推算补收费；下降的计数建立新基线。

**这仍然是采样，不是精确计量。** 未经过任何快照的短连接、最后快照到关闭之间的尾部字节，以及进程故障等间隔仍可能漏计。用户中心会对使用 mihomo 的订阅提示此限制。需要严格用户账单时，应选择具备逐用户内核计数的适配，而不能把全局流量按比例猜分给用户。

面板不修改用户流量倍率、不补扣估算流量，也不把改进采样包装为「精确」。真正无损的 mihomo 按用户计量需要上游提供可追溯的逐用户累计计数或关闭事件，本次没有修改外部 mihomo 内核。

## 其他内核与状态更新

其他适配上报「内核用户计数」及实际读取的成功／失败时间；不支持用户计量的内核明确显示不支持。方法名称不承诺进程故障或采集链路永不丢数据。

元数据由 Agent 心跳携带。状态切换和首次成功立即写入；连续正常时面板最多每分钟保存一次，以避免每秒写数据库。最后成功时间超过 3 分钟显示较旧，节点离线或内核停止显示暂停。安装更新后的 Agent 才能提供新增元数据。
