# 流量计量方式与采集状态

节点详情和内核列表展示计量方式、最后成功采集时间及采集状态。未上报、暂停、近期失败、结果较旧与正常分别显示；心跳在线不代表采集成功。旧 Agent 没有此元数据时保留「未上报」，不能把旧数据或缺失时间当成零流量。

## mihomo：内核累计计数与原版兼容

原版 mihomo v1.19.15 的 `/connections` 只包含活动连接。上游在连接关闭时删除记录，没有可供面板追溯的逐用户关闭计数；全局总量也不能可靠分配给不同用户。

Agent 现在在内核运行期间每秒读取一次活动连接快照，将观察到的增量暂存，按原有流量批次交给持久队列。相比只在默认 10 秒结算周期读取，可覆盖更多在两个结算批次之间已关闭的连接。即使下一次 API 读取失败，已观察到的增量也可交付一次，不会被丢弃或重复结算。异常负值、重复连接 ID 和下降的计数不会产生负扣量或推算补收费；下降的计数建立新基线。

**这仍然是采样，不是精确计量。** 未经过任何快照的短连接、最后快照到关闭之间的尾部字节，以及进程故障等间隔仍可能漏计。用户中心会对使用 mihomo 的订阅提示此限制。需要严格用户账单时，应选择具备逐用户内核计数的适配，而不能把全局流量按比例猜分给用户。

Polaris 计数构建在固定的 mihomo v1.19.15 提交 `c5fe3670eff8ac030702959099505522aa7c0caa` 上增加逐用户累计计数。补丁覆盖原生 TCP 读写、缓冲与零拷贝回调，以及 UDP 收发和初始缓冲数据；连接关闭后保留累计值，控制器重置全局统计也不会清空这些值。`/connections` 的 `polarisUserTraffic` 扩展携带版本、进程 epoch 和按认证用户划分的累计上下行字节。Agent 按 epoch 与上次读数计算增量，重试不重复结算；同一 epoch 的计数下降或扩展消失会报采集失败，不会静默切回采样。

`.github/workflows/mihomo.yml` 构建 Linux amd64/arm64，发布 `mihomo-v1.19.15`，同时附上完整打补丁源码、GPL 许可证和校验值。Agent 优先安装此构建；该版本已安装原版时，下次启动 Agent 会尝试升级。未发布、校验失败或其他版本保留原版，页面继续显示采样限制。面板根据实际心跳报告的方式显示「内核用户计数」，不会仅根据内核名称推断精度。

这是内核存活期间的累计有效载荷计数，消除了连接快照造成的短连接及尾部遗漏；它不是断电安全的内核账本。内核/Agent 崩溃仍可能丢失尚未送入持久队列的末次增量，匿名或协议未提供用户身份的流量不能凭空归属。内部限速回流及诊断身份仍由 Agent 排除，防止重复扣量或扣到真实用户。面板不修改倍率，不按全局总量猜分或补扣。

## 其他内核与状态更新

其他适配上报「内核用户计数」及实际读取的成功／失败时间；不支持用户计量的内核明确显示不支持。方法名称不承诺进程故障或采集链路永不丢数据。

元数据由 Agent 心跳携带。状态切换和首次成功立即写入；连续正常时面板最多每分钟保存一次，以避免每秒写数据库。最后成功时间超过 3 分钟显示较旧，节点离线或内核停止显示暂停。安装更新后的 Agent 才能提供新增元数据。

## 验证与上游依据

- `scripts/mihomo-meter.patch` 原生竞态回归覆盖并发用户、零拷贝路径、已关闭连接、重复计数隔离和控制器重置；`internal/core/mihomo/native_meter_test.go` 以真实 TLS/VLESS 内核验证已关闭短连接、逐用户隔离、UDP 精确字节、epoch 重启和异常扩展。
- `internal/core/mihomo/meter_test.go` 覆盖已观测短连接关闭后结算、单次交付、失败保留、重复／负值／下降计数和停止采样取消。
- `internal/panel/traffic_meter_test.go` 覆盖心跳入库、失败状态即时更新和旧 Agent 兼容。
- `web/scripts/traffic-meter-ui-smoke.py` 覆盖采样提示、时间、失败、过期和未上报的移动／桌面展示。
