# CDN 的 HTTP 与 HTTPS 节点

在「链路与路由 → CDN 配置档」中新建或编辑配置档，选择「CDN 协议」。该选项控制客户端到 CDN 的连接，独立于 Cloudflare 的回源 SSL 模式。既有配置和不带此字段的旧备份保持 HTTPS；编辑时旧 API 省略该字段会保留当前值。

| CDN 协议 | Cloudflare 支持的端口 | 订阅连接 |
| --- | --- | --- |
| HTTP | 80、8080、8880、2052、2082、2086、2095 | 不使用 TLS，保留入口的 HTTP Host 和路径 |
| HTTPS | 443、2053、2083、2087、2096、8443 | 使用 TLS，入口域名作为 SNI 和 HTTP Host |

切换 CDN 协议后，表单会重置可用端口。可调整端口顺序，第一个是默认连接端口。入站使用该 CDN 协议支持的 Cloudflare 端口时，订阅保持入站原端口；入口显式指定的端口同样按所选 HTTP/HTTPS 端口集合校验。

HTTP 客户端通过 Cloudflare 时，回源也使用 HTTP，关联入站应关闭 TLS。HTTPS 客户端的回源由 Full / Full (strict) / Flexible 决定。HTTP 配置档同步 DNS 只维护 DNS 记录，不修改整个域名的 SSL 模式，也不签发未使用的 Origin 证书。同一域名需要同时提供 HTTP 与 HTTPS 节点时，可以分别建立配置档。

- Cloudflare 的 gRPC 入口要求 **HTTPS + 443**。HTTP 可用于面板支持的 WS、HTTPUpgrade、XHTTP 传输。
- 内置 Caddy 统一回源目前使用 TLS，HTTP 配置档会关闭此选项。
- HTTP 节点依赖不被 Cloudflare 的 Always Use HTTPS 或其他规则重定向。入口检测使用 HTTP 握手，并在被转向 HTTPS 时给出原因。
- 一键配置及新建 CDN 入站会按配置档选择端口与回源安全方式；模板自动分配端口也识别所选方式。

测速结果只在相同 CDN 协议（HTTP/HTTPS）和实际测速端口之间共享。默认优选列表使用配置档第一个端口的结果，其他入口端口优先使用对应端口的测速结果；没有匹配结果时保留现有地址作为未验证的候选，并在入口提示，不会把其他端口的测量当作该端口已通过。切换有测速点的配置档前，需先移除测速点及上报结果，避免将旧协议的测速结果带到新协议中；关联入站的回源安全方式不匹配时也会拒绝切换，可新建配置档并调整入口。

新版 `cf-ip-probe` 支持 HTTP 与 HTTPS。一键安装命令声明 `-scheme`、`-port` 和独立 `--instance`，HTTP 默认测 80、HTTPS 默认测 443。验证、下载和上报使用同一协议与端口；HTTP 被重定向到 HTTPS 不算通过。可关闭下载测速，或提供相同协议的自建下载 URL。节点可达性检查覆盖默认端口和实际入口使用的端口，分别保存不可达地址和检测时间；旧检测结果只适用于默认端口。全体地址不可达时显示不确定结果并保留候选列表。检查受总时间预算限制，未完成端口保留上次结果，下一轮优先检查较旧的端口。

API 字段是 `scheme: "http" | "https"`，适用于创建及完整编辑 CDN 配置档。入口的 `target.scheme` 会返回实际 CDN 协议，订阅、检测与页面展示使用同一规则。

参考：[Cloudflare 支持的端口](https://developers.cloudflare.com/fundamentals/reference/network-ports/)；[Full 模式按客户端协议回源](https://developers.cloudflare.com/ssl/origin-configuration/ssl-modes/full/)。

## 端口与检测结论

普通 Cloudflare 代理不会自动把入站的 31000 端口映射为客户端的 443。新建/更新入口时，未使用 Caddy 的隐式端口回退会被拒绝；旧入口若存在此问题，会提示配置错误并暂停该 CDN 入口的订阅输出。可将入站调整为受支持的端口，或启用可用的 Caddy 统一回源。确实已经在外部配置了 Origin Rules 等端口改写的，应在入口的「端口（可选）」中明确填写客户端端口。该字段声明外部改写，面板不会替用户创建或证明外部规则已生效。

Flexible 的原生例外是 **客户端 HTTPS 443 → 回源 HTTP 80**，不需要外部改写；其他 HTTPS 端口回落到 Full，需要相同端口上的 TLS 回源。一键创建会按实际客户端端口选择回源安全方式。入口的 `target.originPort` 展示实际回源监听端口，故障直连诊断使用该端口。

入口检查先识别 Cloudflare 拦截、认证拒绝、限流、重定向及服务错误。WebSocket 101 响应会校验 Upgrade 响应头与 `Sec-WebSocket-Accept`；通过仅表示传输握手成功，不代表代理凭据、HTTPS 访问或业务流量通过。gRPC/XHTTP 的普通 HTTP 响应返回 `partial: true, ok: false`，页面显示「检测部分完成」。

## 为测速点选择端口

「添加测速点」可以选择端口，生成的命令通过 `--args '-scheme https -port 8443'` 设置。专用令牌同时绑定配置档、名称和端口，其他端口的上报会被拒绝。对绑定端口的令牌，面板能为省略端口字段的旧程序补齐绑定信息。同一台机器测多个端口时，使用不同测速点名称。面板为每个「配置档 + 名称」生成稳定的独立实例名，服务、配置、二进制和自动更新任务互相隔离；同名重新配对更新原实例，并撤销原令牌。

新版测速程序给上报增加 `scheme`、`port`。未标注端口且未绑定端口的旧 HTTPS 上报按历史默认 HTTPS:443 兼容处理，页面标注「旧默认」；这不证明旧程序实际使用了 443，自定义端口的旧测速点应重新配对或更新程序。HTTP 自行上报须明确端口，例如：

```json
{"source":"HTTP-80","scheme":"http","port":80,"ips":[{"ip":"104.16.1.1","latencyMs":20,"loss":0}]}
```

更新顺序：先发布包含 `-scheme` 和 `--instance` 的 polaris-plugins 测速程序及安装脚本，再更新面板。旧安装脚本无法识别新命令的参数。已有服务不会因面板升级自动改成多实例；在面板重新配对并运行命令，确认新实例上报后，再按需卸载旧默认实例。手动固定地址继续保留，各端口的可达性结论只过滤对应端口的订阅地址。
