# 按入站设置出站 IP 策略

> 管理界面入口现已补齐，见[界面接入说明](operations-ui.md)；文中“仅后端/API”是首版交付范围。

参考 FLYX 的出站策略功能语义，实现 Polaris 自己的配置模型、路由和内核适配。本轮仅提供后端/API，现有 UI 不变。

## 用法

先升级节点 Agent，等待它完成一次配置拉取，节点 `agentFeatures` 中应出现 `outbound-ip-v1`。Xray 需要 **26.5.9+**，sing-box 需要 **1.12+**；不支持此功能的内核和旧 Agent 会拒绝配置。

管理员调用以下接口（路径相对于面板 APIBase，默认 `/api/v1`）：

```http
PUT /inbounds/入站ID/outbound-ip
Content-Type: application/json
Authorization: Bearer 管理员登录令牌
```

```json
{"strategy":"prefer_ipv4"}
```

| strategy | 行为 |
| --- | --- |
| `auto` 或空字符串 | 使用内核和系统默认选择，与存量配置兼容 |
| `ipv4_only` | 域名只解析 IPv4，直接请求 IPv6 地址也会拒绝 |
| `ipv6_only` | 域名只解析 IPv6，直接请求 IPv4 地址也会拒绝；节点需要可用的 IPv6 地址和路由 |
| `prefer_ipv4` | 保留双栈解析，TCP 优先 IPv4，连接失败或约 250ms 未连接后尝试 IPv6 |
| `prefer_ipv6` | 保留双栈解析，TCP 优先 IPv6，失败或约 250ms 后尝试 IPv4 |

优先模式直接请求 IP 地址时使用该地址。UDP 按解析结果选址，不因远端静默或业务超时重放数据包。HTTP 错误状态和已经建立后断开的连接不会自动重试到另一种 IP。

入站的监听地址、客户端订阅/分享地址、TLS SNI 和 REALITY 参数均独立于出站策略。链式代理中控制的是本节点实际建立的下一跳连接；最终出口访问目标时的 IP 选择由远端决定。策略不改变节点操作系统、Agent 管理连接或 DNS 服务器自身的网络配置。

新增/修改入站也接受 `outboundIPStrategy`。GET 入站、导入、导出、克隆、模板项生成和同步均保留此字段。旧入站/模板编辑器省略字段时保留已有值；显式设为 `auto` 恢复默认。手工修改已绑定模板的入站会记录独立覆盖项，同步默认保留，需显式选择覆盖才能恢复模板策略。

## 路由、限速和计费

每个启用策略的入站使用独立的出站图，保持路由先后、用户条件、组成员、链式 detour 和均衡器回退关系。共用这些出站的其他入站继续使用原图。内部标签避免成为原有 Xray 前缀选择器的新成员。

Xray 限速器内部改用带身份的 VLESS TCP/UDP 回入，修复原 SOCKS UDP 回入丢失用户身份的问题。sing-box 保留现有带身份的 SOCKS 回入。限速器内部账号携带原入站上下文，回到内核后仍匹配原策略和用户规则；令牌桶与并发额度继续按原用户共享。仅入口用户计入用户流量，限速回入账号和内部回退桥接不重复扣量。内部出站计数汇总回原出站标签，保持原有诊断统计。

## 当前兼容边界

- Xray 26.4.15–26.4.17 的 `/0` IP 匹配会把地址集合误判为空，不能可靠阻止另一种地址族。26.4.25 修复地址匹配；本实现进一步使用 26.5.9 起的 `finalRules`，在路由和 DNS 之后限制地址族，同时保留内核原有的其他默认出口规则。
- 非默认策略不支持可达的 WireGuard 出站；其他不支持的内核也会明确报错。
- 全局 DNS 的 `ipv4_only` / `ipv6_only` 与按入站策略不能混用。改回双栈解析后再设置策略；DNS 配置变更时也会检查现有策略。
- sing-box 当前使用配置中的默认 DNS 服务器，不支持同时启用分流 DNS、Hosts、FakeIP 或路由前预解析（`IPIfNonMatch` / `IPOnDemand`）。这些组合会明确报错，避免绕过已有 DNS 规则。
- sing-box 严格模式暂不支持 detour，或把直连和代理混在同一个可达组/回退图中；纯直连/拦截组和纯代理组可用。它的地址族拒绝规则位于路由阶段，不能对混合组错误地限制代理远端的最终目标。
- 非默认策略不允许用入站高级 JSON 覆盖原生 `tag` / `detour`，以免绕开路由作用域。
- 启用用户限速时须配套更新专业版 Agent 的限速器实现；不支持上下文的旧限速器会拒绝应用，保留原配置。

## 验证

本地受控 DNS 同时返回 `127.0.0.1` / `::1`，分别运行 IPv4、IPv6、单栈 HTTP/UDP 服务，通过真实 VLESS 用户连接真实内核，验证：

- 同一节点五种策略共存时的 TCP/UDP 选址与严格模式拒绝。
- TCP 首选地址族连接失败后的回退，自动模式继续接受两种地址。
- 经专业版限速器后仍保留入站策略，多入口共用同一用户桶。
- Xray 的原用户上下行计数在不同策略、经过限速器前后相同，不把内部账号重复计费。
- 模板同步与手动覆盖、旧编辑器保存、导入导出/克隆，以及 Agent 能力和内核版本检查。

运行原生测试时设置 `POLARIS_XRAY_EGRESS_BIN` 为 26.5.9+ 的 Xray，`POLARIS_SINGBOX_BIN` 为 sing-box。独立的 Xray 测试变量让旧内核兼容性测试继续使用 `POLARIS_XRAY_BIN`，CI 同时下载两个版本。

Xray 限速器对一个 SOCKS UDP 关联最多维护 32 个目标的内部 VLESS UDP 流；流量仍按同一个用户桶整形，关联关闭时清理所有连接，空闲流两分钟后回收。目标失败时丢弃当前数据包，不另发一次。
