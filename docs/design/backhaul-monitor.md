# 三网回程监控

> 状态：设计稿，待审定（D1–D10 为推荐方案，用户可逐条改）。参考竞品 flyx 的同名功能：定时检测每台服务器到电信/联通/移动的延迟与丢包、自动识别 CN2 GIA / 9929 / CMIN2 等回程线路、趋势图与异常告警。本设计不另起炉灶：Polaris 已有 TCP 探针（带运营商字段）、双栈 traceroute 回程检测（含定时调度、历史、路径变化通知）和本地 ASN 注释，本功能只补三处缺口——**按运营商聚合的三网视图、回程线路分类、运营商质量告警**。

## 1. 目标与非目标

### 目标

- 每个节点给出电信 / 联通 / 移动三网各自的当前延迟、连接失败率与近 7 天趋势（数据已在采，缺的是按运营商聚合的呈现）。
- 对回程 traceroute 结果做线路分类，输出 CN2 / 163 / 9929 / 4837 / CMIN2 / CMI / CMNET 等标签并随时间留存，能看出「线路什么时候从 CN2 掉回 163」。
- 线路降级与运营商质量恶化（高失败率 / 延迟突增）进入现有运维通知框架（Telegram / 邮件 / Webhook），默认克制、可关。
- 为后续「公开状态页」（四项借鉴中的第 2 项）预留聚合数据出口：只出数字与标签，不出目标地址与逐跳路径。

### 非目标（首版刻意不做）

- 不引入 ICMP 探针（见 D1）；不做去程（国内 → 节点方向）测量，面板与 Agent 都不在国内侧，测不到。
- 不做严格的 GIA / GT 区分（见 D5 的置信度口径）；不把分类标签当作运营商事实或计费依据。
- 不新增 Agent 探测工具：traceroute 沿用系统包与既有安装机制，不内置 nexttrace 类实现。
- 不改探针采样频率、目标管理与每节点探针策略的既有语义。

硬约束（调研确认）：

- Agent 以 root systemd 服务运行，ICMP raw socket 技术上可用，但现有探针口径是 TCP connect（见 D1）。
- `traceroute` 不是 Agent 内置能力，依赖节点系统包；未安装时回程检测返回 `unavailable`，已有环境检查与一键安装（apt/dnf/yum/apk）。分类功能必须容忍「只有延迟、没有路径」的节点。
- 默认探针目标是第三方公益测速地址（zstaticcdn），可用性不受本项目控制；目标可替换是既有能力，本设计不新增此类依赖。
- 同步升级纪律：新表/新列只增不删（AutoMigrate additive），分类器为纯面板侧逻辑、Agent 零改动，不产生新旧 Agent 能力协商问题。

## 3. 探测设计

### D1 探测方式：延迟/丢包沿用 TCP connect，不引入 ICMP

理由：①现有探针已全量部署、旧 Agent 直接参与，数据口径连续；②TCP 握手成功率对代理业务的代表性高于 ICMP（ICMP 常被骨干限速/低优先级转发，系统性高估丢包）；③再引入 ICMP 等于双口径并行，趋势不可比、维护翻倍。代价：指标本质是「连接失败率」而非 ICMP 丢包率——沿用现有探针文案口径（失败率），不改称丢包率。flyx 用何种探测未公开，此处不跟随。

### D2 目标点选型：沿用 ProbeTarget + carrier 字段，不建独立目标库

- 三网成员资格只看目标的 `Carrier`（ct/cu/cm）；无运营商标记的目标照常采样，但不进三网视图。
- 默认种子维持现有沪上三网各一；管理员可按既有目标管理补异地目标（如北方联通），同运营商多目标在三网视图中按目标分别展示、聚合值按样本数加权（与现有历史端点的加权口径一致）。
- 选型原则（写入目标管理说明）：优先运营商官方或长期稳定的公共服务地址；必须是 TCP 可达端口；不使用个人维护的测速点；不用会因被测而产生滥用风险的地址。

### D3 地址族：首版三网视图与分类只做 IPv4

现有默认目标均为 IPv4；IPv6 目标可经每节点策略自定义并照常采样，但不进三网聚合与线路分类——v6 骨干特征段资料不成熟，强行分类只会产出噪声。IPv6 回程路径仍可走现有手动/定时 traceroute 查看（不分类）。

## 4. 回程线路识别

### D4 识别引擎：复用 route-trace + 面板侧分类器，不新建探测通道

- 输入：一条已完成的回程历史记录（逐跳 IP + 可选 ASN 注释）。
- 分类器是面板侧纯函数 `classifyRoute(hops, asn) → (line, confidence, evidence)`，只对新记录计算并落库；历史不重算（与 ASN 注释的冻结口径一致），分类器版本随结果保存（`classifier_version`），规则升级后新旧结果可区分。
- 频率由既有每节点定时检测（route-schedule）承担：建议管理员对关心线路的节点设 1440 分钟（每日）；默认不自动开启任何节点的定时检测（沿用现状），手动检测同样产出分类。
- 状态衔接：记录未到达（partial/timeout/failed/unavailable）不分类，line 记 `unmeasured`，不冒充未知线路。

### D5 特征规则（首版，数据驱动可扩展）

按「进入中国方向骨干后的特征跳」判定，证据优先级：特征 IP 段直命中 > ASN 命中 > 无特征（unknown）。首版规则：

| 运营商 | 特征 | 标签 | 说明 |
| --- | --- | --- | --- |
| 电信 | 路径含 `59.43.*` | `cn2` | CN2 骨干特征段 |
| 电信 | 含 `59.43.*` 且全程无 `202.97.*` | `cn2` + confidence=suspect-gia | 疑似 GIA：单向回程证据不足以严格区分 GIA/GT，只给疑似 |
| 电信 | 含 `202.97.*`（AS4134 骨干） | `163` | 普通 163 |
| 联通 | ASN 命中 AS9929 或含 9929 特征段（如 `210.51.*`、`218.105.*`） | `9929` | 联通精品网 |
| 联通 | ASN 命中 AS4837 | `4837` | 联通普通骨干 |
| 移动 | ASN 命中 AS58807 | `cmin2` | 移动精品网 CMIN2 |
| 移动 | ASN 命中 AS58453 | `cmi` | 移动国际 CMI |
| 移动 | ASN 命中 AS9808 | `cmnet` | 移动普通骨干 |
| 任意 | 无特征命中 | `unknown` | 如实未知，不猜 |

- 一条路径多运营商特征并存时，以目标所属运营商（目标的 carrier）的特征优先；仍冲突则取最靠近目标侧（最后段）的特征并在 evidence 中保留全部命中。
- `confidence` 三档：`segment`（特征段直命中）、`asn`（仅 ASN 命中）、`suspect`（疑似，如 GIA 推断）。UI 展示「疑似」措辞，通知文案同样不说死。
- 与 [route-asn.md](route-asn.md) 的关系：ASN 注释仍只是归属注释；本分类器是独立的新口径，输出在产品文案中统一称「识别线路（启发式）」。

### D6 原始路径留存：不另存，分类结果只存证据摘要

逐跳原始路径已存在回程历史里（7 天/100 条上限）。分类行只存命中的证据（如 `ttl=9 ip=59.43.x.x rule=cn2-segment` 的结构化摘要，长度受限），便于解释「为什么判成这条线路」，不复制整条路径。

## 5. 采样与存储

### D7 存储：延迟零新表；分类一张新表（additive）

- 延迟/失败率：完全复用 `NodeLatency`。量级与现状相同：每节点每目标每 5 分钟 1 行，3 个三网目标即 864 行/节点/天，7 天约 6 千行/节点——三网视图只是按 carrier 的聚合查询，不产生新写入。
- 新表 `node_route_lines`（AutoMigrate 新建，只增不删）：

| 列 | 说明 |
| --- | --- |
| `trace_id`（PK） | 对应回程历史记录 ID，一条历史至多一行分类 |
| `node_id` / `family` / `target` | 冗余自历史记录，便于按节点+目标查最新 |
| `carrier` | 目标运营商（ct/cu/cm/空） |
| `line` | 标签枚举：cn2 / 163 / 9929 / 4837 / cmin2 / cmi / cmnet / unknown / unmeasured |
| `confidence` | segment / asn / suspect / none |
| `evidence` | 命中摘要（受限长度 JSON） |
| `classifier_version` | 规则版本（整数，首版 1） |
| `created_at` | 分类时间 |

- 保留：跟随回程历史的保留策略清理（trace 被清理时其分类行一并删，节点删除同理），不单独设保留期。行数量级 ≤ 回程历史行数（每节点 ≤100）。
- 「当前线路」不建状态表：按 (node_id, family, target) 取 created_at 最新一行即可，量级小、无一致性负担。

## 6. 告警

### D8 告警：两个新事件，都进现有通知策略框架，默认关闭

仿 `route_changed` 先例：新事件在事件目录中 `defaultOff: true`，管理员按渠道显式开启；重复窗口、维护静默、渠道总开关全部沿用现有策略，不另建通道。

1. `route_line_changed`（线路降级）：同 (node, target, family) 相邻两次**可分类**结果之间，线路等级下降才触发——等级序：cn2 > 163、9929 > 4837、cmin2 > cmi > cmnet（同运营商内比较）；变为 unknown 不直接触发（缺跳/ECMP 噪声大），连续 3 次 unknown 且此前为已知精品线路时降为一条「线路无法识别」提示；升级（如 163 → cn2）不发故障通知，如实记入历史供查看。触发点在分类落库事务提交后（仿 route_changed 的事务后生成），迟到/重复完成不重发。
2. `carrier_quality`（运营商质量）：独立评估器仿 `resourcealert.go` 形态——Leader 周期读 `NodeLatency` 5 分钟槽，按 (node, carrier) 聚合：连续 3 个槽（15 分钟）失败率 ≥ 50%，或平均延迟 ≥ 该节点该运营商近 7 天同时段基线的 2 倍且绝对值 ≥ 200ms（基线样本不足时只用失败率与绝对延迟 ≥ 400ms 兜底）→ 进入 breach 状态发一条；恢复（连续 2 槽回落）发恢复事件。状态存新表 `carrier_quality_states`（additive，仿 `NodeResourceAlert`），Leader 切换不重发。阈值走 settings（`carrier_alert_loss_pct`、`carrier_alert_ms`、`carrier_alert_minutes`），给默认值且可在设置页调。

去抖总原则：同一 (node, carrier/target) 的两类事件各自走策略框架的 repeatWindow 合并；线路抖动（两次分类间来回跳）由「相邻比较 + 降级才发」天然抑制，不再叠加额外抑制层。

## 7. 展示

### D9 管理端展示：节点详情为主，探针大盘为辅

- 节点详情页新增「三网回程」小节（放在现有延迟趋势与网络检测之间）：
  - 三列（电信 / 联通 / 移动）：最新槽的延迟与失败率、近 1 小时失败率、识别线路标签（含置信度措辞，如「CN2（疑似 GIA）」）、最近一次分类时间；
  - 每列下方一条 24 小时迷你趋势（复用探针 spark 数据口径，缺口如实断开，不填造）；
  - 无该运营商目标 / 节点探针关闭 / 无 traceroute 能力时，对应列显示原因态（未配置 / 已停用 / 无法识别），不显示假数字。
- 线路历史：在现有回程历史列表加 `line` 列与详情中的证据摘要，不新建页面。
- 探针大盘（Probe.tsx）：批 3 再评估给节点卡加三网徽标，首版不做，避免大盘信息过载。
- 仪表盘不新增汇总块：运维汇总已有采样健康入口，三网异常经告警触达即可。

### D10 公开状态页预留：只预留字段与开关，本项不实现页面

- `/status/data` 快照预留可选字段 `carriers`：每节点 `{ct:{ms,loss,line}, cu:{...}, cm:{...}}`，仅在新设置 `probe_public_carriers=true`（默认 false）时输出；关闭时快照不出现该字段（字节级无变化，批 3 以此验收）。
- 只出聚合数字与线路标签：不出目标地址、逐跳路径、证据明细；隐藏/撤销节点的排除规则沿用现有公开边界。
- 字段形状在本设计定死，第 2 项（公开状态页）直接消费，不再另议接口。

## 10. 风险与未决

- **分类本质是启发式**：ECMP 多路径、骨干 ICMP/UDP 限速、缺跳都会造成 unknown 或误判。置信度与「疑似」措辞是产品口径的一部分，不允许在后续迭代中悄悄去掉。
- **GIA/GT 之争**：用户对「是不是 GIA」敏感度高。首版只到「CN2（疑似 GIA）」；若后续要更强断言，需要双向路径与对端配合，不在本设计范围。
- **traceroute 覆盖率**：未装 traceroute 的节点只有延迟没有线路；一键安装已存在，但云厂商镜像差异下仍可能有节点长期 unavailable，展示需如实（D9 原因态）。
- **默认目标的代表性**：沪上单城目标对北方节点参考价值有限；靠管理员自加目标解决（D2），首版不扩充默认种子，避免替用户决定测速点。
- **未决**：①`carrier_quality` 的基线口径（同时段 7 天基线）在批 3 实现时若数据量不足，是否降级为纯绝对阈值，批 3 设计内决定；②线路标签是否进节点列表页（批 2 后看使用反馈再定，不预先承诺）。

## 11. 决策清单

| 编号 | 问题 | 推荐 | 备选与代价 |
| --- | --- | --- | --- |
| D1 | 探测方式 | 沿用 TCP connect 探针，不引入 ICMP | ICMP 并行：口径翻倍、趋势不可比、骨干限速致假丢包 |
| D2 | 目标点选型 | 沿用 ProbeTarget + carrier 字段与现有默认种子，管理员自加异地目标 | 内置多城目标库：替用户选测速点，长期维护与可用性责任在本项目 |
| D3 | 地址族 | 首版只做 IPv4 的三网聚合与分类 | 双栈分类：v6 特征资料不成熟，噪声大于信息 |
| D4 | 识别引擎 | 复用 route-trace + 面板侧分类器，频率随既有定时调度（建议每日） | Agent 内置 nexttrace 式探测：新工具链、新能力协商、与既有历史体系重复 |
| D5 | 特征规则 | 特征段 > ASN 的规则表，GIA 只给「疑似」，多特征按目标运营商优先、末段取舍 | 强分 GIA/GT：单向证据不足，误判会直接误导用户 |
| D6 | 原始路径留存 | 不另存，分类行只存证据摘要，路径查回程历史 | 分类行复制全路径：与历史重复存储、保留期不一致风险 |
| D7 | 存储 | 延迟零新表；分类新表 `node_route_lines`（additive），保留跟随回程历史 | 给回程历史加列：改动旧表语义，分类器版本迭代时不便并存 |
| D8 | 告警 | 新增 `route_line_changed`（仅降级）与 `carrier_quality` 两事件，进现有策略框架且默认关，阈值走 settings | 默认开：route_changed 先例即默认关，线路类通知噪声大，先关后开更稳 |
| D9 | 展示落点 | 节点详情「三网回程」小节 + 回程历史 line 列；大盘徽标延后批 3 评估 | 直接上仪表盘汇总：与运维汇总重复，且三网异常更适合告警触达 |
| D10 | 公开状态页预留 | `/status/data` 预留 `carriers` 字段 + 默认关开关，本项定形状不做页面 | 等第 2 项再议接口：第 2 项会被迫改快照结构，返工 |
