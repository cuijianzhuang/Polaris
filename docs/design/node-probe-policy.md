# 每节点探针策略

> 管理界面入口现已补齐，见[界面接入说明](operations-ui.md)；文中“仅后端/API”是首版交付范围。

节点支持继承全局测试点、独立测试点、关闭三种策略。本轮仅提供后端和 API，不改管理界面；现有节点默认继承，无需升级 Agent。使用现有 TCP connect 探测命令，结果不是 ICMP 丢包或真实代理业务验证。

## API

管理员会话可访问 `GET /nodes/:id/probe-policy` 和 `PUT /nodes/:id/probe-policy`。现有节点管理员和 API 令牌默认不开放新增接口；未知节点返回 404。GET 返回 `mode`、自行配置的 `targets` 和当前生效的 `effectiveTargets`。

独立配置示例：

```json
{
  "mode": "custom",
  "targets": [
    {"name": "上海电信", "carrier": "ct", "addr": "sh-ct-v4.ip.zstaticcdn.com:80"},
    {"name": "IPv6 测试", "carrier": "", "addr": "[2001:db8::1]:443"}
  ]
}
```

地址示例中的 IPv6 是文档地址，实际使用应替换为可达目标。支持现有省市运营商预设地址及自定义主机或 IP，不需要先加入全局测试点库。每节点 1–20 个目标，地址不区分大小写去重；名称、运营商和端口沿用全局校验。不接受客户端提供的目标 ID，也不接受禁用目标；关闭探测应使用 `off`。

切换为 `{"mode":"inherit"}` 或 `{"mode":"off"}` 时不传 targets，清空独立配置。继承仅使用全局已启用目标；全局没有目标也不影响其他节点独立配置。全局 `probe_enabled=false` 优先于所有节点策略，停止定时探测。关闭节点探测不关闭该节点代理服务。

## 采集、历史与公开边界

任务仍每 30 秒执行，最多 32 个并行命令，总截止时间 25 秒，单命令上限 15 秒；排队等待并发槽也响应任务截止时间。超时取消不额外记成目标失败。Agent 返回负值、NaN、无穷或不可解析的数据不作为有效延迟。

修改节点策略与记录结果共享节点数据库锁。写入时重新核对生效的目标 ID 和地址，旧策略命令即使迟到也不能恢复已移除测试点。节点删除后不接受迟到结果。全局目标变更/删除与采样写入也按目标行串行，避免地址已变化但旧值混入新趋势。数据库失败时策略和历史修改一起回滚。

相同地址改名或调整顺序保留目标 ID 与历史；地址替换使用新 ID。切换策略时删除不再生效目标的历史，保留继续生效目标的历史；其余历史仍按 5 分钟聚合、保留 7 天。关闭后不展示旧结果为当前状态；配置变化前已经发出的网络请求可能完成，但无效结果不会入账。

管理端节点延迟接口返回该节点有效目标及趋势。探针概览的目标字典包含各可见节点的有效目标，仅公开 ID、名称、运营商，不公开测试地址；隐藏节点的独立目标不出现在公开目标字典中。节点通用接口不输出独立目标地址。管理员配置接口和节点历史接口可读取地址，权限沿用现有探针管理边界。

策略和独立目标存于节点记录，随现有跨数据库备份恢复。删除节点同步清理配置和趋势；没有额外全局测试点引用。维护模式、回程分析和线路变化通知不包含在此功能中。

## 验证

测试覆盖三种策略的实际命令派发、全局关闭、独立历史、改名保留、地址替换、迟到结果、全局目标改址/删除、节点删除、非法配置、公开页隔离、节点管理员权限、事务失败回滚及备份恢复。
