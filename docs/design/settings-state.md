# 开关读取与设置保存

设置页的开关表示启用配置，服务是否已运行则来自独立的运行状态。Telegram 已配置启用但尚未启动、正在重连或启动失败时，不能把启用配置自动显示为关闭。

## 读取规则

- 首次设置请求完成前显示加载状态；读取失败显示错误和重试入口，不展示可编辑的默认开关。
- 设置表单直接从成功响应派生初始值，不经过「先渲染默认关闭，再异步填入」的窗口。重新读取期间禁用编辑，保存失败保留本地输入。
- 设置值统一按字符串处理，凭据是否存在、ACME 是否可用等布尔元数据保留布尔类型。数值 `0`、字符串 `false` 和显式空值不会被 `||` 替换为默认开启。
- 后端设置接口补全缺失记录的有效默认值，不修改数据库、不替换显式空值。读取数据库失败返回错误，不能用空对象和默认值伪装成功。
- 布尔语义按实际运行逻辑保持一致：多数开关仅 `true` 开启；订阅开关以 `false` 关闭，订阅域名限制以 `0` 关闭，S3 路径风格以 `false` 关闭。

## Telegram

运行状态每 5 秒刷新，上一请求未完成时跳过本次轮询。配置和编辑草稿使用独立的数据源，刷新运行状态不会覆盖尚未保存的开关。运行状态读取失败显示「状态获取失败」，而非「未运行」，相关运行操作保持禁用。

保存后重新读取配置和运行状态。读取失败可以重试；不再使用一次固定延时刷新来推断机器人是否已启动。Bot Token 留空仍代表不修改现有凭据。

## 保存一致性

整个设置请求先完成权限与字段校验，再通过事务一次提交。字段校验失败或数据库写入失败时不会留下部分开关修改。缓存失效、审计和节点配置更新在提交成功后执行，空的凭据字段继续保留原密钥。

读取保护覆盖 Telegram 及提醒模板、工单、商城、订阅、订阅转换、DDNS、审计、邮件、备份、Geodata、探针、自动更新和流量异常提醒表单。证书创建与 CDN Token 状态也等待读取确认，避免误选自签证书或误报未配置。

## 验证

- Go 测试验证缺失默认值、显式空值和 `0`、凭据隐藏、运行状态独立、数据库读取错误、无效请求与事务失败回滚。
- 浏览器回归覆盖慢请求、读取失败、格式错误响应、重试、保存失败、重复提交、运行状态轮询及保存后回读；分别运行 Chromium 和 WebKit。
- 新回归放入独立 CI 分组，避免延长原有设置分组的串行执行时间。
- 开发代理只匹配 `/sub/…` 订阅路径，避免将 `/sub-templates` 设置页误转发到后端。
