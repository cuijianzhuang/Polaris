# 节点小批升级

2026-10-25。社区版功能。入口有三个：「节点 → 升级全部 Agent」「节点 / 内核 → 批量升级内核」，以及面板自动更新后自动升级 Agent。

## 行为

1. 先升级**首批**节点（默认 1 个）。
2. 等这一批全部恢复正常，并持续**观察时间**（默认 120 秒）不中断，再按**每批**数量（默认 4 个）继续下一批。
3. 任一节点出现以下情况，任务立即停止，后续批次不再执行，并通过 Telegram / 邮件 / Webhook 通知：
   - 升级命令失败；
   - 新内核版本启动失败（Agent 会自动退回旧版本）；
   - 10 分钟内没有恢复正常。
4. 内核升级失败时，本批节点会进入回滚流程，等待 Agent 上报旧版本正在运行、配置已应用且健康检查通过后才记录已退回；超时显示回滚未确认。之前已完成的批次不会回退。
5. 支持 `agent-rollback-v1` 的 Agent 在本机监督进程下试运行新版本，5 分钟内完成面板 mTLS 认证、当前配置应用、内核运行检查和心跳发送后才替换正式文件。崩溃、卡死、校验失败或确认超时会停止候选进程并启动旧文件；监督进程或机器在确认前重启也使用旧文件。正式文件旁保留 `.previous`。小批升级仍会因目标版本未恢复而停止后续批次并告警。

   旧 Agent 首次升级到本版本仍沿用旧更新方式；从本版本开始，后续升级才受本机监督器保护。首次更新本身不具备这一回退保障。监督器只在 Linux 提供父子进程寿命绑定。
6. 升级开始时离线的节点记为「跳过」，不算失败。

## 判定「正常」

以下条件全部满足才算正常：

- 节点在线；
- Agent 版本（或内核的运行版本）等于目标版本，并且内核处于运行状态；试运行的 Agent 上报 `目标版本-trial`，本机完成确认并提交后才报告正式版本；
- 已应用的配置版本不低于期望版本，节点没有处于下发失败状态；
- 开启「入站探测」时，该节点所有对外 TCP 入站都能通过外部探测（与「入站健康检测」使用同一套探测）。

## 运行方式

- 任务保存在 `upgrade_rollouts` 表中。主控每 15 秒推进一次，用租约认领任务（与退款任务相同的机制）。面板重启或主控切换后，任务会接着执行。
- 同一时间只能有一个进行中（或暂停中）的任务。
- 可以暂停、继续、取消。继续后，当前这一批重新开始计算观察时间。取消不会回退已经升级的节点。
- API（管理员）：
  - `GET /rollouts`、`GET /rollouts/:id`
  - `POST /rollouts`，参数 `{kind: agent|core, coreType?, version?, nodeIds?, canary, batchSize, soakSeconds, probeInbounds}`。`nodeIds` 留空时，选中所有需要升级的节点。
  - `POST /rollouts/:id/pause|resume|cancel`
- 面板自动更新后（`update_then_agents`），Agent 改为按小批方式升级。首批数量由设置项 `update_canary` 决定，默认 1。

## 故障一致性

任务创建在数据库中串行准入，避免多个面板同时启动升级。批次、原版本和待执行状态先持久化，再发送命令；重启可继续未完成的批次。暂停与取消不会中止已经发出的命令，其返回结果仍保留，但旧执行者不能覆盖管理员设置的终态。租约过期的执行者不能保存进度。

内核故障先持久化 `rolling_back`，逐节点区分等待回滚、回滚中、已退回和回滚未确认。恢复正在进行时不开放暂停或取消，以免中断已请求的恢复流程。回滚任务仍占用唯一进行中的任务名额。任务属于运行控制记录，不随业务备份导出或恢复，避免重放历史升级。

## Agent 本机恢复记录

Agent 服务主进程保留监督职责，工作进程退出码 75 表示已保存待试运行版本；不会用新版本覆盖正在运行的监督进程。临时文件与正式文件位于同一目录，升级 journal、确认 nonce 和结果位于数据目录的 `agent/` 下，以 0600 权限保存。候选文件启动前、提交前均核对 SHA-256；保留旧 inode、文件替换及 journal 更新均同步落盘。

`agent/upgrade-result.json` 记录最近目标版本、确认/回退状态、原因和时间。回退后重连会通过节点进度展示原因，持久原因也可在本机日志和该文件中查看。试运行期间拒绝并发升级。受监督的外部内核随工作进程死亡而终止，回退前先等待候选进程退出。

此保护覆盖启动确认窗口；确认后的长期业务故障仍由小批观察与运维监控处理，不会自动回退所有已完成节点。初次部署后可在节点能力中核对 `agent-rollback-v1`。无效或被修改的 journal 会拒绝执行；修复前保留正式文件、`.previous` 和 journal 供排查。
