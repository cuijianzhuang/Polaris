# Snell 独立用户接入

## 内核与模式

Polaris 使用 **带 `with_v2ray_api` 的 sing-box 1.14.0+** 实现 Snell 服务端，无需安装 Surge 官方 `snell-server`。官方内核目前没有接入 Polaris。

先升级 Agent，让节点完成一次配置拉取并报告能力，再安装带统计构建。现有安装器优先下载 Polaris 构建；若回落到无用户统计的官方 sing-box，Snell 应用会失败，不会继续提供无法扣量的服务。已报告 `noUserTraffic` 的内核也不能用于新建 Snell。

| 模式 | 监听端口 | 客户端凭据 | 计费来源 | 客户端输出 |
| --- | --- | --- | --- | --- |
| 多用户 `userkey`（默认） | 多名用户共享一个入站端口 | 入站 PSK + 各自 userkey | 原生用户计数 | sing-box 1.14+ |
| 独立 `psk` | 每个入站明确指定一名用户，独占已有端口 | 按入站种子及用户身份/密码派生的独立 PSK | 该入站计数归入指定用户 | Surge 标准配置、sing-box 1.14+ |

独立模式通过一个入站对应一个用户保留标准 Snell PSK 握手，不依赖 Surge 未公开的 `userkey` 字段。不是把所有用户改成同一个密码。管理员可使用现有克隆/端口分配流程创建多个独立入站；本轮不自动为所有账号批量分配监听器。

独立模式需要 Agent 报告额外的 `snell-psk-v1`。只理解首版 `snell-users-v1` 的 Agent 会被拒绝拉取该配置，避免按旧含义启动服务。

## 后台配置

1. 新建或编辑 Snell 入站，选择“独立 PSK / 端口（Surge 兼容）”。
2. 搜索并指定专属用户。**选择专属用户不增加授权**，仍需已有分组、节点或直接入站授权；其他被授予同一入站的用户不会获得这个专属监听器或订阅。
3. 使用独立端口；现有端口冲突检查、防火墙、来源限制以及 L4 中转仍适用。
4. 默认服务端 v5，对外使用 v4 客户端线协议，支持 `none` / `http` 混淆。没有实现 v5 QUIC 代理模式，因此 Surge 配置固定导出 `version=4`。
5. 可选服务端/客户端 v6，要求 Surge iOS 5.20.0+ 或 Mac 6.7.0+；v6 上游仍可能存在 beta 协议差异，需要实际客户端验收。

v6 支持 `default` / `unshaped`。独立 PSK 模式禁止 `unsafe-raw`：它去掉加密，无法据 PSK 建立这里所需的身份隔离。原有明确携带 userkey 的多用户模式保持其选项。

Snell 只监听 TCP，同时承载 TCP/UDP 代理业务，不额外开放 UDP 监听端口。没有修改既有“全协议”模板；独立用户字段可在模板编辑器配置，但仍受正常授权约束。

## 凭据、归属与撤销

`protocol.serverKey` 是加密存储的入站随机种子；编辑留空保留原值，配置预览脱敏。独立模式通过 HMAC-SHA256，以入站种子为密钥，对域标识、用户 ID、UUID、密码的 JSON 数组派生 URL-safe PSK。订阅不直接下发入站种子；更换用户、重置用户密码或轮换入站种子均改变最终 PSK。

独立监听的原生 Snell 没有 `metadata.User`。适配器据明确的“入站 tag → 指定用户”映射，将该入站的原生业务字节数加到对应用户；保留原始 tag 计数用于入站图表，两类不能相加充当账号扣量。其他入站已有的同一用户计数继续累计。用户路由条件同步转换为专属入站条件；限速首跳按该入站送入指定用户的限速绕回，返回后保留已有别名和路由上下文。

归属映射不能在 Render 时生效。Agent 先按旧归属采集最后一笔流量；独立模式同步停止旧进程，再启动新配置并启用新映射，避免旧进程字节记给新用户。映射绑定实际配置文件的 SHA-256；被校验拒绝而未写入的草稿不能改变手动重启后的归属。旧进程日志回调完全排空后才切换映射，失败回退沿用配置回退机制。

用户停用、到期、超额、撤回授权或删除后，没有合格授权用户则移除监听器。多用户模式同样不能对零用户下发空数组，因为上游会退回共享 PSK 模式。高级 JSON 禁止覆盖身份、PSK、用户、tag、detour 等关键字段。独立模式还禁止 `api`、空 tag，以及包含 `>>>` 或 `]` 的 tag，避免统计分隔符或日志边界破坏归属。

用户变更仍依赖策略检查、配置发布和 Agent 应用，会中断同一 sing-box 内核上的现有连接；不是逐用户无损热更新或即时硬配额。单纯未认证的 TCP 建连不计为用户在线；仅在握手成功后的日志中关联真实来源 IP。

## 订阅与版本过滤

Surge 只接收明确标记为独立 PSK 的 Snell 节点，不下发 userkey 模式。已知平台及版本低于 v6 要求时过滤 v6 节点。Surge 有时仅在 User-Agent 携带内部构建号，无法确定平台/版本的请求和手动导出保留管理员明确选择的 v6；不把“未识别”当成已验证兼容。

sing-box/SFA/SFI/SFM/SFT 的已知旧版本、以及无法识别兼容内核版本的这些客户端/Hiddify，会过滤 Snell。显式 singbox 浏览器/手动导出可包含 Snell，要求最终导入 1.14+。其他未实现标准输出的客户端格式仍跳过 Snell。

含 Snell 的 Surge/sing-box 输出使用内置转换器。外部转换器的链接回调无法完整表达 Snell 凭据，不能因转换丢失节点或身份。来源解析明确区分原生 userkey 与标准 PSK 条目，协议过滤/去重均保留认证模式、凭据、版本及整形/混淆差异。外部订阅源的共享 PSK 不会因此变成 Polaris 可独立撤销的账号凭据。

尚未新增 Snell 链式出站或 Snell 真实业务诊断实现。

## 自动验证与实际 App 验收

固定 upstream **sing-box v1.14.4**，提交 `c005f35300ce76427dc285481ec5695f5b179cd2`，构建启用 `with_v2ray_api,with_clash_api`。真实传输仅访问回环目标。

```bash
POLARIS_SNELL_BIN=/path/to/sing-box go test -count=1 -v ./internal/core/singbox ./internal/panel -run Snell
# 链接 Pro 源码后验证实际限速路径
POLARIS_SNELL_BIN=/path/to/sing-box go test -tags pro -count=1 -v ./internal/agent -run Snell
```

覆盖多用户模式与独立 PSK v5/v5 HTTP/v6 default/unshaped 的两用户 TCP/UDP、精确原生字节数、错误 PSK、跨用户端口凭据隔离、旧凭据与已有连接撤销、零用户关监听、用户路由、认证后来源关联。特别测试先 Render 新配置再采集旧进程，确保旧用户最后一笔流量不丢失/串账。

面板测试串联实际订阅配置 → 内核传输 → 原生采集 → 收件箱 → 2 倍率结算 → 重复批次去重 → 超额撤销订阅与旧凭据。Pro 测试验证实际限速出站经过目标字节数，且普通/IPv4 策略下不重复扣量。另有旧 Agent 协商、未授权指定用户、来源解析、配置注入与版本过滤测试。

UI：启动 Vite 后运行 `POLARIS_WEB_TEST_URL=http://127.0.0.1:5187 python3 web/scripts/snell-ui-smoke.py`，覆盖手机/桌面授权模式、用户选择、选项联动与保存。脚本使用模拟 API。

**当前环境无法运行 Surge iOS/Mac App。** 已验证官方文档规定的配置格式和不携带 userkey 的同协议流量链路，不能据此声称两个 Surge App 已实测通过。实际 App 还需分别验收订阅导入、TCP 下载/上传、UDP/QUIC、切换网络、重置凭据与停用后的连接失效；建议先用默认 v5/v4 配置，再验证双方匹配的 v6 版本。

## 可发现入口与能力检查（2026-10-25）

入站页提供独立「Snell 入站」按钮，不需要先找到协议网格。选择节点后，后台 `/nodes/:id/snell-readiness` 检查 Agent 的用户授权及独立 PSK 特征、实际运行的 sing-box 稳定版（至少 1.14.0）、运行状态及用户计数能力。就绪后打开已选择 sing-box / Snell / 独立 PSK 的新建表单，指定专属用户后才允许保存；仍沿用后台已有的用户授权、停用及计费校验。

未就绪时分别提示升级 Agent、安装/运行支持版本或补齐 with_v2ray_api 统计构建，提供节点与内核管理入口及重新检查。仅修改期望版本不视为就绪，须等待节点上报实际版本。无需额外安装官方 snell-server。

面板的 Agent 安装器会优先下载本仓库发布的统计版。如果对应版本尚未发布，可使用仓库已有的 sing-box builds 流程构建发布，或等待其计划任务；上游不含统计功能的构建不能用来启用 Snell 用户计费。
