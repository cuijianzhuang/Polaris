# 服务器网卡流量与成本统计

服务器成本页的「近 30 天」按面板本地日期统计今天及前 29 天，不包含未来日期。统计采用节点配置的计费方式：出站、入站、期间上下行总量的较大值，或双向合计。「取较大值」比较整段期间的收发总量，不累加每日较大值。每 GB 成本使用同一口径，GB 沿用面板的 1024³ 字节口径。

页面同时展示入站、出站原始值、计费方式和有数据的日期数。零流量与未采集区分显示。有数据的日期不代表全天连续采集，也不代表已经覆盖完整 30 天。网卡统计包含服务器其他程序的用量，与用户套餐流量、服务商的计费记录可能不同；本周期手动校准不会倒推修改历史每日流量。

## 采集与去重

新 Agent 上报网卡累计值、来源标识和主机运行时间毫秒值。来源标识为主机启动 ID、接口名称及接口索引的摘要；Agent 自身重启保留相同来源。主机重启、增删或替换网卡时建立新基线，不把新接口启动以来的累计值重新记为新增流量。计数下降也只重设基线；来源变化边界的未观测流量无法准确还原，因此不会估算入账。

排除 loopback、常见 Docker/veth/bridge 和 tun/tap/WireGuard/Tailscale/CNI/Flannel 等虚拟接口，避免同一数据在宿主网卡和隧道接口重复累计。自定义接口名、特殊网络拓扑仍需结合主机和服务商记录核对。

不完整采样（读文件失败、数值无效、接口身份读取失败）不上报有效计数；观察到的真实零计数可以建立基线。相同来源下按主机运行时间去掉重复或乱序心跳。旧 Agent 缺少这些来源和顺序信息，兼容接收但不能提供同等的乱序保护，应同步升级。

## 原子入账

后端在事务中先锁定节点，再读取基线和计算增量。节点本周期总量、最新基线和每日账本同事务提交；失败时整笔回滚，下次心跳可重试，避免账本写入成功但基线失败造成重报。告警在提交成功后发送。

周期重置、手动校准和服务商同步也使用同一节点事务锁。跨过重置日后，首个心跳先开启新周期再入账；小时巡检重新读取锁定后的周期状态，不能清掉已经记入新周期的流量。重置保留网卡累计基线和每日历史，校准只修改本周期偏移量。心跳跨零点的未观测区间归入收到该心跳的日期与周期，不按时间比例猜测拆分。

校准基于锁内最新计数计算偏移，避免与心跳并发时重复计入增量。写入失败时返回错误，服务商校准的告警仅在事务提交成功后发送。

## 旧数据

旧版每日记录标记为待核对，不自动清零、折半或按新流量猜测修正。同一天混入旧 Agent 数据后仍保留旧版标记，避免把混合记录当作全部可信。升级需要同时更新面板和各节点 Agent；修复能保护后续采集，但不能仅凭旧汇总还原此前的真实用量。历史更正需要可靠的服务商或主机记录。
