# 管理员通行密钥与账号恢复

2026-10-25。社区版与专业版均支持；入口为「设置 → 账号安全 → 通行密钥」，登录页提供通行密钥登录和账号恢复。

## 配置与注册

先将面板的公开地址配置为 HTTPS 域名，并通过该域名打开后台。本机测试可使用 `http://localhost:端口`；不使用 IP 地址注册。RP ID 和允许的 Origin 仅由管理员配置的公开地址产生，忽略 Host / X-Forwarded-Host。后台路径和端口不属于 RP ID；Origin 包含协议和端口。更换域名需要在新域名重新注册，不会自动转移密钥。

管理员先通过现有密码、TOTP 或已绑定身份登录，再完成最近 10 分钟的敏感操作验证，输入设备名称注册。浏览器调用标准 WebAuthn 创建可发现凭据，要求用户验证（设备 PIN、指纹、面容或支持用户验证的安全密钥），不接受仅触摸但无用户验证的降级流程。每账号每域名最多 20 个密钥；服务端保存 AES-GCM 加密的完整 WebAuthn 记录，含计数和备份标志。私钥由认证器保存，永不上传。

## 单次挑战与登录

注册和登录挑战分离，2 分钟过期，在数据库加密保存，任一实例均可处理。完成接口先原子删除挑战；无效签名和验证失败同样消费，不能重试同一挑战。注册还绑定管理员 ID、会话 ID、账号版本和公开 Origin。事务内重新检查会话、敏感验证和账号版本，防止注销或账号恢复后的在途请求重新注册密钥或生成恢复码。

登录采用可发现凭据，不返回账号是否注册密钥的信息。验证 challenge、RP ID、Origin、签名、用户在场、用户验证及 user handle 的实际账号归属，拒绝跨域和异常克隆计数。同步型通行密钥的零计数/备份语义交由 WebAuthn 库验证，保存新的签名计数和备份状态。

通过设备用户验证的通行密钥是一条独立登录方式，不再要求额外输入现有 TOTP。密码登录原有 TOTP 要求保持有效。登录失败使用现有 IP 防护，挑战另有每 IP 每分钟限额（多实例可使用既有 Redis 共享限额）。

## 撤销与恢复

撤销只影响所选通行密钥及使用它签发的登录会话；密码登录和其他密钥的会话不受影响。密码、现有 TOTP 恢复码、已绑定的其他身份提供方仍可用于正常登录。

首次注册时，如没有账号恢复码，则生成 10 个独立的 192-bit 随机恢复码，只展示本次，数据库只保存 SHA-256 哈希。这些码与原有 TOTP 恢复码不同，每个码都具备重置整个管理员账号的能力，需离线安全保存。设置页可在敏感操作验证后重新生成，整组旧码立即失效。所有认证响应跳过幂等缓存，避免在响应缓存中保存恢复秘密或重放挑战成功结果。

丢失登录方式时，从登录页「无法使用通行密钥？恢复账号」输入用户名、账号恢复码、新密码和确认密码。服务端在一个事务中核验恢复码、重置密码、关闭 TOTP、清理原有 TOTP 秘密及恢复码、撤销全部通行密钥和登录会话、提升账号版本，并删除整组账号恢复码；并发使用同一个恢复码最多一次成功。不自动签发登录会话，随后用新密码登录并重新配置二次验证和密钥。不存在的账号与错误恢复码返回相同提示。如果密钥和恢复码全部丢失，但仍有服务器运维权限，可执行 `polaris admin reset-passkeys -u 用户名` 撤销该账号所有通行密钥、账号恢复码和会话；密码/TOTP 另用 `reset-password` / `reset-2fa` 命令恢复。

备份包含加密的通行密钥记录，支持跨服务器密钥重新封装。恢复备份会清理所有通行密钥挑战和账号恢复码，并撤销通行密钥会话，避免回滚重新激活已用秘密；恢复后重新生成账号恢复码。

## 验证

Go 回归覆盖可信 RP 配置、敏感验证、会话绑定、过期/失败/跨用途挑战、撤销会话、恢复并发、缓存排除、恢复备份不复活挑战及在途请求的会话复检。PostgreSQL 和 race 执行同组安全测试。

`npm --prefix web run build` 后运行：

```sh
POLARIS_PASSKEY_BROWSER_TEST=1 go test ./internal/panel -run '^TestLivePasskeyBrowser$' -count=1 -v
```

需要 Python Playwright 和 Chromium。测试使用真实 HTTP 服务、React 页面和 Chromium 虚拟认证器，执行注册、真实签名登录、跨域篡改拒绝、签名计数回滚拒绝、挑战重放拒绝、撤销及恢复表单；不输出私钥或恢复码。此测试不替代 iCloud Keychain、Android 密码管理器及实体安全密钥的设备验收。
