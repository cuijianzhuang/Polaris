# 可复用订阅处理组

订阅转换页增加「处理组」，集中维护过滤、重命名、排序和去重步骤；订阅组按选择顺序引用，支持跟随最新或固定版本。数据模型、路由、备份和界面位于 Polaris，执行链和管理实现沿用现有专业版分工，位于配套 polaris-pro。

## 执行顺序与权限

顺序为：可选全局规则 → 引用的处理组（按引用顺序）→ 本订阅组的处理步骤。组内步骤同样按顺序执行。每个订阅最多引用 20 个不同处理组，每组最多 64 步、规则 JSON 最多 48 KiB，不支持嵌套引用。

处理组仅包含规则，不包含订阅源、节点、用户或授权。先按原有账号状态、到期和额度校验，再获取该账号原本可访问的节点及订阅来源，最后执行处理链。停用、删除、到期或超额仍阻断整个关联订阅；客户用量仍只使用关联账号口径，上游额度不混入客户额度。未关联账号的独立组合订阅维持原语义。

已有订阅默认没有处理组引用，结果保持不变。旧编辑器省略 `processingGroups` 时保留原引用；显式提交 `[]` 清除引用。公开订阅与草稿预览共用同一条处理链，第三方转换接收同样处理后的节点快照；已经发出的响应或短期转换回调不会被追溯改写，回调的账号失效校验仍按原规则执行。

## 数据与版本

- `SubProcessingGroup`：当前名称、备注、规则和版本。
- `SubProcessingGroupVersion`：每次保存形成的不可变版本，按 `(group_id, revision)` 唯一。
- `SubProfile.processingGroups`：`[{"groupId":"...","revision":0}]`。0 跟随最新，大于 0 固定指定版本。

编辑规则、名称或备注时版本递增；无变化保存不增加版本。固定版本不随新版本改变，恢复旧版本是以其规则再次保存为新版本。版本及引用随现有备份一起导出/恢复；处理组缺失、版本缺失或规则无效时订阅请求报错，不静默跳过规则。

## 接口与变更预览

相对于 APIBase，以下接口仅管理员会话可用；不向节点操作员、API 令牌或匿名访问开放。

| 接口 | 行为 |
| --- | --- |
| `GET /sub-processing-groups` | 列出当前处理组 |
| `POST /sub-processing-groups` | 创建，版本为 1 |
| `GET /sub-processing-groups/:id/versions` | 最近 100 个版本的元数据 |
| `GET /sub-processing-groups/:id/versions/:revision` | 指定不可变版本的规则；旧固定版本仍可直接读取 |
| `POST /sub-processing-groups/:id/preview` | 根据草稿和引用关系计算影响范围与强 ETag |
| `PUT /sub-processing-groups/:id` | 带 `If-Match` 和 `expectedRevision` 更新 |
| `DELETE /sub-processing-groups/:id` | 带相同预览条件删除；任何引用均阻断删除 |

创建/编辑正文：

```json
{
  "name": "共同过滤与命名",
  "remark": "多个订阅共用",
  "operators": [
    {"type":"filter","dropInfo":true},
    {"type":"rename","template":"{region} {name}"}
  ],
  "expectedRevision": 1,
  "action": "update"
}
```

创建时省略 action，expectedRevision 为 0。编辑/删除先以相同正文请求预览，action 分别为 update/delete，再将返回的带引号 etag 原样作为 `If-Match` 发送。DELETE 也携带该 JSON 正文。

预览列出引用订阅的 ID、名称、启用状态、是否跟随最新和固定版本号。`affected` 为跟随最新的引用数量，包含停用订阅，因为再次启用后也会使用新规则；固定版本引用列出但不计入更新数量。响应不包含订阅 token、源地址或节点凭据。

版本或引用配置变化使旧预览返回 412。没有 If-Match 同样拒绝；删除仍有引用时返回 409。禁用订阅、固定版本引用也需要先解除，不能强制级联删除。界面修改草稿立即丢弃旧预览，冲突后要求重新预览。

组写入、预览以及订阅引用保存/删除共用数据库协调锁，SQLite 在读取前预占写事务，PostgreSQL 锁共享设置行，防止跨实例引用与删除竞争。订阅执行在一个只读快照中解析引用，避免多个组混用同一请求内的新旧版本；网络拉取不占用该事务。此锁不保护直接修改数据库的操作。多实例应全部更新到支持处理组的版本后再启用引用，旧程序不会执行新处理链。

读取现有配置和继续交付已有订阅沿用现有许可行为；新建和修改需要订阅转换功能许可。社区版保留模型和备份兼容性，界面提示专业版限制，不能借处理组绕过订阅转换能力边界。

## 界面与验证

「订阅转换 → 处理组」支持创建、编辑、影响预览、版本历史、以历史规则创建新版本及删除保护。「订阅组」编辑中可添加/移除/排序引用，并选择跟随或固定版本；规则编辑器与本地处理步骤共用。

后端覆盖顺序执行、固定版本、不可变历史、预览失效、并发更新、所有引用的删除保护、非法规则/引用、旧编辑器、账号停用、客户用量、真实公开订阅输出，以及备份恢复与权限边界。同时修复原有已存在订阅更新时初始化新主键导致查询 404 的问题，并覆盖新建订阅的 ID/token 生成。

前端执行 `npm run build`、`npm run i18n:check`。浏览器脚本使用模拟 API 验证 390/1440 像素下的新建、预览、If-Match、删除保护、固定版本保存和冲突处理：

```sh
# 先启动 Vite，并安装 Python Playwright 与 Chromium
POLARIS_WEB_TEST_URL=http://127.0.0.1:5187 python3 web/scripts/sub-processing-ui-smoke.py
```
