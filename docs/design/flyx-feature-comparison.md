## 最新 FLYX 变化带来的判断

### 1. 订阅拉取防护：Polaris 已有基础，应核对代理环境

FLYX 最近增加订阅、模板和图标库的安全拉取。Polaris 已有 `safeClient` 和默认关闭的 `allow_private_sources`，不能把防 SSRF 整体列为缺失。

原先两者代理场景处理不同：Polaris 使用 `http.ProxyFromEnvironment`，地址检查在实际拨号时进行；配置 HTTP(S) 代理后，实际拨号地址可能是代理服务器，而非下载目标。FLYX 新实现额外在代理请求前解析并检查目标。

该边界已通过 #154 补充检查和代理重定向回归，区分代理拨号与下载目标。即使允许访问内网，也拒绝链路本地等非目标地址；远端代理的 DNS 解析结果未被固定，不能据此宣称完全解决 DNS 重绑定。

### 2. SS2022 多用户撤回：不能照搬共享凭据模式

FLYX 最新更新日志和 `SupportsUsers` 已撤回刚加入的 SS2022 多用户功能，恢复共享凭据。该结论只针对其实现，不表示协议普遍无法多用户。

Polaris 应保留自身现有的独立用户模型。今后增加 Snell 时，也要单独核对所选内核版本的用户能力、客户端兼容、独立停用和真实计数，不能以“能生成连接”代替机场计费验收。

### 3. 订阅可读性与兼容性适合作为后续完善

FLYX 新增失效原因占位节点、流量/到期提示、来源 User-Agent，以及模板断言、`exclude-type`、YAML 继承兼容。Polaris 来源拉取已有 User-Agent，不能重复建设。

建议先做客户端兼容样例核对，再决定补差异。失效提示必须不携带旧凭据、不绕过账号失效策略；不能仅为了返回 HTTP 200 而重新输出可用代理。显示流量/到期也不能掩盖下面的额度口径问题。

### 第一优先：订阅额度口径和下载边界

**已修复（pro #17）**：此前 pro `profileNodesForUser` 先写入关联用户的已用流量和总额度，又把每个上游来源的上传、下载和总量相加，并取最早到期日。这会将客户账号额度与供应商共享套餐额度混在同一份订阅信息中；不是已经证明的数据库重复扣量，但会造成客户端额度显示误导。

现已实现：关联用户时，客户端计费信息以该账号为准，上游用量独立作为来源信息；未关联的个人组合订阅保留明确的聚合模式。零额度、无限额度、过期来源和多个共享上游必须有明确语义，不能直接相加。

验收：账号 100 GB、上游 1 TB 时不显示成客户有 1.1 TB；停用、超额、到期仍阻断全部关联内容；网页、原始订阅和转换回调口径一致。下载边界按上节测试矩阵单独验证后修复，避免将待验证风险混同于已复现缺陷。

### 第二优先：真实业务诊断

现有分层诊断会取消请求并共用 15 秒超时，`businessVerified` 保持 `false`；这些不是缺失项。本轮已补充贯穿入口、认证隧道、Xray VLESS 与 HTTP(S)/UDP DNS 目标的首版真实验证，已通过 #156 合并。

建议增加短期专用诊断身份、受限测试目标和隔离计量，记录认证、TCP 上下行、UDP 回包及失败阶段。诊断身份不应成为用户可用的永久旁路，也不能借用真实客户凭据。

验收：端口开但认证错、隧道密码错、UDP 被阻断均不能通过；诊断不改变任何客户用量；直连、多级回退、限速和多入口都要验证；请求取消和超时后释放身份、会话与临时资源。

### 第三优先：中转可维护性

多入口创建已完成，名称/分享地址编辑、整组查询/启停/删除已通过 #155 合并；[启停/删除影响预览与引用保护](relay-change-preview.md)，支持可选 If-Match 条件、明确资源范围和外部依赖检查，已通过 #158 合并。独立改名不应重建监听；整组操作需定义原子性、离线节点状态、重复请求语义及部分应用错误的恢复。

验收：删除一个入口不破坏其他入口；共用后续节点不误删其他线路；源地址白名单按剩余引用收敛；订阅更新不泄露只允许中转的落地地址；批量操作失败后可重试且不重复创建。

### 第四优先：每节点探针策略与通知降噪

**上一轮已通过 #156 合并**：每节点继承全局、独立配置 1–20 个目标及关闭策略，复用现有 Agent 命令；已接入采集、趋势与公开探针数据，处理迟到结果和备份恢复。仅后端/API，见[每节点探针策略](node-probe-policy.md)。已通过 #156 合并；双栈回程首版已通过 #160 合并，本轮本地补充历史和路径变化对比。通知降噪本轮已补充后端/API，见[运维通知策略](notification-policy.md)：事件×渠道开关、按节点/渠道的定时维护、按接收人和资源持久合并；安全、客户和交易通知保留原规则。SMTP/Telegram 仍为尽力发送，非可靠消息队列。

测试点支持继承全局、自定义、关闭，配合限并发、超时、结果新鲜度与历史保留；节点改动后清理旧策略引用。双栈回程保留原始 hop/ASN 证据，不把 TCP 连接失败率称为 IP 层丢包，也不把各段延迟相加称为真实客户端端到端延迟。

通知先统计高频事件及现有节流覆盖，再做事件×渠道和维护静默。验收故障持续期间不反复发送同类消息、恢复只发一次、重启及多副本不造成重复投递；安全和交易类通知另行定义，避免被统一静默误吞。

### 第五优先：复用和新协议

依次评估可复用订阅处理组、外部节点资源化、Snell。处理组必须提供受影响订阅预览和引用保护，且不能扩大用户原有权限。Snell 的版本、订阅客户端过滤、独立凭据、停用与真实用户计量都通过后，才算完成接入。

转发商品、Passkey、跨面板共享和更大范围 UI 改版暂后置，按明确业务需求决定。
