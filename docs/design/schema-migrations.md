# 版本化数据迁移

GORM 的 AutoMigrate 只会建表和加列，不会改名、删列、改类型，也不会修数据。这类变更放进 `internal/store/migrate.go` 的编号迁移里。

## 行为

- 启动时先 AutoMigrate，再按编号依次执行还没执行过的迁移，每个迁移在一个事务里完成，完成后写入 `schema_migrations`（编号、名称、时间）。
- 某个迁移失败时，它的改动整体回滚，后面的迁移不执行，面板启动失败并报出是哪一步；修复后重启会从这一步继续。
- PostgreSQL 上每个迁移先取事务级 advisory lock，多个主控同时启动时，同一步只会执行一次，其余实例等待后跳过。SQLite 只有一个写连接，天然串行。
- 新安装同样会执行全部迁移（对空表通常什么也不做），并记录下来。
- `schema_migrations` 不进备份。恢复备份只恢复数据，不恢复「哪些迁移跑过」，所以迁移本身要对旧备份恢复出来的数据同样正确，或者由恢复流程负责处理。

## 新增一个迁移

1. 在 `migrations` 末尾追加，编号为上一个加 1。已发布的迁移不能改编号、不能修改内容。
2. `Up` 必须同时兼容 SQLite 和 PostgreSQL，并在两种数据库上测试（`POLARIS_TEST_POSTGRES_DSN`）。
3. 如果判断条件依赖 AutoMigrate 之前的表结构（例如某列之前是否存在），在 `Probe` 里读取，结果会传给 `Up`。
4. 大表上的数据修正注意耗时：迁移在启动时同步执行，期间面板不可用。
