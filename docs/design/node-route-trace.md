# 节点双栈回程检测（首版）

仅管理员后端/API，沿现有节点命令通道执行，不改 UI。PR #156 的 TCP 测试点采集继续使用原调度；本功能按需运行，不新增周期探测流量。

## 请求

`POST /nodes/:id/route-trace`

```json
{"ipv4":"1.1.1.1","ipv6":"2606:4700:4700::1111"}
```

可只指定一个地址族。目标必须是对应地址族的公网 IP 字面量，不接受域名、端口、IPv4 映射 IPv6、本地/私有/链路本地地址或网卡 zone，面板和 Agent 均校验。不以 DNS 自动降级为另一个地址族，也不从当前管理连接推断用户所在网络。需管理员自行选择有代表性的运营商测试地址。

旧 Agent 未声明 `route-trace-v1` 或节点离线时返回 409。命令失败或返回格式错误为 502；两种地址族分别返回执行结果，单个地址族失败不丢弃另一个结果。

```json
{"nodeId":"NODE_ID","results":[{"family":"ipv4","target":"1.1.1.1","checkedAt":"2026-10-24T02:00:00Z","state":"partial","hops":[{"ttl":1,"addresses":["192.168.1.1"]},{"ttl":2,"addresses":[]}],"raw":"..."}]}
```

`checkedAt` 为 Agent 开始采样的时间。状态：

- `reached`：探测输出包含目标地址回复，未带不可达标记；不代表 TCP、代理认证或实际业务已通过。
- `partial`：保留已观察到的跳点，未证明到达目标；星号只表示该次探测无回复，不称为丢包率。
- `timeout`：Agent 检测上下文取消或截止时间到达，保留已采到的证据。
- `unavailable`：未安装 `traceroute`。
- `failed`：工具启动或执行失败（例如权限不足、不支持所用参数或缺少 IPv6 路由），保留工具原始错误。

## Agent 运行边界

Linux Agent 声明能力；需预先安装支持 `-4/-6 -n -q -w -m` 的 Linux `traceroute`。不自动安装工具、不调用 shell、不提权、不调用外部 IP/ASN 服务。以 UDP 探测，固定每跳 1 包、最多 20 跳、每跳等待 1 秒，单地址族总时间 12 秒。IPv4/IPv6 并行运行，Agent 同时最多接受两个检测请求（最多四个子进程）；繁忙时立即拒绝，不无限排队。

每地址族原始输出上限 32 KiB，数值跳点最多 20 条；关闭反向 DNS。面板请求整体 15 秒超时。现有命令通道不会把浏览器断开直接转发为 Agent 取消；断开后面板停止等待，Agent 最迟在自己的 12 秒截止时间终止子进程。Agent 检测上下文取消也会终止子进程。Agent 异常退出时，工具进程可能继续到其自身的逐跳上限结束，首版不承诺父进程死亡即刻回收。本功能不创建任何代理用户，也不写入客户计费；探测仍可能消耗服务器网卡流量。

原始输出可能含私网跳点和节点网络信息，结果仅返回给管理员，不接入公开探针或普通用户接口。

## 仍未完成

这是节点到所指定测试 IP 的路径证据，不是测试点到节点的正向路径，也不是客户到代理网站的业务验证。ECMP、ICMP 限速和防火墙可造成缺跳，不能据此推断完整物理线路。已合并的首版不返回 ASN/运营商归属，也不持久化；本轮本地补充历史和路径变化对比，详见后文，仍不发告警。

本轮补充历史保留和同目标/地址族的路径比较。事件通知、ASN 数据来源、测试点配置/UI 仍待后续实现。

## 验证

回归覆盖地址族与目标校验、双栈独立结果、原始证据、缺失工具、执行失败、上下文取消、输出/并发上限、明确的命令参数、不可达标记、旧 Agent 与离线节点，以及管理员/节点操作员权限。命令执行测试使用临时夹具程序验证参数；不以此声称已验证真实公网路由、全部 traceroute 发行版或 IPv6 连通性。

## 历史与路径变化对比（本轮本地实现）

检测命令发出前，在面板数据库中为每个地址族创建一条记录；一次双栈请求共享 `runId`。`POST /nodes/:id/route-trace` 保留原有 `results`，另返回 `history` 元数据。命令失败、无效 Agent 结果或请求中断也会结束对应记录，不保存 Agent 任意错误字符串。离线、旧 Agent 或请求校验不通过时未执行命令，不创建历史。

- `GET /nodes/:id/route-traces?limit=20&before=123&family=ipv6&target=2606:4700:4700::1111`：管理员分页历史。默认 20、最多 100 条；`before` 为前一页返回的 `nextBefore`，0 表示已无下一页。`family` 与 `target` 均可省略。IP 目标按标准写法归一化，IPv6 不同文本形式不会拆成不同历史。
- `GET /nodes/:id/route-traces/:traceId`：管理员详情，包含原始输出。详情必须同时匹配节点 ID 和记录 ID。

列表和 POST 的 `history` 不返回原始输出正文（`result.raw` 为空），但保留逐跳地址；原有 POST `results` 仍包含本次原始输出。节点操作员、普通用户、API 令牌和公开探针不获得新接口权限。

记录的 `state` 为 `running`、`completed`、`failed` 或 `interrupted`；其中 `completed` 仅表示命令返回了有效结构，仍需看 `result.state` 判断是否到达。面板异常退出或 HTTP handler 丢失后的未完成记录超过 30 秒在读取时显示为 `interrupted`；下一次检测开始时持久化这一状态，迟到结果不会将其改回成功。

历史按数据库分配的尝试 ID 倒序排列，不按 Agent 的采样时钟或结果返回顺序排列。已结束的尝试不能被重复完成覆盖；新尝试先返回、旧尝试后返回时，最新记录仍是新尝试。历史不会因旧结果补到而重新计算既有比较结果，也不会发送补偿通知。

`comparison.state` 包括：

- `baseline`：当前结果完整，但同范围尚无之前记录。
- `same` / `changed`：同节点、同目标、同地址族、同检测 profile，前后均已到达目标，TTL 从 1 连续且每跳恰有一个有效地址；按每跳的规范 IP 比较，变化位置在 `changedTtls`。
- `not_comparable`：未完成、缺跳、超时、失败、工具缺失、前一条记录不完整、profile 改变、采样间隔超过 24 小时、面板时间逆序或两次执行重叠。`reason` 给出原因。

仅与同范围紧邻的前一条尝试比较，遇到失败不会越过它去比较更旧的成功结果。RTT 文本、原始输出格式和 Agent 时钟变化不参与路径比较。路径长度不同也会计入相应 TTL 的变化。

变化仅表示两次 UDP traceroute 观察到的 IP 路径不同。ECMP、路由器不同接口回复和临时路由都可能产生差异；不能据此断言运营商、ASN 或物理线路发生变化。本轮不发送通知。

保留最近 7 天，每节点最多保留 100 条已结束记录（双栈占两条）；运行中的记录暂保留，下次检测会将过时记录收敛后纳入数量清理。读取时也按有效期过滤；定期清理过期记录。较早的 `previousId` 可能因保留策略已不可查询。

节点删除在同一事务清理历史；完成回调会重新确认节点和原尝试仍存在，不能重新创建记录。配置备份不导出这些运行观测，恢复配置时清空旧历史，避免把恢复前证据当成恢复后的检测结果。持久化失败返回错误，不将未保存的结果声称为已记录。

新增回归覆盖分页、目标归一化、原始输出隔离、完整/缺跳/重叠/过期比较、迟到与重复完成、并发创建、失败结果留痕、节点删除、保留上限和备份恢复；保留 PostgreSQL 与竞态验证。
