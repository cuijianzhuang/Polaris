# 节点双栈回程检测（首版）

仅管理员后端/API，沿现有节点命令通道执行，不改 UI。PR #156 的 TCP 测试点采集继续使用原调度；本功能按需运行，不新增周期探测流量。

## 请求

`POST /nodes/:id/route-trace`

```json
{"ipv4":"1.1.1.1","ipv6":"2606:4700:4700::1111"}
```

可只指定一个地址族。目标必须是对应地址族的公网 IP 字面量，不接受域名、端口、IPv4 映射 IPv6、本地/私有/链路本地地址或网卡 zone，面板和 Agent 均校验。不以 DNS 自动降级为另一个地址族，也不从当前管理连接推断用户所在网络。需管理员自行选择有代表性的运营商测试地址。

旧 Agent 未声明 `route-trace-v1` 或节点离线时返回 409。命令失败或返回格式错误为 502；两种地址族分别返回执行结果，单个地址族失败不丢弃另一个结果。

```json
{"nodeId":"NODE_ID","results":[{"family":"ipv4","target":"1.1.1.1","checkedAt":"2026-10-24T02:00:00Z","state":"partial","hops":[{"ttl":1,"addresses":["192.168.1.1"]},{"ttl":2,"addresses":[]}],"raw":"..."}]}
```

`checkedAt` 为 Agent 开始采样的时间。状态：

- `reached`：探测输出包含目标地址回复，未带不可达标记；不代表 TCP、代理认证或实际业务已通过。
- `partial`：保留已观察到的跳点，未证明到达目标；星号只表示该次探测无回复，不称为丢包率。
- `timeout`：Agent 检测上下文取消或截止时间到达，保留已采到的证据。
- `unavailable`：未安装 `traceroute`。
- `failed`：工具启动或执行失败（例如权限不足、不支持所用参数或缺少 IPv6 路由），保留工具原始错误。

## Agent 运行边界

Linux Agent 声明能力；需预先安装支持 `-4/-6 -n -q -w -m` 的 Linux `traceroute`。不自动安装工具、不调用 shell、不提权、不调用外部 IP/ASN 服务。以 UDP 探测，固定每跳 1 包、最多 20 跳、每跳等待 1 秒，单地址族总时间 12 秒。IPv4/IPv6 并行运行，Agent 同时最多接受两个检测请求（最多四个子进程）；繁忙时立即拒绝，不无限排队。

每地址族原始输出上限 32 KiB，数值跳点最多 20 条；关闭反向 DNS。面板请求整体 15 秒超时。现有命令通道不会把浏览器断开直接转发为 Agent 取消；断开后面板停止等待，Agent 最迟在自己的 12 秒截止时间终止子进程。Agent 检测上下文取消也会终止子进程。Agent 异常退出时，工具进程可能继续到其自身的逐跳上限结束，首版不承诺父进程死亡即刻回收。本功能不创建任何代理用户，也不写入客户计费；探测仍可能消耗服务器网卡流量。

原始输出可能含私网跳点和节点网络信息，结果仅返回给管理员，不接入公开探针或普通用户接口。

## 仍未完成

这是节点到所指定测试 IP 的路径证据，不是测试点到节点的正向路径，也不是客户到代理网站的业务验证。ECMP、ICMP 限速和防火墙可造成缺跳，不能据此推断完整物理线路。历史和路径变化对比已通过 #161 合并；默认关闭的变化通知已通过 #162 合并，见后文。目前不返回 ASN/运营商归属。

历史保留和路径比较已合并。默认关闭的路径变化通知已合并。本轮本地补充按节点定时检测，见后文；ASN 数据来源、测试点配置/UI 仍待后续实现。

## 验证

回归覆盖地址族与目标校验、双栈独立结果、原始证据、缺失工具、执行失败、上下文取消、输出/并发上限、明确的命令参数、不可达标记、旧 Agent 与离线节点，以及管理员/节点操作员权限。命令执行测试使用临时夹具程序验证参数；不以此声称已验证真实公网路由、全部 traceroute 发行版或 IPv6 连通性。

## 历史与路径变化对比（#161 已合并）

检测命令发出前，在面板数据库中为每个地址族创建一条记录；一次双栈请求共享 `runId`。`POST /nodes/:id/route-trace` 保留原有 `results`，另返回 `history` 元数据。命令失败、无效 Agent 结果或请求中断也会结束对应记录，不保存 Agent 任意错误字符串。离线、旧 Agent 或请求校验不通过时未执行命令，不创建历史。

- `GET /nodes/:id/route-traces?limit=20&before=123&family=ipv6&target=2606:4700:4700::1111`：管理员分页历史。默认 20、最多 100 条；`before` 为前一页返回的 `nextBefore`，0 表示已无下一页。`family` 与 `target` 均可省略。IP 目标按标准写法归一化，IPv6 不同文本形式不会拆成不同历史。
- `GET /nodes/:id/route-traces/:traceId`：管理员详情，包含原始输出。详情必须同时匹配节点 ID 和记录 ID。

列表和 POST 的 `history` 不返回原始输出正文（`result.raw` 为空），但保留逐跳地址；原有 POST `results` 仍包含本次原始输出。节点操作员、普通用户、API 令牌和公开探针不获得新接口权限。

记录的 `state` 为 `running`、`completed`、`failed` 或 `interrupted`；其中 `completed` 仅表示命令返回了有效结构，仍需看 `result.state` 判断是否到达。面板异常退出或 HTTP handler 丢失后的未完成记录超过 30 秒在读取时显示为 `interrupted`；下一次检测开始时持久化这一状态，迟到结果不会将其改回成功。

历史按数据库分配的尝试 ID 倒序排列，不按 Agent 的采样时钟或结果返回顺序排列。已结束的尝试不能被重复完成覆盖；新尝试先返回、旧尝试后返回时，最新记录仍是新尝试。历史不会因旧结果补到而重新计算既有比较结果，也不会发送补偿通知。

`comparison.state` 包括：

- `baseline`：当前结果完整，但同范围尚无之前记录。
- `same` / `changed`：同节点、同目标、同地址族、同检测 profile，前后均已到达目标，TTL 从 1 连续且每跳恰有一个有效地址；按每跳的规范 IP 比较，变化位置在 `changedTtls`。
- `not_comparable`：未完成、缺跳、超时、失败、工具缺失、前一条记录不完整、profile 改变、采样间隔超过 25 小时（给每日调度预留执行余量）、面板时间逆序或两次执行重叠。`reason` 给出原因。

仅与同范围紧邻的前一条尝试比较，遇到失败不会越过它去比较更旧的成功结果。RTT 文本、原始输出格式和 Agent 时钟变化不参与路径比较。路径长度不同也会计入相应 TTL 的变化。

变化仅表示两次 UDP traceroute 观察到的 IP 路径不同。ECMP、路由器不同接口回复和临时路由都可能产生差异；不能据此断言运营商、ASN 或物理线路发生变化。路径变化通知见后文，默认关闭。

保留最近 7 天，每节点最多保留 100 条已结束记录（双栈占两条）；运行中的记录暂保留，下次检测会将过时记录收敛后纳入数量清理。读取时也按有效期过滤；定期清理过期记录。较早的 `previousId` 可能因保留策略已不可查询。

节点删除在同一事务清理历史；完成回调会重新确认节点和原尝试仍存在，不能重新创建记录。配置备份不导出这些运行观测，恢复配置时清空旧历史，避免把恢复前证据当成恢复后的检测结果。持久化失败返回错误，不将未保存的结果声称为已记录。

新增回归覆盖分页、目标归一化、原始输出隔离、完整/缺跳/重叠/过期比较、迟到与重复完成、并发创建、失败结果留痕、节点删除、保留上限和备份恢复；保留 PostgreSQL 与竞态验证。

## 路径变化通知（#162 已合并）

新增运维事件 `route_changed`，Webhook 类型为 `node.route_changed`。通知策略接口的事件目录返回 `defaultOff: true`、`cooldown: true`。Telegram、邮件和 Webhook 均默认关闭此事件；需管理员按渠道显式开启。现有渠道总开关、管理员订阅、节点权限及 Webhook 事件过滤继续生效。

先 `GET /notifications/policy` 读取现有配置，再在原配置相应渠道中设置 `route_changed: true` 后 `PUT` 保存。PUT 为完整替换，须保留原有事件开关、维护窗口和重复窗口。例如只开启 Telegram：

```json
{
  "repeatWindowSeconds": 300,
  "channels": {
    "telegram": {"route_changed": true},
    "email": {"route_changed": false},
    "webhook": {"route_changed": false}
  },
  "maintenance": []
}
```

仅在完整、可比较的检测结果为 `changed` 时产生事件；基线、路径相同、缺跳、失败、过期、重叠和不可比较结果不产生事件。事件随历史事务成功提交后生成，回滚不发；重复完成同一记录不重发。事务检查时已有同节点/目标/地址族的更新尝试，则旧尝试仅保留历史，不发迟到提醒。提交后发生的新检测及异步渠道处理仍可能影响消息到达顺序，不承诺跨渠道严格排序。

消息包括节点名、目标 IP、地址族、变化 TTL 和前后记录 ID；Webhook 数据包含 `node_id`、`family`、`target`、`trace_id`、`previous_trace_id`、`changed_ttls`、`observation_only`。不携带原始逐跳地址或原始输出，不把路径变化称为业务故障。节点操作员可能按既有通知权限收到摘要，但详情 API 仍仅管理员可读。

此事件按渠道、接收人、节点及目标/地址族共用冷却窗口，使用现有 `repeatWindowSeconds`。与普通的“相同内容合并”不同，窗口内即使路径再次变化也合并，避免 ECMP/路由抖动持续刷屏；下次允许发送的新变化附带合并数量。窗口设为 0 时每次可比较变化均可发送，但重复完成仍不生成第二个事件。维护窗口及渠道关闭不积压旧事件，结束后不会补发；仅未来的新变化重新判断。已经持久化、待重试的 Webhook 暂停期间保留原事件，按既有策略恢复重试。

配置损坏或无法读取时，本默认关闭事件停止新投递并暂停其 Webhook 重试；其他既有运维事件的故障回退行为不变。历史记录继续保留，不因通知关闭而停止检测。

通知继承当前的尽力交付边界：提交后进程退出、事件通道满或发送失败都可能导致未收到通知。Telegram/邮件没有新增持久发送队列；Webhook 仅在已入交付队列后持久重试。没有新增后台周期检测，按需调用检测后才可能产生变化事件。

新增回归覆盖默认关闭、独立渠道、冷却合并、节点维护、Webhook 重试静默、无效配置关闭投递、事务回滚、迟到及跨实例重复完成，以及原始网络证据不进入消息。

## 按节点定时检测（本轮本地实现）

新增管理员接口：

- `GET /nodes/:id/route-schedule`：配置、运行游标、Agent 能力、在线状态和全局暂停状态。
- `PUT /nodes/:id/route-schedule`：完整替换该节点配置。首次 GET 默认为关闭、60 分钟、无目标且运行游标为 null，不发起网络请求。

```json
{
  "enabled": true,
  "targets": {"ipv4": "1.1.1.1", "ipv6": "2606:4700:4700::1111"},
  "intervalMinutes": 60,
  "expectedRevision": 0
}
```

启用至少需要一个对应地址族的公网 IP，并要求节点已声明回程检测能力；离线但已支持的节点可预先配置。间隔 5–1440 分钟，省略或为 0 时使用 60 分钟。`expectedRevision` 可省略；建议使用 GET 返回的 policy.revision，版本不符时返回 409。相同配置不重复递增版本、不重复审计、不推迟下一次执行；真正修改配置后重新安排下一个间隔。PUT 是完整替换，暂停时若要保留目标和间隔，应提交原配置并将 enabled 改为 false。

启用后首次检测在一个间隔之后执行；需要立即检测时继续使用手动接口。定时和手动调用共用同一命令执行、结果校验、历史、路径对比及通知逻辑。历史增加 `source`（manual / scheduled）和 `scheduleRevision`，旧记录没有 source 时按 manual 展示。

Leader 每 30 秒检查到期配置，每轮最多取 16 个节点、并发 4 个节点，工作预算 25 秒；剩余预算不足完整命令窗口时留到后续轮次。单节点双栈仍最多两个地址族并行。检测周期从本轮调度时间向后安排，不补跑错过的历史时间点；不承诺精确到秒的执行时间或固定每日整点。

跨实例通过节点数据库锁及持久游标抢占，推进游标与创建本次历史记录在同一事务内完成，未提交的抢占不发送命令。节点离线、Agent 退回旧版本、配置损坏或已有未结束的手动/定时检测时，本轮跳过并安排下一个间隔，避免离线节点占据整个候选队列或密集重试。进程在抢占后、发送前退出会丢失该轮检测，不会在重启时重复补发；下个间隔恢复正常工作。

`runtime.lastState` 反映最近调度/执行状态：waiting、running、completed、failed、interrupted、offline、unsupported、busy 或 invalid_policy。completed 表示获得有效结果，是否到达仍查看每个地址族的历史 result.state。运行状态仅对当前配置版本有效；旧回调不能覆盖新版本或新运行游标。

全局 `probe_enabled=false` 同时暂停周期 TCP 测试点和本功能；手动检测仍可调用。关闭/修改配置不会撤回已提交的在途命令，Agent 最长仍受已有执行截止时间约束。旧配置版本的完成结果保留为历史，但在事务检查时配置已关闭、版本改变或全局探针已暂停，则不生成该定时结果的变化通知。已进入异步投递的通知不能保证撤回。

定时配置不会自动开启变化提醒；通知仍需按渠道单独开启。没有新增公共探针展示，也没有修改 UI、客户计费、内核配置或触发核心重载。

配置随备份保留，运行游标不导出；恢复后清空运行游标和检测历史，首次调度仅安排未来一个间隔，不立即对全部节点集中探测。节点删除同时清理配置、游标和历史。历史完成回调匹配节点、记录 ID 与 runId，即使记录编号复用，也不能由旧回调写入新尝试。

新增回归覆盖默认关闭、版本冲突/无操作保存、跨实例单次抢占、全局暂停、离线/旧 Agent/手动检测繁忙跳过、并发上限、预算/取消、抢占回滚、备份恢复、权限、旧配置通知抑制及编号复用防护。ASN 归属与 UI 仍待后续实现。
