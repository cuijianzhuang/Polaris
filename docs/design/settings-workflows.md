# 设置工作流与移动端完善

## 实现顺序与范围

1. 未保存保护：邮件、通知、备份、常规、自动更新、登录防护注册当前草稿。分区切换、侧栏、命令跳转、后退和退出登录统一提供继续编辑、放弃修改、保存后离开。保存成功才继续导航；接口失败、重复点击、无效 SMTP 端口不会导致丢输入或重复提交。访问地址、密码、SSO 和待上传数据库等需要逐项确认的操作只提供继续编辑或放弃，不会在离开时自动应用、更改密码或上传文件。刷新/关页注册浏览器原生 beforeunload 提醒。
2. 手机交互：保留横向标签，增加末端渐隐提示和 44px 点击区域。软键盘缩小 visual viewport 时收起底部导航，将保存操作条移到可见区域上方；失焦或键盘收起时恢复。
3. 设置精简：常规配置保持可见，高级访问限制、证书验证、部署信息默认折叠。域名配置的原说明保留在“配置前请阅读”下，服务端动作的确认流程仍存在。
4. 保存反馈：共用保存条明确展示加载中、待保存、保存中、已保存和保存失败。字段在提交期间禁用；同步锁阻止连续点击重复写入；失败显示接口原因并保留字段及替换密码，允许重试。SMTP 端口的范围错误显示在字段旁。
5. 浏览器验证：工作流回归覆盖 Chromium/WebKit、390/1440px、中英文及带后台路径的导航。旧探针、外观和运维回归继续运行。

## 实现要点

React Router 使用 data router 的导航阻断接口，设置分区同步 URL hash。未保存弹窗约束键盘焦点并在提交期间禁止关闭；关闭时恢复焦点。草稿仅保存在 React 内存中，密码、令牌和配置输入不会写入 localStorage/sessionStorage。背景数据的读取不触发自动提交。

保存后离开采用各表单自身的校验与提交函数，多个草稿依次保存；任一失败即停留。已经成功写入的表单不会回滚，也不会将仍有错误的其他表单标记为成功。

## 验收边界

浏览器回归的接口均为合成数据。键盘用 visual viewport 事件模拟，不能替代真实 iPhone 上键盘、地址栏伸缩、安全区域与浏览器原生关页提示的人工验收。WebKit 自动回归并不等于 iOS Safari 真机验收；浏览器是否显示 beforeunload 提醒取决于平台支持与用户交互条件。
