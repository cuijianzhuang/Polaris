# 设计：授权管理（许可证）

状态：已实现：社区源码许可证（AGPL-3.0-only）、授权框架、联网激活、功能开关；授权服务器（私有仓库 polaris-license）；闭源拆分（私有仓库 polaris-pro，见第 9 节）。待定：节点 / 用户上限数值

## 1. 先说清楚一个前提

仓库 `cuijianzhuang/Polaris` 是公开仓库，社区代码采用根目录 [LICENSE](../../LICENSE) 中的 GNU AGPL v3.0，SPDX 标识为 `AGPL-3.0-only`。

- **AGPL 允许商业使用**：使用和分发时应履行协议规定的对应源码提供、版权声明等义务；对修改版提供网络服务时，需按协议第 13 条向交互用户提供对应源码获取方式。它不要求所有商业使用者都必须购买授权。第三方依赖及独立内核遵循各自许可证。
- **公开源码 = 技术校验挡不住会改代码的人**：任何人都能删掉校验、自己编译。所以许可证要分两层：
  1. **源码许可**：社区代码采用 AGPL-3.0-only；在 AGPL 条款之外使用或分发，须另行取得相应权利人的授权。未公开的专业版代码由相应权利人另行许可。
  2. **技术层**：官方发布的二进制文件校验许可证，限制节点数 / 用户数 / 高级功能。目的是"让付费变成最省事的选择"，不追求无法破解。

**采用方案：开源核心 + 闭源高级功能（open core）。**
- **社区代码**采用 AGPL-3.0-only 许可：面板、Agent、内核管理、订阅。面板激活码属于产品功能授权，不改变社区代码的开源协议。
- **私有高级功能**由 `polaris-pro` 提供，用 Go build tag `pro` 编入专业版：客户独立限速、Telegram 高级管理、备份推送、订阅转换、DDNS 等，具体范围以实际私有代码与相应授权条款为准。已经公开在本仓库中的代码仍适用本仓库的开源许可证。
- 专业版由社区代码和另行许可的私有代码构建，使用与分发时应分别满足相关权利人的授权条款。

## 2. 许可证文件

一个用 **Ed25519** 签名的 JSON，用 base64 编码成一段文本，方便复制粘贴。

```json
{
  "id": "lic_8f2k…",
  "customer": "某某公司",
  "email": "admin@example.com",
  "plan": "pro",
  "limits": { "nodes": 20, "users": 2000, "plugins": 10 },
  "features": ["speed_limit", "sso", "costs", "reports", "tg_menu"],
  "instance": "inst_3h9x…",
  "issued_at": "2026-10-17",
  "expires_at": "2027-10-17",
  "updates_until": "2027-10-17"
}
```

字段说明：
- `limits`：数量上限，0 或缺省表示不限。`plugins` 是可同时安装的插件数；社区版（无许可证）固定为 3，授权后以许可证为准（0 不限）。
- `instance`：绑定的面板实例，可以为空（不绑定）。
- `expires_at`：到期时间，为空表示永久授权。
- `updates_until`：在这个日期之前发布的版本都可以使用。

- **签名**：私钥只放在授权服务器上，公钥在构建时写进二进制。面板不联网也能校验（离线验证）。
- **实例 ID**：面板首次启动时随机生成一个 `inst_…` 存进数据库，是可迁移的身份。换服务器时用备份恢复即可带走，不绑硬件，避免迁移麻烦。
- **防止多台共用一个许可证**：联网激活时，授权服务器记录"许可证 → 实例"的对应关系。同一个许可证只能有一个活跃实例，迁移时先在旧实例点"停用"，或在授权后台解绑。

## 3. 套餐与限制（示例，可调整）

| 套餐 | 节点数 | 用户数 | 高级功能 | 价格思路 |
|---|---|---|---|---|
| 社区版（免费，无需许可证） | 3 | 100 | 无 | 引流 |
| 专业版 | 20 | 2,000 | 全部 | 年付 |
| 企业版 | 不限 | 不限 | 全部 + 优先支持 | 年付 / 买断 |

## 4. 到期和超限时怎么处理（原则：绝不中断已有服务）

| 情况 | 行为 |
|---|---|
| 节点数或用户数达到上限 | 不能再新增，提示升级套餐；已有的继续工作 |
| 许可证到期 | 降回社区版的限制；已有的节点和用户**继续运行**，超出部分只是不能编辑或新增；高级功能变为只读（已生效的限速保持不变）；提前 30 / 7 / 1 天在面板和 Telegram 提醒 |
| 版本发布日期晚于 `updates_until` | 不允许升级到这个版本（面板在线升级时提示），当前版本可以一直用 |
| 联网校验失败（授权服务器不可达） | 保留 14 天宽限期；超过后暂停管理修改，已有代理、订阅、流量上报和后台任务继续运行；联网校验成功或导入有效离线许可证后恢复 |
| 许可证被吊销（退款、滥用） | 下次联网校验时生效，处理方式同"到期" |

## 5. 面板端实现

- **新增 `internal/license` 包**：
  - `Parse(text) (*License, error)`：校验签名和字段；
  - `Current()`：返回当前生效的许可证，没有则返回社区版默认值；
  - `Allow(feature)`、`Limit("nodes")`：供各处判断。
- **执行点**：
  - 创建节点（`api_nodes.go`）、创建或导入用户（`api_users.go`）：检查上限；
  - 高级功能的 API 统一加一个中间件 `requireFeature("speed_limit")`，未授权时返回 402，并说明需要的套餐；
  - Agent 不做校验，许可证只在主控上判断，避免节点因为授权问题断线。
- **设置页「许可证」**：
  - 显示当前套餐、到期日、节点和用户用量条；
  - 支持粘贴许可证文本，或输入激活码联网激活；
  - 提供停用（迁移用）按钮；
  - 未授权的功能入口显示锁标记和"升级"链接，不直接隐藏，用户才知道有这个功能。
- **命令行**：`polaris license show | install <文件> | deactivate`。
- **联网校验**：面板启动时异步执行一次，此后每 6 小时加 0–30 分钟随机延迟，`POST /v1/check {license_id, instance, version}`，返回状态和吊销标记。只上传这三项，不上传任何用户数据，并在隐私说明里写明。

## 6. 授权服务器（新的私有项目）

- 一个小型 Go 服务 + 简单的管理后台：
  - 签发许可证（选套餐、填客户、设期限）；
  - 激活 / 停用 / 解绑实例；
  - 吊销列表；
  - 续费延期（重新签发一份新文件）。
- **对外接口**：`/v1/activate`、`/v1/deactivate`、`/v1/check`。
- **支付**：初期手动签发（客户付款后在后台点"签发"，系统发邮件或 Telegram）；后期再接支付平台的 webhook，付款成功后自动签发。
- **私钥安全**：只放在授权服务器的环境变量或密钥管理里，离线备份。另外准备一把备用密钥，二进制里同时内置两把公钥，私钥泄露时可以轮换。

## 8. 需要你决定

1. **商业模式**：开源核心 + 闭源高级功能（推荐），还是整个项目改为闭源（仓库转私有）？
2. **限制维度**：按节点数、用户数、高级功能，三者都用吗？各套餐的具体数值是多少？
3. **授权方式**：年付订阅，还是买断 + 一年更新（`updates_until`）？
4. **是否需要联网激活**：联网可以防止一个许可证多台共用；纯离线更简单，但只能靠实例绑定。

## 9. 闭源拆分（已实现）

- **两种构建**：
  - 不加标签编译的是**社区版**；
  - 加上 polaris-pro 的源文件、用 `-tags pro` 编译的是**专业版**（官方发布包）。
- **私有文件**放在 `cuijianzhuang/polaris-pro`：
  - 路径和公开仓库一一对应，例如 `internal/panel/backuppush_pro.go`；
  - 文件第一行是 `//go:build pro`；
  - 构建时由 `scripts/pro.sh copy` 放进公开仓库的同名目录，属于同一个 Go 包；
  - 公开仓库的 `.gitignore` 忽略 `*_pro.go`。
- **社区版空实现**（`*_oss.go`，标签 `!pro`）：
  - `internal/agent/limiter_oss.go`：没有限速器，内核不会接入限速转发；
  - `internal/panel/edition_oss.go`：不生成用户限速、不推送备份；
  - `internal/panel/telegram_admin_oss.go`：管理菜单只显示“专业版”说明；
  - `internal/panel/edition_ddns_oss.go`：订阅源 / 订阅组和域名绑定 / DDNS 的接口返回 402，组订阅 `/sub/p/` 不输出，节点 IP 变化只记录不跟随。
  - `internal/panel/brand_oss.go`：自定义 Logo（`branding`）上传返回 402，始终显示内置 Logo。
- **专属主题**（`themes`，例如黑金）是纯前端样式：许可证不包含时主题卡片锁定，已选的专属主题自动退回默认主题。
- **社区版构建的许可证状态**：
  - 不论许可证或试用期如何，高级功能都不可用；
  - 许可证页提示“社区版构建”；
  - 设置限速返回 402。
- **许可证校验**保留在公开代码里：专业版构建同样需要有效的许可证或试用期。
- **发布流程**：
  - 仓库 Secret `PRO_TOKEN`（对 polaris-pro 只读）存在时，发布流程编译专业版，CI 也会额外跑专业版测试；
  - 不存在时编译社区版，并在 Actions 里给出警告。
- **本地开发**：运行 `scripts/pro.sh link ../polaris-pro`，改动直接写回私有仓库。
- 旧版本的这些代码仍在公开仓库的历史记录里，拆分只影响之后的版本。

## 10. 全部高级功能与授权服务器地址

- **全部高级功能**：许可证的 `features` 里带 `*` 时，面板开放当前版本的所有高级功能，包括以后新增的。授权服务器签名时同时写上当前的功能列表，不认识 `*` 的旧版面板照常生效。
- **授权服务器地址**的优先级：
  1. 环境变量 `POLARIS_LICENSE_SERVER`；
  2. 旧版本保存的地址（兼容现有部署，页面和管理 API 均不可修改）；
  3. 构建时内置的 `LICENSE_SERVER`。
  地址由部署端管理。许可证页面及接口不返回地址或配置来源，仅展示最近一次授权通信状态和时间；未通信过显示“尚未校验”，不将已配置等同于连接正常。旧修改接口及通用设置接口均拒绝修改地址，连接错误不回传 URL，历史地址修改审计对外脱敏。
- **立即校验**：许可证页面可立即检查授权变更，校验请求之间有 30 秒冷却，并与自动校验互斥；过于频繁时返回 HTTP 429 和 `Retry-After`。

## 11. 联网校验调度与断网恢复

- 面板运行时启动独立、可取消的校验循环，不阻塞 HTTP / Agent 服务启动。无许可证、无效许可证和离线许可证不发校验请求。
- 每次成功后，在 6 小时加 0–30 分钟随机延迟后再次校验，避免所有实例在固定时刻请求。连续失败分别在 5 分钟、30 分钟后重试，再失败则每 2 小时重试；成功后回到正常间隔。间隔从上一请求结束计算，重启时重新执行启动校验。
- 自动校验与手动校验共用重试状态，手动成功会取消旧的失败退避。检查、激活、导入及停用串行执行，避免旧请求结果覆盖新许可证。面板关闭会取消在途自动校验。
- 只有有效的授权服务器响应才能刷新 `license_check_at`；`ok:false` 且没有明确吊销结果、无效续签文件和请求失败均不延长宽限期。明确吊销沿用原有降级规则。
- 本地导入在线许可证不算联网成功。缺少历史成功时间时，使用持久化的首次导入时间 `license_online_since` 作为宽限期起点；重复导入、停用再导入及面板重启均不刷新此起点。导入已记录吊销的在线许可证也不会自行清除吊销状态。运行中面板每分钟检查 CLI 导入变更，受设置缓存影响通常在 1–2 分钟内生效。
- 超过 14 天未成功校验时，保留套餐、功能与运行配置，仅将管理操作设为只读；到达边界时按当前时间判断，不等待下次网络重试。已生效代理、流量结算、订阅、用户自助和后台任务继续工作。
- 只读限制覆盖管理员 REST 的修改请求（含 API 令牌、插件调用）及 Telegram 管理修改。GET / HEAD / OPTIONS 读取、身份验证与账号安全、许可证安装/激活/停用/校验、面板升级和 API 令牌撤销保留原有权限及 sudo 检查，便于恢复。用户/节点新增、编辑、删除、同步和管理侧续期等修改暂停。
- 有效离线许可证仍只做本地签名、实例、版本和有效期校验。断网宽限期不改变离线许可证或无联网许可证的社区版/试用规则。
