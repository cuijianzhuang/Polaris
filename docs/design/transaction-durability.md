# 订单、计费与备份的故障一致性

## 订单权益

新在线订单在下单时保存版本化 `entitlements`，交付时按快照设置账户流量、有效期、重置策略和设备/IP 限制；流量包保存额度与适用套餐。Stars 仅复用权益快照也相同的未付款订单。商品的节点访问、限速及降级策略保持动态；套餐已删除则记录开通失败并由管理员处理，不恢复已删除的路由授权。没有快照的旧订单无法还原当时权益，保留原交付规则。损坏/未知版本快照不得回退成当前商品。

## USDT 报价

`usdt_reservations` 以链、规范化地址和金额为主键，订单与预留在同一事务中创建；唯一约束冲突时尝试下一个尾数。已支付或取消的订单也保留报价，直到订单有效期与创建时间较晚者再加 3 小时，并额外保留 1 分钟，覆盖链上时间戳的匹配容差。遗留无地址订单的金额也会避让。

新订单固定收款地址；专业版按链与原地址分组扫描，EVM 游标隔离到地址。交付事务失败时返回错误，扫描不会跳过该区间。旧订单没有保存地址，只能继续使用配置地址；请在其处理完毕后再切换。无法自动消除升级前已发生的同额冲突，需按原始付款凭证人工核对。升级多实例集群时必须使全部实例使用相同修复版本，旧进程不受新预留约束保护。

## 在线备份

全部表和分页共享一个读事务。PostgreSQL 使用只读 REPEATABLE READ；SQLite 使用 WAL 读事务快照。事务覆盖数据导出，不覆盖压缩及 S3 上传；文件格式和恢复入口保持兼容。回归在读取账户后并发结算，再恢复备份，验证已结算与待结算流量守恒。

## Agent 队列

队列和递增序号以临时文件写入、文件同步、原子替换、目录同步持久化。写入失败时标记 dirty，保留内存并暂停周期采集；上报前必须先持久化。确认后的裁剪失败可以在重启后重放旧批次，由面板持久化去重处理，不能为新流量复用旧序号。读取错误、损坏 JSON 或非法序号拒绝启动。

该实现不能消除「内核已清零、Agent 尚未持久化就崩溃」的窗口，也不能在磁盘长期不可用且进程被强制终止时挽救内存数据。存储故障和队列容量丢弃均写入错误日志；运维应监控日志并优先修复存储。
