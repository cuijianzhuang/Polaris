# REALITY 目标发现与复核

参考 [REALITY 目标筛选文章](https://www.aspchang.com/posts/reality-steal-domain/) 和 [XTLS/RealiTLScanner](https://github.com/XTLS/RealiTLScanner)，沿用项目原生 Go 扫描引擎，在现有 Shodan 发现功能之上，采用“发现候选 → 对目标地址实测 → 填入已验证的 target / SNI”的流程。

## 本轮实现

### 发现候选

Shodan 保存为面板侧加密密钥，通过现有二次验证设置接口写入；接口和页面仅显示配置状态、套餐和查询额度。Agent 只接收候选地址、SNI 和索引元数据，不接收 API Key。

发现表单支持国家、ASN、网段及自定义查询。ASN 接受 `AS64500` 或 `64500`，网段要求合法 CIDR。自定义查询已有同名过滤条件时沿用查询内条件，最终实际查询会显示在结果区，字段参考 [Shodan 过滤条件](https://www.shodan.io/search/filters)。网段字段只过滤 Shodan 索引；主动 CIDR 探测仍由独立的手动扫描入口触发。

每页最多 100 条、一次最多 3 页。候选包含原始服务 IP/端口、独立 SNI，以及 Shodan 返回的 ASN、组织、国家。SNI 优先从证书 SAN 中选择具体域名，再考虑 CN 和主机名；通配符保留为证书信息，不能通过去掉 `*.` 推断出可用 SNI。没有域名线索时由实测读取证书继续发现。

按地址和 SNI 配对去重。同一证书部署在多个 IP 上时，每个 IP 都保留。后续页失败会保留已取得的候选并显示错误及实际读完的页数；发现结束后刷新额度信息。

### 验证地址与 SNI

1. 手填域名以该域名作为 SNI；Shodan 候选以原始 IP 拨号，独立发送候选 SNI。
2. 对没有 SNI 的 IP，先读取默认证书发现具体域名，再连接同一个实际 IP，携带该 SNI 重新握手。最终检查以第二次握手为准。
3. 校验信任链、有效期、域名匹配、TLS 1.3 和 h2；展示实际协商的密钥交换、证书信息、链大小及最终 TCP + TLS 握手耗时。
4. `target` 保留实际配置的拨号目标；`serverName` 表示本次尝试的 SNI；只有基础检测通过时才返回可填入的 `names`，其中仅含实际验证的 SNI。完整证书 SAN 放在 `certNames`，供查看证书详情。
5. 点击“使用”同时填入 target 和已验证的 SNI，不将 IP 替换为可能解析到其他地址的证书域名。

“基础检测通过”描述本次 TLS 结果。X25519MLKEM768、ML-DSA 所需链大小是额外兼容性信息；链大小为证书 DER 字节总量，不能替代完整 REALITY 部署测试。首页状态、跳转、CDN 和长期可用性属于进一步评估。Shodan 的国家和组织是索引信息，同 ASN 或低延迟也不能证明同机房。

### 执行位置与兼容

新版面板使用 `reality_scan_v2` 命令向在线节点传递结构化候选，新 Agent 同时保留旧命令。旧 Agent 不认识新命令、或节点离线时，面板可自行验证并明确显示来源及复测提示。节点执行失败、超时和无效返回直接报错，避免悄悄从面板重复扫描后当作节点结果。

每次输入最多 512 个目标，手动 CIDR 每段最多展开 256 个地址，并发最多 32 个；单个候选的发现与复核共享 6 秒预算。超出总数在发起连接前报错。面板本地扫描响应请求取消；远程命令随 Agent 连接上下文结束，关闭浏览器只会停止面板等待，完整任务取消需要后续的显式任务协议。

## 后续设计

| 能力 | 实施方式与验收标准 |
| --- | --- |
| HTTP 首页复核 | 可选开启，使用同一目标 IP/SNI 发起限时请求；记录状态码和 Location，限制响应体，明确是否跟随跳转，保留实际检测来源。 |
| CDN 与网络关系 | 使用有版本和来源的 ASN / CDN 数据，分别显示匹配证据、未知状态和更新时间；按用户选择筛选，不把组织名关键词当作确定结论。 |
| 外部扫描结果导入 | 按 CSV 表头读取 IP、ORIGIN、CERT_DOMAIN 等字段，兼容上游新旧列顺序；导入后仍复核 IP/SNI，通配符不能直接填入。 |
| 长任务与取消 | 任务 ID、进度、明确的 Agent 取消命令、断线状态及每节点并发额度；取消必须停止排队和进行中的连接。 |
| 候选池复测 | 保存选择的地址/SNI及上次检测来源和时间，定期复测并提示失效；替换入站目标由管理员确认。 |

上述能力作为后续阶段，本轮仅交付前述发现、实测和配置链路；界面不将尚未执行的检测显示为通过。

## 验证

本地 TLS 虚拟主机覆盖“无 SNI 时合格、带 SNI 时不合格”、名称不匹配、同证书多个服务地址和重复候选。Shodan 使用模拟 API 检查 ASN/CIDR、具体 SAN、元数据、分页中断与密钥不回显。节点命令测试区分新 Agent、旧 Agent 回退、执行失败和异常响应；浏览器检查表单、来源标识与一键填入的地址/SNI配对。
