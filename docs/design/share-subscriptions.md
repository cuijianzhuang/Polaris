# 分享订阅（独立凭据 / 独立限额 / 独立计量）

> 状态：设计稿（2026-11-27，D1–D9 待审定）。借鉴 flyx 的「分享订阅」：用户把自己的订阅分享出去时用独立凭据、独立流量限额、到期自动断开；SS/SS2022 还能按订阅独立密码、独立计量。
>
> 一句话方案：**flyx 的前半截 Polaris 已有，后半截只缺一个「分享」对象**——独立凭据、用户流量限额、到期停用、SS 每用户独立密码与独立计量都已实现且有代码证据（§3）；真正的缺口是：一个用户只有**一套**订阅凭据，把订阅给别人用只能交出主链接，泄露或收回都只能全量轮换、连带掐断自己。本设计新建 `ShareSubscription` 实体（独立 token + 独立节点凭据组 + 独立限额/到期 + 独立计量），其余全部复用现有凭据、渲染、计量与执行路径，不重复造已有能力。
>
> 产品定位：沿用既定口径——付费许可证解锁全部高级功能、不单卖拆卖；分享上限的载体（设置项 vs 许可证字段）留作拍板点（D6）。

## 1. 角色

| 角色 | 域 | 说明 |
| --- | --- | --- |
| **全局管理员** | 全部用户 | 用户详情看其名下分享列表与用量；可代吊销单个分享（滥用处理）；调全局每用户分享上限 |
| **订阅用户（分享方）** | 自己的分享 | 门户自助新建/改备注/改限额与到期/启停/吊销/看每份分享的用量与最后活跃 |
| **被分享者** | 无账号 | 只持有一条订阅链接，不登录、不出现在用户列表里；其全部流量记在分享名下、归分享方主账号总账 |

| 操作 | 全局管理员 | 分享方（仅自己的） | 被分享者 |
| --- | --- | --- | --- |
| 新建/修改/吊销分享 | —（v1 不代建） | ✓（上限内） | — |
| 代吊销任意用户的分享 | ✓ | — | — |
| 拉取分享订阅 | — | ✓ | ✓（持链接即可，与主订阅现状一致） |
| 看分享用量/最后活跃 | ✓ | ✓ | —（订阅信息头可见剩余额度，见 §6） |
| 改主账号额度/到期 | ✓ | — | — |

## 2. 目标与非目标

### 目标

- 用户可并行持有多份分享，每份有独立 token、独立节点凭据（UUID/Password/SSSeed）、独立流量限额、独立到期、独立启停/吊销、备注名。
- 吊销一份分享只掐断这一份：旧链接立即 404、其节点凭据从节点配置移除；主订阅与其他分享不受影响（与现状「全量轮换连带掐断自己」相对）。
- 每份分享独立计量：门户/面板能按分享看已用流量；分享超额只停该分享，主账号超额/到期/停用连带停全部分享。
- SS/SS2022 在分享维度同样独立：每分享独立 SSSeed 派生独立密码、按分享身份独立计量（内核例外如实标注，见 §5）。

### 非目标（v1 刻意不做）

- 分享的独立授权范围：分享继承分享方的全部入站授权，不做「这份分享只给某几个节点」（节点子集留 v2 议题）。
- 用户 × 入站交叉用量（按分享 × 入站拆账）：现有标签计数不分用户（§3），要做必须改采集协议，成本另议（D8）。
- 分享转让、分享商城化、被分享者注册转化：不做。
- 给分享单独的速度/IP/设备限制：v1 沿用主账号口径（IPLimit/DeviceLimit 仍按主用户计，见 §9 的已知取舍）。

## 3. 现状核实（差距结论，逐项带代码证据）

| flyx 卖点 | 结论 | 证据 |
| --- | --- | --- |
| 订阅凭据与登录密码独立 | **已有** | `store.User`（`internal/store/models.go:176,230`）：`Password` 是下发内核的订阅凭据，`PasswordHash` 是用户中心/member 登录密码，注释明示严格分离；订阅另有独立 `SubToken`（:187，唯一索引） |
| 流量限额、到期自动断开（账号级） | **已有** | `User.TrafficLimit/ExpireAt`（`models.go:178,181`）；`computeStatus`（`internal/panel/traffic.go:711`）推导 limited/expired，`enforceLimits`（:561）落状态并通知；节点侧 `inboundUsers`（`internal/panel/spec.go:324,339`）只下发 active（及带流量包的 limited）用户；订阅侧 `servedUser`（`internal/panel/nodequota.go:90`）同口径 |
| SS 传统密码按用户独立 | **已有** | 每用户随机 `SSSeed`（`models.go:177`，建号时 `pki.Token(24)`，`internal/panel/api_users.go:267`）；`model.User.SSKey`（`internal/model/spec.go:28`）：传统密码直接用用户 `Password`（每用户不同） |
| SS2022 按用户独立密码 | **已有** | `SSKey` 对 2022 密码派生 `HMAC-SHA256(SSSeed, method)` 截断至密码长度；入站级只有服务器 PSK `Protocol.ServerKey`（2022 协议本身要求）；客户端密码 = `ServerKey + ":" + 用户Key`（`ssClientPassword`，`internal/panel/inbounds.go:398`）；sing-box 渲染 `users[]{name,password}`（`internal/core/singbox/singbox.go:368`）、xray 渲染 `clients[]{password,email}`（`internal/core/xray/xray.go:347`），均为每用户一条 |
| SS 按用户独立计量 | **已有（两个内核）/ 没有（mihomo）** | 内核按用户身份回传 `model.TrafficDelta{UserID}`（`internal/model/spec.go:315`），xray/sing-box 的 SS 身份即用户；**例外**：mihomo 的 SS 监听是单用户模型，只有服务器 PSK、无法按用户计量（`internal/core/mihomo/mihomo.go:226` 注释明示），该组合下订阅直接下发 `ServerKey`（`inbounds.go:399`） |
| 泄露后吊销 | **部分有（只有全量轮换）** | 管理员 `POST /users/:id/reset-token`（`internal/panel/api_users.go:865`）、门户 `POST /u/reset`（`internal/panel/portal.go:603`）、Telegram 自助（`internal/panel/telegram.go:718`）都走 `rotateUserCredentials`：SubToken/UUID/Password/SSSeed **整组轮换**——旧链接与已导入节点立即失效，但分享方自己的一切客户端同样失效 |
| 「分享」作为独立对象（多份并行、独立吊销/限额/到期/用量） | **没有** | `User` 的凭据字段全是单值（`models.go:172` 起），全仓无分享实体；`SubProfile`（`models.go:1032`）是管理员的组合订阅/转换档案（外部来源 + 处理组，`PanelUserID` 只是引用某用户节点），没有独立凭据、限额与计量，**不是**分享对象，不复用（D1） |
| 按节点拆用量看 | **部分有** | `TrafficHourly/TrafficDaily`（`models.go:453,1213`）是 用户 × 节点 粒度；但入站粒度只有 `TagTraffic`（`models.go:1449`，节点 × tag 全量合计、不分用户），用户 × 入站交叉不存在 |
| 按分享计量 | **没有** | `TrafficDelta` 只有 `UserID` 一个维度，结算 `settle`（`traffic.go:213`）只归用户总账 `UsedUp/UsedDown` |

**结论**：要补的只有三件——①分享实体本身；②分享维度的计量归账与超额执行；③分享独立到期。其余皆为复用与接线。

## 4. 数据模型（只增不删，符合迁移纪律）

新增一张表 `share_subscriptions`（`store.ShareSubscription`），主用户凭据保持不动、即「第 0 号主订阅」，存量用户零迁移、零行为变化：

| 字段 | 说明 |
| --- | --- |
| `ID`（string, 主键, size 32） | 同时用作计量合成身份的后缀（§6） |
| `UserID`（string, size 32, index） | 分享方（主用户） |
| `Name`（string, size 64） | 备注名（如「给父亲」「备用机」），列表与审计展示用 |
| `Token`（string, size 64, uniqueIndex） | 订阅 token，`pki.Token(32)`，与 `users.sub_token` 同强度 |
| `Enabled`（bool） | 启停开关；吊销 = 删除行（凭据一并销毁，不留软删） |
| `TrafficLimit`（int64） | 本分享流量上限（字节），0 = 不限（仍受主池总闸约束，D3） |
| `UsedUp / UsedDown`（int64） | 本分享自创建以来累计（不随主周期重置，见 §7） |
| `ExpireAt`（*time.Time, index） | 本分享到期；nil = 跟随主账号（取先到，D5） |
| `CredUUID / CredPassword / CredSSSeed` | 独立节点凭据组，生成方式与主凭据相同（`pki.UUID()/Password(20)/Token(24)`）；`CredSSSeed` 不出 JSON（照 `User.SSSeed` 的 `json:"-"`） |
| `LastUsedAt`（*time.Time） | 最后活跃：订阅被拉取或产生流量（二者取近，节流写，D9） |
| `CreatedAt / UpdatedAt` | 常规 |

不改 `User`、不改 `TrafficDelta`、不改 Agent 协议（§6 的合成身份在面板内闭环）。

## 5. 凭据与渲染

- **订阅解析双路**：`GET /sub/:token`（`internal/panel/router.go:99`，处理在 `internal/panel/subscription.go:33`）先按现状查 `users.sub_token`；未命中再查 `share_subscriptions.token`（Enabled 才认）。命中分享后，渲染所用身份换成分享凭据组，授权集合仍是分享方的 grants（`subNodesFor` 的 `GrantsSQL` 不变）。
- **节点侧身份**：节点配置构建 `inboundUsers`（`spec.go:324`）在每个主用户之外，为其每份「有效分享」（启用 ∧ 未到期 ∧ 未超额 ∧ 主用户本身在下发集合内）追加一条 `model.User`：UUID/Password/SSSeed 用分享凭据组，`ID` 用合成身份 `主用户ID + "#" + 分享ID`（D4）。内核侧据此天然按分享区分连接与计数；SS2022 客户端密码由现有 `ssClientPassword` 逻辑按分享 SSSeed 派生，`ServerKey:分享Key`，与主订阅互不相同、互不影响。
- **吊销即时性**：吊销（删行）/停用/改凭据后 `MarkDirty(nodesForUsers(主用户))`，与现有凭据轮换同一条下发路径；旧 token 在解析层立即 404（查不到行），旧节点凭据在节点应用新配置后失效——即时性与现有 reset-token 一致（秒级到一个下发周期），不承诺连接级硬切断（现有用户停用同样是配置下发口径）。
- **mihomo 例外（如实保留，D7）**：mihomo 的 SS 入站没有用户维度——分享在该节点上与主订阅共用 `ServerKey`、流量计回主用户总量（无法归分享）。分享的 token/限额/到期在订阅层仍独立有效（链接可单独吊销、拉取可单独停），只是该内核 × 协议组合下没有节点级独立计量。文档与门户提示均须明示，不假装全协议覆盖（与 Snell 独立模式当年标注 sing-box 例外的做法一致）。

## 6. 计量与独立限额执行

- **归账双写**：Agent 回传的 `TrafficDelta.UserID` 是内核侧身份字符串，合成身份原样透传（实现前置核查：xray email / sing-box name 对 `#` 后缀无格式校验冲突，Agent 仅透传不解析——批 2 开工先以真实内核测试钉住）。结算 `settle`（`traffic.go:213`）按 `#` 切分：主段归主用户总账（倍率、节点配额等现有口径全不变，保证**主限额永远是总闸**），同时把同一笔增量累加到对应分享的 `UsedUp/UsedDown`。分享行已删除（吊销后残余流量迟到）时只归主账，不复活分享。
- **超额执行**：结算后仅对本轮涉及的分享做超额检查（仿 `capForwards` 的定向写法，`traffic.go:546`，不做全表扫描）：`TrafficLimit > 0 ∧ Used() >= TrafficLimit` → 该分享退出下发集合（状态计算属性，不落 capped 字段，与 `computeStatus` 的推导风格一致）+ `MarkDirty` 重建相关节点 + 发 `share_capped` 通知（Telegram/邮件/Webhook，文案带分享备注名）。恢复路径：分享方调高限额或管理员给主账号加量后，下个结算/状态周期自动回补下发（分享 Used 不清零，靠限额抬升恢复；如需「重置分享用量」由分享方在门户手动执行，记审计）。
- **延迟口径（如实写明）**：计量是计费口径不是实时闸门——Agent 10 秒采集 + 结算 + 配置下发传播，超额发现与生效约 10–30 秒（与中转配额设计的同口径结论一致）；高带宽分享在这段空窗可多跑的量级与主账号相同，不因分享而放大或缩小。
- **订阅信息头**：分享订阅的 `sub.Info`（`subscription.go:56`）——Used 显示分享自身用量；Total 显示分享 `TrafficLimit`（为 0 时显示主账号口径）；Expire 显示主/分享先到者。被分享者在客户端能看到这份分享的剩余额度，不暴露主账号总量（主 Total 仅在分享不限额时按现状显示，属已知取舍，§12 未决 4）。

## 7. 到期与停用关系

| 事件 | 主订阅 | 该用户全部分享 | 单份其他分享 |
| --- | --- | --- | --- |
| 主账号到期/超额/被停用（disabled） | 停 | **连带停**（订阅层 `servedUser` 不过、节点侧身份不下发） | — |
| 主账号恢复/续期/加量 | 恢复 | 按各自状态恢复 | — |
| 单份分享到期（`ExpireAt` 到点） | 不受影响 | — | 仅该份停 |
| 单份分享超额 | 不受影响（其流量仍计入主账，主可能因此超额，那是主规则） | — | 仅该份停 |
| 单份分享被吊销/停用 | 不受影响 | — | 仅该份，凭据销毁不可恢复 |
| 主凭据被轮换（reset-token） | 换新 | **不受影响**（分享有独立凭据组——这正是本设计相对现状的改进点） | 不受影响 |

- 分享到期扫描并入现有 `enforceLimits` 周期（新增对 `share_subscriptions.expire_at` 的到期判定；状态是计算属性，扫描只负责触发 `MarkDirty` 与通知，不落状态字段）。
- 分享 `Used` 不随主账号周期重置（`resetTrafficCycles` 只清主账）：分享限额是「这份分享总共能用多少」的语义；周期性分享额度（如每月给家人 50GB）留 v2 议题，v1 可由分享方手动重置用量替代。

## 8. 社区版与专业版

主案：**不新增许可证字段、不挂 Feature 开关**——分享是基础订阅能力的延伸（社区版本就有订阅），数量上限走设置项（D6）。备选案：新增 `Limits.ShareSubsPerUser`（`omitempty`、旧证无字段 = 不限，照 `UserNodes`/polaris-license PR #50 先例），社区版默认给一个小数值（如 3）。二者取舍留拍板（§12 未决 2）：选备选才需要动 polaris-license 签发侧。

## 9. 安全与滥用

- **token 强度与枚举**：与主 token 同为 `pki.Token(32)`；`/sub/:token` 现有 IP 限频（`subLimit`）对分享 token 同样生效；解析双路不改变 404 语义（不存在/已吊销/已停用一律 404，不给区分提示）。
- **防转卖可见面**：备注名、创建时间、最后活跃（`LastUsedAt`）、累计用量——够分享方识别「这份分享还在不在用、用得多不多」；不做被分享者的 IP/设备画像（`IPLimit/DeviceLimit` 仍按主用户整体计：一份分享被多人共用会更快撞主账号的 IP/设备上限，这是 v1 的已知约束，文案明示）。
- **凭据隔离**：分享凭据组与主凭据、与其他分享两两独立；任何一份泄露，轮换范围只限该份（门户「重置此分享凭据」= 只换该行 Cred* + token，主订阅无感）。
- **审计**：`share.create / share.update / share.revoke / share.reset_credentials / share.reset_usage` 全部记审计（actor 区分管理员代吊销与用户自助）；v1 不新增 webhook 事件 kind。
- **数量与体积**：每用户分享数上限（D6）同时约束节点配置体积——每个 SS/VLESS 等入站的 users 数组按「主用户 + 其有效分享」增长，节点身份总数 ≈ Σ(1 + 分享数)，上限 5 时最坏 6 倍于现规模，仍在现有下发/内核承载的量级内（批 1 验收含大入站渲染回归）。

## 10. 决策（D）

- **D1 新建 `ShareSubscription` 实体，不复用 `SubProfile`**。推荐：新建。理由：`SubProfile` 是管理员侧组合订阅（外部来源拼接 + 处理组 + 转换），`PanelUserID` 仅表示「捎带这个用户的节点」，没有独立节点凭据、独立限额与按份计量，语义和生命周期都不同，硬套会污染两边。备选（扩展 SubProfile 加凭据/限额字段）代价：组合订阅的失效联动（pro #14 的账号失效阻断整份组合）与分享语义互相打架，不取。
- **D2 每分享独立节点凭据组（UUID/Password/SSSeed），与 token 双层吊销**。推荐：是。理由：只独立 token 不独立凭据，则吊销后对方已导入的节点仍可用（节点认凭据不认 token），等于吊销无效——flyx 强调 SS 独立密码正是此意；本仓凭据生成与下发路径现成，增量只是一组字段。备选（只独立 token）代价小但功能假，不取。
- **D3 额度关系：子额度 + 主池双闸**。推荐：分享流量双写主账与分享账，主限额是总闸，分享限额是分闸。理由：托管计费口径下，主账号买到的总量不能被分享放大；分享方要控制的是「这一份最多用多少」，不是「额外多出一池」。备选（独立池、不计主账）代价：用户可凭多份分享成倍放大实际可用量，与套餐计费冲突，不取。
- **D4 计量维度：内核侧合成身份 `主ID#分享ID`，结算切分双写**。推荐：是。理由：零协议改动（Agent 只透传身份字符串）、零新采集通道，`TrafficDelta` 结构不动；切分点唯一（`settle`）。备选（给 TrafficDelta 加 ShareID 字段）代价：动 Agent ↔ 面板协议与全部内核适配器的身份映射，为同一信息多付一轮兼容成本，不取。前置核查（批 2）：合成身份在 xray/sing-box/mihomo 的 name/email 字段与统计回读中原样往返，以真实内核测试钉住；若某内核对身份字符集有限制，退路是分享方专用影子 `User` 行（IsService 类标记）——成本更高，仅作兜底记录。
- **D5 到期关系：分享独立到期 + 主到期连带，取先到**。推荐：是（§7 矩阵）。理由：与中转配额设计 D10「任一到期即停」同口径，用户心智一致。备选（分享到期独立于主、主停分享不停）等于变相续命主账号，不取。
- **D6 数量上限载体：设置项优先**。推荐：全局设置 `share_sub_max_per_user`，默认 5，0 = 关闭分享功能（新建入口隐藏、存量分享继续有效到期）。理由：先以最低成本上线，观察真实使用再决定是否升为许可证维度。备选：直接进 `Limits`（§8 备选案），代价是要等 polaris-license 签发侧配套，且「不拆卖」定位下没必要为基础能力造收费维度。**留拍板**。
- **D7 mihomo SS 例外如实保留**。推荐：接受并在门户/手册明示（该组合流量计主账、节点凭据与主共享）。理由：这是 mihomo 内核单用户模型的硬约束，现状主订阅同样如此；为分享单独绕行（如强制该节点换内核）代价与收益不成比例。
- **D8 用户 × 入站交叉用量不做**。推荐：不做。理由：`TagTraffic` 不分用户是采集层事实，补它要改内核统计映射与归账协议，与本功能的分享维度正交；分享 × 节点粒度已有（`TrafficHourly/Daily` 的节点维度可按合成身份同法扩展——批 2 顺带把分享增量写入 hourly/daily 时以合成 ID 为键即可得到分享 × 节点曲线，不额外设计）。
- **D9 最后活跃节流写**。推荐：订阅拉取时至多每小时更新一次 `LastUsedAt`（内存节流 + 落库），有流量时结算顺带更新（同节流）。理由：防高频拉取把单行写热；活跃时间是运营参考，不需要秒级精度。

## 11. 分批计划

### 批 1：实体 + 独立凭据 + 独立吊销（不含独立限额/计量）

- `ShareSubscription` 表（additive）与门户 `/u/shares`：列表/新建/改备注/启停/吊销/重置本分享凭据；每用户上限（D6 设置项）校验。
- 订阅解析双路 + 渲染影子身份（分享凭据组进 `inboundUsers` 合成身份，但计量暂全归主账——合成身份在 settle 先做「剥后缀归主」的兼容处理，保证批 1 不丢量、不错量）。
- 分享独立到期扫描接入 `enforceLimits`；主停用连带、主轮换不连带（§7 矩阵中除计量外的行）。
- 验收：建一份分享 → 拉订阅 → xray/sing-box 节点可用、SS2022 密码与主订阅不同；吊销后旧链接 404 且新配置中该分享凭据消失、主订阅与其余分享无感；主 reset-token 后分享仍可用；分享到期只停该份；大入站（多用户 × 多分享）渲染与下发回归通过。

### 批 2：独立计量 + 独立限额执行

- settle 切分双写（主账 + 分享账 + hourly/daily 合成键）、分享超额定向检查与自动停发 + `share_capped` 通知、门户按分享用量/剩余额度展示、订阅信息头分享口径（§6）。
- 前置：合成身份真实内核往返测试（xray / sing-box / mihomo 各一，含 SS2022）。
- 验收：分享跑量，主账与分享账同增、两者之差恒为非分享流量；分享超额只停该份、主与其他分享继续；主超额全停；吊销后迟到流量只归主账不复活分享；mihomo SS 流量归主账且门户有例外标注。

### 批 3（打磨，按需）

- 面板管理员侧：用户详情「分享订阅」区（列表/用量/代吊销）、全局上限设置入口、手册与门户文案（含 mihomo 例外说明）。
- 验收：管理员代吊销即时生效且审计可查；手册口径与实现一致。
