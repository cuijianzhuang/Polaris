# 端口转发商品化（专业版）

2026-10-25。属于专业版的「套餐加购」功能（与流量包、套餐节点倍率用同一个许可证开关 `plan_addons`），不需要重新签发许可证。

## 管理员

在套餐编辑页的「端口转发」区块里设置：

| 字段 | 含义 |
| --- | --- |
| 最多条数 | 用户最多能建几条转发；0 表示不开放 |
| 每周期转发流量 | 和代理流量分开计算；留空表示不限 |
| 端口范围 | 入口端口只能在这个范围里；留空为 10000–60000 |
| 转发倍率 | 在节点倍率之上再乘；留空为 1 |
| 每条限速 | 每个方向各自限速（单位 Mbps），通过 GOST 实现 |

规则：

- 用户购买或开通套餐时，这些权益会复制到账号上，并记入订单快照。之后改套餐，已开通的用户要等下次开通或续费才更新，和套餐的流量、到期规则一致。
- 用户只能在**自己能用的节点**上开转发，也就是套餐授权的入站所在的节点。
- 「端口转发」列表里，用户建的规则会带「用户 xxx」标签。管理员可以照常编辑或删除，也可以用 `GET /forwards?user=<id>` 筛选。

## 用户

套餐包含转发时，用户中心会出现「🔀 我的转发」入口（`/u/forwards`），可以：

- 选择节点和协议（TCP / UDP / 两者），填写目标「地址:端口」。入口端口可以留空，由系统在套餐的端口范围内自动分配。
- 查看已用条数、本周期的转发流量和限速。
- 删除转发。

写操作需要用户中心的 CSRF 请求头，并且按 IP 限制频率。

## 安全

- 一律使用 GOST 引擎。realm 不能按规则统计流量，也不能限速。
- 目标必须是公网地址：拒绝内网、本机、链路本地（包括云厂商的元数据地址）、组播和 0.0.0.0/8，也拒绝面板所管理节点自身的 IP。
- 填写域名时，在添加那一刻由面板解析，并固定为 IP 写入配置，之后 DNS 怎么变都不会让转发指向内网。目标 IP 变了，需要删除后重新添加。
- 用户不能使用隧道、出口 IP、PROXY protocol 等高级参数。

## 计量与停用

- GOST 按规则上报流量（标签为 `fwd-<规则 ID>`）。结算时按「节点倍率 × 转发倍率」计入账号的 `fwd_used`，不占代理流量。原有按入站、出站的流量统计照常保留。
- 用完本周期的转发流量后，`fwd_capped` 置为 true，该用户的转发不再下发，同时通过 Telegram / 邮件 / Webhook 通知（事件类型 `user_forward_capped`）。代理不受影响。
- 周期重置、续费、自动续费时，转发流量清零，转发恢复。
- 账号停用、到期、超出代理流量时，转发和代理一起停用。
- 套餐条数调小后，按创建时间先后保留前 N 条，其余的不再下发（规则本身不删除）。
- 删除用户时，他的转发一并删除。
- 许可证失效后，用户的转发全部停止下发，也不能再新建；管理员自己建的转发不受影响。
