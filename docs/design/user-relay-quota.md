# 用户级中转配额（管理员直授 + 自有节点自助转发）

> 状态：设计稿（2026-11-27，D1–D10 待审定）。借鉴 flyx 的「用户隧道授权」：管理员给普通用户分配中转额度（流量上限、每月重置日、规则数上限、到期日），中转与订阅额度分开计算，用户在门户自助管理转发，超额/到期自动暂停、重置后自动恢复。
>
> 一句话方案：**不新建第二套转发体系**——现有套餐转发（[forward-shop](forward-shop.md)）的归属、计量、执行、门户全部复用；本设计只补三块缺口：①管理员**不经套餐直接给单个用户授额度**（flyx 的主形态，现只能由套餐应用写入）；②中转有**独立的重置日与到期日**，不再搭订阅周期（现 FwdUsed 随账号周期清零、无套餐的用户永不重置）；③注册用户能在**自己的节点**上建转发（现可选节点只有套餐授权入站所在节点，member 面板无转发路由）。
>
> 产品定位：沿用既定口径——付费许可证解锁全部高级功能、不单卖拆卖；本功能继续挂在现有许可证开关 `plan_addons` 下（见 §5、D4），不新造收费维度。

## 1. 角色

| 角色 | 域 | 说明 |
| --- | --- | --- |
| **全局管理员** | 全部用户 + 全部规则 | 给用户直授/调整/收回中转额度；看全部用户规则（现有「用户 xxx」标签与 `?user=` 筛选）；随时删改用户规则 |
| **订阅用户** | 自己被授予的转发额度 | 已有套餐转发（forward-shop）；本设计后也可被管理员直授（无套餐或套餐外追加） |
| **节点管理员（注册用户 / member）** | 自己的节点 + 自己被授予的转发额度 | 在门户自助建转发，可选节点新增「自己的已批准节点」；面板 member 视图 v1 不开转发（见 D6） |

| 操作 | 全局管理员 | 订阅用户 | 节点管理员（仅自己） |
| --- | --- | --- | --- |
| 直授/修改/收回用户中转额度 | ✓ | — | — |
| 在运营授权节点上建/删自己的转发 | ✓（代建，归属管理员） | ✓（额度内） | ✓（额度内） |

| 看全部用户规则与用量 | ✓ | —（仅自己的） | —（仅自己的） |

## 2. 目标与非目标

### 目标

- 管理员在用户编辑处**直接填写**中转额度（条数、每周期流量、端口范围、倍率、限速、独立重置日、独立到期日），不经套餐、不产生订单，保存即生效。
- 直授额度与套餐额度**来源可辨、优先级明确**（D2），两边都写入同一组执行字段，计量与暂停只有一条路径。
- 中转周期与到期**独立于订阅**：无套餐的注册用户也有每月重置；中转到期不连带订阅、订阅到期也照旧停中转（任一到期即停，D10）。
- 注册用户能在自己已批准的节点上建转发，与在运营节点上共用同一额度池（条数、流量合并计）。
- 超额/到期自动暂停、周期重置/延期后自动恢复，全部沿用现有下发过滤与通知，不新增执行器。

### 非目标（v1 刻意不做）

- 面板 member 视图内的转发写操作（门户已覆盖自助面；member 路由当年刻意排除 relay，见 §3）。
- 逐条规则审批（权益即许可，D8）。
- 用户间转让额度、额度商城化（直授不走订单/支付；要卖请用套餐转发）。
- 用户规则参与链式中转（Chain/RelayFor）、隧道、PROXY protocol 等高级参数（与 forward-shop 的安全边界一致）。
- realm 引擎的用户规则（不能按规则计量与限速，现状即如此）。

## 3. 现状与复用点

调研结论：**flyx 的模型在 Polaris 里已经实现了大半**，载体是套餐转发。本设计的增量必须建立在以下现状上，不另起炉灶：

- **规则已有归属**：`store.ForwardRule`（`internal/store/models.go:807`）已有 `UserID`（`""` = 管理员规则，size 32 带索引）、`Enabled`、引擎、限速（`RateIn/RateOut/MaxConns`，gost）等全部字段。**本设计不需要给规则加 owner 字段**（简报假设需要，经核实已有）。
- **额度字段已有**：`store.ForwardEntitlement`（`models.go:795`）含 `FwdMax`（条数，0 = 不开放）、`FwdPortLo/Hi`（0 = 10000–60000）、`FwdTraffic`（每周期字节，0 = 不限）、`FwdRate`（倍率，0 = 1）、`FwdSpeedMbps`（每条每方向限速）；同时内嵌于套餐 `Group`（`models.go:327`）与 `User`（`models.go:271`），`User` 另有 `FwdUsed`（本周期已用）与 `FwdCapped`（已触顶）。语义约定与本设计完全一致：**0 的含义按字段区分**（条数 0 = 不开放、流量 0 = 不限），不引入 -1。
- **执行点已收口**：`internal/panel/forward_shop.go`——`fwdServes`（:70，许可证 `plan_addons` ∧ 账号 active ∧ `FwdMax>0` ∧ 未触顶 ∧ 未用尽）、`createUserForward`（:149，条数/节点/端口/目标校验齐全）、`userForwardAllowed`（:202，下发时按归属过滤，套餐缩水保留最早 N 条）、`deleteUserForward`（连带删该规则的 `TagTraffic`）。下发过滤挂在节点配置构建 `internal/panel/api_forwards.go:337`。暂停形态是**规则不进节点配置**，不是下发禁用标记。
- **计量已分开**：Agent 每 10 秒采集一轮（`internal/agent/agent.go:142` `cfg.Traffic = 10s`，`trafficLoop` 采集+上报，磁盘队列保证面板宕机不丢量），GOST 按规则以 `fwd-<规则ID>` 标签上报；面板 `settleTraffic`（`internal/panel/traffic.go:203`）按「节点倍率 × 用户 FwdRate」结算入 `fwd_used`（:255–287、:371–409），与代理流量 `UsedUp/UsedDown` 完全分开；结算后 `capForwards`（:546）置 `FwdCapped` 并发 `user_forward_capped` 通知（Telegram/邮件/Webhook）。
- **重置搭订阅周期（缺口所在）**：`FwdUsed/FwdCapped` 只在三处清零——账号周期重置 `resetTrafficCycles`（`traffic.go:725`，daily/weekly/monthly/cycle，monthly 用账号 `ResetDay`）、自动续期（:681）、套餐重应用且 reset 时（`internal/panel/plans.go:104`）。**没有套餐、没有 ResetPolicy 的注册用户永远不会被重置**，直授前必须先补独立重置（D3）。
- **到期搭账号到期（缺口所在）**：`fwdServes` 只看账号 `Status`，而 `computeStatus`（`traffic.go:711`）由账号 `ExpireAt` 与代理流量推导——中转没有自己的到期日。
- **授予路径只有套餐（缺口所在）**：管理员 `updateUser`（`internal/panel/api_users.go:651`）可直改代理侧的 `TrafficLimit/ExpireAt/ResetPolicy/ResetDay`（直授在代理侧是既有范式），但**不含任何 Fwd 字段**；Fwd 权益只能由套餐应用整组写入（`plans.go:101`），且订单快照留痕。
- **门户已就绪**：`/u/forwards`（`internal/panel/router.go:146`，`portal_forwards.go`）列表/新建/删除齐全，写操作有 CSRF（`portalWrite`）与 IP 限频（`ticketLimit`）；入口显隐在 `portal.go:467`（`FwdMax>0` ∧ `plan_addons`）。可选节点来自 `fwdNodes`（`forward_shop.go:79`：用户被授权入站所在的节点，经 `GrantsSQL`）——**不含用户自己的节点**（缺口 ③）。
- **member 面板刻意无转发**：`memberRoutes`（`internal/panel/memberlogin.go:41`）没有任何转发路由，批 2 注释明确「node publication, relay, CDN and template routes are deliberately absent」；`memberNodeScope`（:127）每请求现算（`owner_id` = 本人 ∧ `review_state = approved`）。另注意 [user-nodes](user-nodes.md) 的红线是「用户节点不参与**中转**（RelayFor）」——指公共链式中转；在自己节点上开一条只服务自己的 L4 转发是另一回事，本设计在 §9 显式区分，不偷改红线。
- **端口分配已串行化**：`createUserForward` 在 `relayMu` 内用 `randomFreePort` 在权益范围内选口并做 `forwardPortConflict` 校验，与管理员规则、入站共用同一冲突域；删规则即回收，无保留期。权益校验 `validFwdEntitlement` 已限制端口范围 ≥1024、条数硬顶 `fwdMaxPerUser = 100`（`forward_shop.go:23`）。
- **目标安全已收口**：`fwdTarget`（`forward_shop.go:93`）创建时解析并固定 IP，拒绝内网/本机/链路本地/云元数据/面板所管理节点自身 IP，用户规则不能用隧道/出口 IP/PROXY 等高级参数。
- **许可证先例**：限额走 `Limits`（`internal/license/license.go:59`，字段 `omitempty`、旧证无字段 = 不限）、质变走 Feature；社区版默认值放 `Community` 常量（`CommunityUserNodes = 3`，:47）。面板侧收紧范式是 `userNodeCap`（`internal/panel/user_nodes.go:52`：许可证上限 ∧ 套餐再收紧）。

## 4. 数据模型（只增不删，符合迁移纪律）

全部加在 `store.User` 上，存量用户零值即现状行为：

| 变更 | 说明 |
| --- | --- |
| `FwdSource`（string, size 8） | 额度来源：`""` = 无额度；`plan` = 套餐应用写入（只读，归套餐管）；`grant` = 管理员直授。存量有 Fwd 权益的用户在迁移时按 `PlanID!= ""` 回填 `plan`、否则留空待管理员认领（见 §11 批 1） |
| `FwdResetDay`（int） | 中转独立月重置日：0 = 跟随账号周期（现状）；1–28 = 每月该日独立重置（月末自动钳制，复用 `monthlyBoundary`）。仅清 `FwdUsed/FwdCapped`，不动代理流量 |
| `FwdExpireAt`（*time.Time, index） | 中转独立到期：nil = 跟随账号到期（现状）；非 nil 时与账号到期**取先到者**（任一到期即停发）。套餐应用时写 nil（套餐来源的到期由账号管） |

不新增表、不动 `ForwardRule`、不动 `ForwardEntitlement` 结构。重置所需的「上次中转重置时间」不另加字段：独立重置分支以 `FwdResetDay` 的月界与一个新字段 `FwdLastResetAt *time.Time` 比较（同批新增，避免借用账号 `LastResetAt` 造成两边互相踩）。

| 变更（续） | 说明 |
| --- | --- |
| `FwdLastResetAt`（*time.Time） | 上次中转独立重置时刻；仅 `FwdResetDay > 0` 时使用 |

## 5. 社区版与专业版（D4 的展开）

| 维度 | 社区版（免费） | 专业版（许可证） | 机制 |
| --- | --- | --- | --- |
| 用户自助转发（含直授） | 不开放（`FwdMax` 恒为 0 的效果） | 开放，额度数值由管理员直授或套餐决定 | 现有 Feature `plan_addons`（`fwdServes` 已收口） |
| 每用户条数硬顶 | — | 100（防呆，非收费维度） | 现有常量 `fwdMaxPerUser` |
| 许可证新增字段 | 无 | 无 | **不新增 Limits 字段**（主案，见 D4） |

理由要点：中转消耗的是**运营方**的节点端口与带宽（与自带节点消耗用户自己的机器不同），免费送中转等于运营方贴钱，不符合 [user-nodes](user-nodes.md) 给社区版留量的前提；且产品定位已定「付费解锁全部、不拆卖」，为直授再造一个 `relay_*` 限额等于把 forward-shop 已定的门推翻重议。备选案（新增 `Limits.UserRelayRules` 给社区版留引流口子）及推荐数值写在 D4 里，留给审定时拍板。

## 6. 额度来源与优先级（D2 的展开）

```text
套餐应用（含续费重应用） ──整组覆盖──▶ User.Fwd*（FwdSource=plan, FwdExpireAt=nil）
管理员直授（用户编辑） ──整组写入──▶ User.Fwd*（FwdSource=grant）
管理员收回 ──FwdMax=0──▶ FwdSource=""
```

- 同一时刻只有一个来源生效，**不做 max 合并、不做叠加**：合并规则会让「我到底有多少额度」在续费、改套餐、直授三种操作下不可预测，且订单快照与直授审计会互相打架。
- 套餐覆盖直授时，管理端在套餐应用确认里明示「该用户有直授中转额度，将被套餐覆盖」，审计各记一条（`forward.grant_overwritten_by_plan`），不静默。
- `FwdSource=plan` 时，用户编辑页的中转区只读并标注套餐名；管理员要改，先「转为直授」（整组复制当前值、来源变 grant、与套餐脱钩，后续套餐续费重应用会再覆盖——确认框明示）。
- 直授不产生订单、不进商店、不影响套餐快照；删除用户时其规则照旧连带删除（现状）。

## 7. 执行、计量与暂停（D7 的展开）

全部沿用现状机制，本节只定增量：

- **暂停**：`fwdServes` 增加两个判定——`FwdExpireAt` 已过 → 不服务；其余（许可证、账号状态、条数、触顶、流量）不变。暂停仍是下发过滤：`userForwardAllowed` 不放行 → 规则不进节点配置；恢复（重置清零/延期）后由重置路径已有的 `MarkDirty` 把相关节点标脏、下一轮构建自动带回（`resetTrafficCycles` 对 capped 用户回补节点的现成做法，独立重置分支必须照做）。
- **独立重置**：`resetTrafficCycles` 增加中转分支——`FwdResetDay > 0` 的用户（无论有无 ResetPolicy）按自己的月界清 `FwdUsed/FwdCapped` 并写 `FwdLastResetAt`；`FwdResetDay = 0` 的用户维持现状（跟随账号周期清零）。两条路径互斥，避免同周期清两次。
- **计量可信度（如实写明）**：额度是**计费/公平使用口径，不是实时闸门**。链路延迟由三段构成：Agent 采集间隔 10 秒 + 上报/结算批量 + 配置下发传播；稳态下超额发现约在 10–30 秒量级。超量幅度 ≈ 规则实际速率 × 延迟：一条跑满 1 Gbps 的规则 30 秒约多跑 3.7 GB；有 `FwdSpeedMbps` 限速时按限速封顶（如 100 Mbps → 30 秒约 375 MB）。**建议管理员给直授用户设每条限速**，把最坏超量压到可接受范围。Agent 侧磁盘队列保证面板/Agent 宕机期间不丢量（恢复后补结，`FwdCapped` 可能迟到但不漏置）。结算的字节数是**计费字节**（原始字节 × 节点倍率 × FwdRate），与代理侧口径一致，门户展示需标注「计费流量」。
- **防抖**：`FwdCapped` 置位已有幂等守卫（`capForwards` 只在 false→true 时通知一次）；重置后同周期内再次触顶同理只通知一次。不设数值宽限（见 §12 未决 4）。

## 9. 安全与隔离红线（逐条要落测试）

1. 用户规则的目标校验**不因节点归属放宽**：自有节点上的规则同样拒绝内网/本机/链路本地/云元数据/面板所管理节点 IP（v1 口径；放宽与否见 §12 未决 3）。
2. 用户只能在「授权节点 ∪ 自己已批准的节点」上建规则；pending/rejected 的自有节点、他人的节点、管理员未授权节点一律拒绝（逐类落测试）。
3. 条数与流量是**合并池**：同一用户在运营节点与自有节点上的规则合计不得超过 `FwdMax`，流量合计入 `FwdUsed`，不给「自有节点另算一份」的口子。
4. 端口冲突域全局统一：用户规则与管理员规则、入站端口同域校验（`forwardPortConflict`），先到先得，后建者报错，不抢占、不静默改口（用户指定端口被占时报错，留空时自动分配）。
5. 许可证失效（`plan_addons` 不可用）时全部用户规则停发且不能新建，管理员规则不受影响（现状，回归覆盖）。
6. 直授的写路径只有管理员：任何用户侧接口不得回写 `Fwd*` 权益字段（门户创建只读权益）。
7. [user-nodes](user-nodes.md) 的「用户节点不参与中转」红线维持原义：用户节点仍不得作为 Chain/RelayFor 的中转跳板供他人流量通过；本设计的自有节点转发是**节点主人自己的 L4 规则、流量计入主人自己的额度**，不构成「参与公共中转」。两者的区分写进用户手册，避免口径漂移。

## 10. 前端

- 管理端用户编辑页新增「中转额度」区块：来源徽标（无/套餐 xx/直授）、六个权益字段 + 独立重置日（下拉：跟随账号/每月 N 日）+ 独立到期（日期，可空）；`plan` 来源时只读 + 「转为直授」按钮。用户列表加一列中转摘要（可藏）。

- 设置页不新增开关（模式、许可证门都在既有位置）。

## 12. 风险与未决问题

1. **社区版是否留免费口子**（D4 备选案）：主案是社区版全关。若要引流，新增 `Limits.UserRelayRules`（每用户条数上限，许可证 ∧ 直授/套餐取小），社区默认建议 **3 条**（与 `CommunityUserNodes` 同范式）、流量与端口不另设社区默认（由管理员直授值决定，无直授时不可用）。代价：polaris-license 要同步发字段，且「社区版能建 3 条」会成为既成预期，收回成本高。
2. **直授与套餐的覆盖方向**：本稿定「套餐应用覆盖直授」（商品优先）。反方向（直授锁定、套餐不覆盖中转区）会让套餐商品的转发权益对老用户失效，与 forward-shop 的订单口径冲突，故不推荐；但若运营习惯是「直授是长期承诺、套餐是临时商品」，需在审定时改口径。
3. **自有节点转发到内网目标**：在自己节点上转发到自己的内网服务（NAT 穿透）是真实诉求，但面板无法区分「用户自己的内网」与「借道打运营方/云厂商内网」。v1 一律拒绝（红线 1）。若要放行，最小口径是：仅自有节点 + 目标为 RFC1918 + 排除面板/集群地址段 + 管理员全局开关默认关——留作 v2 议题，本稿不预设实现。
4. **超额宽限**：不设数值宽限（计量延迟造成的超量按 §7 估算，建议以限速压 bound）；批 3 的 80% 预警是唯一的软化手段。若运营要「超额 X% 内不停」，需在 `fwdServes` 之外加第二阈值，账目口径要另定，本稿不预设。
5. **倍率口径**：直授的 `FwdRate` 与节点倍率叠乘沿用套餐口径；管理员直授时容易误以为 FwdTraffic 是原始字节——管理端字段旁需标注「计费流量（已含倍率）」，批 1 文案落实。
6. **存量来源回填的误判**：历史上管理员若曾用 SQL/脚本直接改过某用户 Fwd 字段且其无套餐，回填会留空来源（`""` 但 `FwdMax>0`）——这类用户在批 1 上线后权益照常执行（执行不看来源），来源仅影响编辑只读判定；管理端对这类用户显示「来源未知，可认领为直授」，不阻塞。

## 13. 决策（待审定）

| # | 问题 | 推荐 | 理由（一句） |
| --- | --- | --- | --- |
| D1 | 额度模型载体 | 复用 `User.ForwardEntitlement + FwdUsed/FwdCapped`，不新建字段组；0 的语义按字段现状（条数 0=不开放、流量 0=不限），不引入 -1 | 计量/执行/门户全已按这套运转，新造一套等于两条执行路径 |
| D2 | 额度来源与优先级 | 加 `FwdSource`（plan/grant）；套餐应用整组覆盖直授（有提示+审计），不合并；plan 来源在用户编辑页只读，可「转为直授」 | 合并规则让额度在续费/改套餐/直授下不可预测；整组覆盖与现有套餐行为一致 |
| D3 | 独立周期与到期 | 加 `FwdResetDay`（0=跟随账号）与 `FwdExpireAt`（nil=跟随账号，到期取先到者）；独立重置只清中转 | 无套餐用户现永不重置、且 flyx 明确要求分开计算；复用 `monthlyBoundary` 与现有重置框架 |
| D4 | 许可证维度 | **不新增 Limits 字段**，沿用 Feature `plan_addons` 门：社区版不开放、专业版额度数值由管理员定（硬顶 100）。备选：新增 `Limits.UserRelayRules` + 社区默认 3 条 | 中转消耗运营方资源、非用户自有资源，与 userNodes 留免费量的前提不同；且定位已定不拆卖。备选留给想要引流口子时拍板 |
| D5 | 规则归属与范围 | `ForwardRule.UserID` 已有，不加字段；节点范围 = 授权入站节点 ∪ 自有已批准节点，每请求现算（仿 `fwdNodes`/`memberNodeScope`），条数与流量合并计一个池 | 归属与范围计算都已有现成范式，合并池防双份额度 |
| D6 | 自助入口 | v1 只做门户（已有 `/u/forwards`），面板 member 不新增转发路由；批 3 再评估 member 只读 | member 路由当年刻意排除 relay，写面推翻需单独安全评审；门户对注册用户本来就开放 |
| D7 | 执行与暂停 | 沿用下发过滤（`userForwardAllowed`/`fwdServes`），不下发禁用标记；恢复靠重置路径的 `MarkDirty` 回补；不设数值宽限，超量按计量延迟如实估算并建议限速压 bound | 现有形态已验证且与套餐转发同一条路径；禁用标记要改 Agent 配置协议，收益不成比例 |
| D8 | 是否审批 | 不审批：权益授予即许可，规则创建不再过人工；自有节点沿用节点本身的审批状态把门 | 与 flyx 及 forward-shop 一致；规则已有目标/端口/条数三重约束，逐条审批只积压 |
| D9 | 端口资源 | 沿用权益端口范围（默认 10000–60000、≥1024）+ `relayMu` 串行分配 + 全局统一冲突域；删即回收、无保留期；指定端口被占报错不抢占 | 分配与冲突机制已在套餐转发上验证，自有节点不另开冲突域 |
| D10 | 到期语义 | 中转到期（`FwdExpireAt` 或账号到期任一）只停发不删规则；延期/续费/重置后自动恢复；删用户连带删规则（现状） | 与套餐转发的停发模式一致，恢复零人工 |
