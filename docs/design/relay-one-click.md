# 入站一键中转与转发

> 管理界面入口现已补齐，见[界面接入说明](operations-ui.md)；文中“仅后端/API”是首版交付范围。

参考 [FLYX 中转文档](https://kure29.github.io/flyx/guide/relay) 的“围绕落地入站创建线路”思路：选择已有入站和中转节点，由面板分配端口、生成配对配置、发布中转入口并统一清理。本轮提供后端接口，现有页面布局不变。

## 能力与边界

| 模式 | 配置 | 行为 |
| --- | --- | --- |
| 原样转发 | `mode: l4` | realm 转发，按照落地协议保留 TCP / UDP；不建立代理账号，不改变原协议 |
| 认证隧道 | `mode: tunnel`，`transport: tcp` 或 `ws` | GOST 成对配置接收端和发送端，自动生成认证信息；UDP 可经隧道承载 |

一条线路支持 1–3 个中转节点，最后接到已有落地入站。节点不能重复；落地入站必须已启用且面向用户。原样转发要求落地监听地址可被上游访问；隧道可接到仅本机监听的入站。手工配置接收 PROXY protocol 的入站仍需自行匹配发送端；下文的访问保护接口可为受管原样 TCP 线路自动配对。

TCP / WS 隧道提供认证和转发，**不会额外添加 TLS 加密**；客户端原有协议及加密保持不变。一键配置暂不包含 TLS / WSS / QUIC 隧道；来源白名单与 PROXY protocol 通过独立的访问保护策略配置。现有手工配置功能保留。

```text
客户端 → 中转 A 公网入口
           → 中转 B 认证接收端 → B 本机转发端
                                  → 落地认证接收端 → 原入站
```

中间节点的本机转发端只监听 127.0.0.1，不自动开放公网防火墙；接收端固定目标，不能由客户端指定任意目的地址。认证信息加密存储，不通过管理接口返回，只随节点私有配置下发。

## 接口流程

下列路径相对于面板 `APIBase`（默认 `/api/v1`；自定义管理路径时为该路径加 `/api/v1`），使用管理员登录返回的 Bearer token。节点受限操作员和现有 API 令牌暂未开放这些新接口。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /inbounds/:id/relays/preview` | 预览，不创建资源 |
| `POST /inbounds/:id/relays` | 应用已预览方案 |
| `GET /inbounds/:id/relays` | 查看受管线路及每个节点的下发状态 |
| `PUT /inbounds/:id/relays/:rid/state` | 启用 / 停用，正文 `{"enabled": true}` 或 `false` |
| `DELETE /inbounds/:id/relays/:rid` | 删除线路及其受管入口 |
| `PUT /inbounds/:id/relay-access` | 设置来源限制与 PROXY protocol 配对 |
| `PUT /inbounds/:id/publication` | 设置发布策略，正文 `{"relayOnly": true}` 或 `false` |
| `POST /inbounds/:id/relays/:rid/diagnose` | 手动分层诊断，无需正文 |

预览请求示例：

```json
{
  "name": "香港中转 → 新加坡落地",
  "mode": "tunnel",
  "transport": "ws",
  "relays": [
    {"nodeId": "香港节点ID", "port": 24001},
    {"nodeId": "中间节点ID"}
  ],
  "remark": "业务线路"
}
```

`relays` 按连接顺序填写，不包含落地节点，落地由 URL 中的入站确定。`port` 可省略，由面板在 20000–60000 中选择；中间隧道接收端口也自动分配，必要时可用 `tunnelPort` 指定。首个中转没有隧道接收端，不填 `tunnelPort`。落地接收端口由面板分配。

预览返回 `planToken`、`expiresAt`、`chain`、入口 `address` / `port`、`network`、`ports` 和 `warnings`。`ports` 列出节点、端口、网络、引擎及是否需要公网放行，供检查云安全组。离线节点和禁用自动防火墙的节点会提示警告；预览不能保证远端离线机器上的端口空闲。

检查后，原样提交返回的令牌：

```json
{"planToken": "预览返回的完整值"}
```

方案有效期 10 分钟，绑定创建预览的管理员、目标入站和节点地址。首次应用前会重新检查端口和输入；占用端口、过期方案、节点地址或入站配置变化均需重新预览，不会静默换用别的端口。应用不要求再次提供隧道密码。

同一个方案重复提交只创建一次，也支持 `Idempotency-Key` 请求头。创建、入口关联、审计及重放记录在同一事务中提交；失败整体回滚。SQLite 写事务和 PostgreSQL 事务 advisory lock 协调一键创建。尚未部署到 Agent 的旧版本不能识别新隧道配置，应先升级参与线路的 Agent。

## 订阅与生命周期

- 创建时生成该入站的中转入口。默认发布策略下，若此前依赖默认直连发布，会保留为显式直连入口；已有直连 / CDN / 中转入口保持原有集合。创建线路不会自动切换发布策略。
- 如果原先已明确只发布中转入口，停用或故障时不会擅自新增直连入口。客户端已有订阅缓存需刷新。
- 停用线路会从期望节点配置和新订阅中移除该线路；启用时重新生成配置。
- 删除线路、落地入站或线路中某个节点时，清理该线路及所属入口，对剩余节点重新下发。手工转发、直连和 CDN 入口不随线路删除。
- 受管线路不能经旧的通用链路更新接口修改，也不能单独删除其入口；换路径时应重新预览创建，再删除旧线路。

### 仅通过中转提供

将 `relayOnly` 设为 `true` 后，用户订阅与分享链接只展开该入站的有效中转入口，过滤直连与 CDN 入口。存量默认 `false`，保持升级前行为。修改入站和创建入站也可显式传入 `relayOnly`；旧编辑器未传此字段时保留原值。导出、导入和克隆保留该策略；克隆不会复制旧线路，应为新入站另建线路。

这个开关不要求已经存在可用中转。没有中转、线路停用、删除最后一条中转或其入口时，保持不发布直连；离线也不自动退回直连。原始直连 / CDN 入口记录保留，关闭此策略后按原有记录发布，不会额外新建入口。打开策略后新建一键中转也不补建隐式直连入口。

此策略控制订阅和分享，不修改入站监听、防火墙或客户端已有的订阅缓存；TLS SNI、REALITY 目标和线路名称仍保留协议所需信息。需要限制实际直连访问时，可使用下文的来源限制；它与发布策略是两项独立配置。仅中转提供的入站不再执行原先的直接健康探测，避免把有意关闭直连误报为故障，改用线路诊断。

## 中转来源限制与真实客户端 IP

该功能仅提供管理员后端接口，当前不修改 UI。先升级面板及线路各接收节点的 Agent，并让新版 Agent 至少完成一次配置拉取。Agent 使用 `X-Polaris-Agent-Features: relay-access-v1` 声明支持，面板记录在节点的 `agentFeatures` 中；旧 Agent 无法获取带 `accessRules` 的新配置，避免把未知字段忽略后继续启动未受保护的监听。保护期间不要降级 Agent，也不要清除节点本地配置或访问规则状态文件。

对已存在的落地入站调用：

```http
PUT /inbounds/落地入站ID/relay-access
Content-Type: application/json
```

```json
{
  "enabled": true,
  "proxyProtocol": 2,
  "sourceOverrides": {
    "中转节点ID": ["203.0.113.9/32", "2001:db8::9/128"]
  }
}
```

- `enabled` 必填；开启后同时设为仅发布中转，不能单独恢复直连发布。
- `proxyProtocol` 可取 `0`（只限制来源，不传递客户端 IP）、`1`、`2`。真实 IP 自动配对目前要求受管原样 TCP 线路，以及 Xray TCP 落地入站（可配 TLS / REALITY）；不支持 UDP / 混合协议或认证隧道。入口从实际连接生成头，中间跳接收后继续传递，落地自动开启接收。存储中的手工传输选项不被覆盖，关闭策略后恢复原值。
- `sourceOverrides` 可省略。默认使用上一跳 Agent 上报的公网 IPv4 / IPv6；尚未上报时仅允许使用节点地址中的 IP 字面值，不将域名解析结果当作可信来源。NAT、专线或多个出口请明确填写实际连接来源的 CIDR；`/0` 等宽网段会扩大信任范围，应填写所需的精确地址或网段。
- 规则覆盖每一跳的接收端口。原样转发保护中间端口和落地入站；认证隧道（`proxyProtocol: 0`）保护公网隧道接收端口，本机桥接仍只监听 loopback。每个落地入站独立设置，多个受管线路合并允许来源。
- 不支持共享端口、共享回落主 / 子入站和 Caddy 共用回源入口；手工链路需先迁移为受管线路。无法确认来源、Agent 不支持或配置不兼容时拒绝启用，不会静默减弱限制。
- 节点公网 IP 或地址改变会重新下发相关线路；新旧规则切换可能短暂中断连接。停用全部线路或删除最后一条线路后，落地端口仍拒绝外部来源，不恢复直连。

接收节点必须安装 **nftables（`nft`）并具备 NET_ADMIN 权限**。这项来源限制是强制执行的访问策略，独立于“自动开放防火墙端口”开关；关闭自动开放仍需云安全组 / 系统防火墙允许合法中转来源。Agent 只维护自己的 `inet polaris_access` 表，不清空其他规则。loopback 连接不受此来源限制；本机进程仍由主机自身信任边界约束。

Agent 在启动 / 修改内核之前原子提交过渡规则：旧、新配置共用端口只允许来源交集，其他受保护端口仍保留限制。内核配置、停止进程或防火墙操作失败时不确认新版本，保留限制并报告错误；可能暂时不可用，需修复后重试。所有内核应用成功后才提交最终规则。已有连接也受来源规则约束，但 API 保存成功不代表离线节点已生效，应等待线路部署状态。

明确关闭策略：

```json
{"enabled": false, "proxyProtocol": 0}
```

向同一接口提交后，待 Agent 应用成功移除本策略的限制；`relayOnly` 保留，需要恢复直连发布时再单独修改发布策略。旧编辑器不会覆盖策略，导出 / 导入 / 克隆保留策略；克隆不复制线路，因此新落地默认拒绝外部访问，需另建线路。导入旧的只保存 `relayOnly` 的配置不会自动启用防火墙限制。

## 状态与诊断

### 修改线路名称与分享信息

管理员可以调用 `PUT /inbounds/:id/relays/:rid/metadata`，例如：

```json
{
  "name": "上海入口 → 香港",
  "remark": "运营备注",
  "shareAddress": "relay.example.com",
  "sharePort": 443
}
```

字段均可省略，省略保持原值。`name` 需要 1–64 字，修改后同时作为该入口在订阅和分享链接里的明确名称；可另传 `shareName` 自定义分享名称，或传空字符串恢复原订阅命名模板。单独修改 `shareName` 不修改管理名称。备注最多 255 字，仅用于管理。

`shareAddress` 只接受 IP 或域名，不含协议、端口、路径；国际化域名转为 ASCII，IPv6 去掉方括号。空字符串恢复使用入口节点地址，`sharePort: 0` 恢复线路入口端口。列表返回 `shareAddress`、`sharePort`、`shareName` 覆盖值；原 `address` / `port` 仍表示实际入口，避免把分享覆盖误当成监听变更。自定义分享地址和端口需管理员确保已有对应 DNS / NAT / 外部映射，接口不验证其真实业务可达性。

此接口仅修改发布元数据，不修改监听、路径、TLS SNI、来源限制、凭据、启停状态或目标版本，也不触发节点配置下发；名称、入口覆盖和审计在同一事务提交。已停用线路仍可修改，修改不会重新发布线路。多入口批次中只影响所选线路；入口记录身份保持原样。已有线路未设置分享名称时继续使用原命名模板。

### 多入口整组管理

创建返回的 `batchId` 可以用于以下管理员接口：

| 接口 | 用途 |
| --- | --- |
| `GET /inbounds/:id/relay-batches/:bid` | 查询当前仍存在的所有组成员及其部署状态 |
| `PUT /inbounds/:id/relay-batches/:bid/state` | 正文 `{"enabled": true}` 或 `false`，整组启停 |
| `DELETE /inbounds/:id/relay-batches/:bid` | 删除当前组成员及其所属入口 |

各成员状态相同时返回该状态，否则整组状态为 `mixed`，应继续检查每条线路及各节点的部署结果。整组启停和删除在数据库事务中完成，审计失败也回滚，不留下部分成员已修改的状态。重复设置相同状态不重复写入审计；全部成员删除后查询及再次删除返回 404，可用现有 `Idempotency-Key` 机制重放成功响应。

组成员按 `batchId` 明确归属，不按名称或共用节点推断；单条删除后整组操作只作用于剩余成员。共用后续节点的其他批次、手工线路和入口不会随本组删除。删除最后一组不会恢复仅中转入站的直连发布，也不解除来源限制；仍有线路时按剩余引用生成允许来源。接口不提供整组改路径或共用认证凭据。

整组操作提交的是期望状态，不代表所有节点同时完成部署。离线或应用失败的节点仍需重连并应用，查询结果保留各成员的配置版本和错误。整组启用需全部成员通过当前入站及来源限制的兼容检查，失败整体回滚，不自动降低限制。

创建成功只表示事务已保存。查询返回各节点的 `desiredRev`、`appliedRev`、`requiredRev` 和错误，汇总为 `pending`、`syncing`、`applied`、`offline` 或 `failed`。入站被关闭时为 `blocked`，线路被关闭时为 `disabled`。关闭状态表示期望配置；具体移除仍需等待 Agent 应用，不能当作立即断开所有现有连接。

`applied` 表示 Agent 已应用所需配置，不能替代真实业务连通性验证。现有 `POST /chains/:id/probe` 对中转逐跳检查 TCP 目标端口，隧道检查接收端口，并保留落地 HTTP 探测；它不是完整隧道认证、代理登录或 UDP 端到端测试。部署后还应使用真实订阅验证协议、上下行和 UDP。

### 分层诊断

`POST /inbounds/:id/relays/:rid/diagnose` 返回 `deployment`、`network`、`checkedAt`、`checks` 和汇总 `state`。它使用管理后台的管理员权限，节点受限操作员和现有 API 令牌暂未开放。每项检查包含 `kind`、`state`、来源节点、目标、延迟和说明：

| `kind` | 检查范围 |
| --- | --- |
| `deployment` | 各节点配置已应用；停用、离线、应用错误或等待下发时返回 `not_ready` 并跳过网络检查 |
| `entry_tcp` / `entry_tls_handshake` | 面板到用户线路入口的 TCP 连接；TLS / REALITY 入站还尝试 TLS 协商，延迟包含解析、连接及握手。不校验证书，也不验证 REALITY 或代理凭据 |
| `hop_tcp` | 上一跳 Agent 到下一跳监听端口；隧道使用接收端口。不能证明隧道认证正确 |
| `landing_egress_http` | 落地 Agent 自身到固定 HTTP 测试地址的出口，不经过中转或用户代理入站 |
| `proxy_business` | 当前为 `not_tested`，明确未测试代理登录、上下行、UDP 端到端业务 |

即使所有可执行检查通过，汇总也为 `partial`，`businessVerified` 保持 `false`；发现网络失败时为 `failed`，不会将“入口端口打开”误标成完整业务通过。UDP 入站跳过入口 TCP / TLS 检查；原样 UDP 转发跳过逐跳 TCP 检查；UDP 经 TCP / WS 隧道时可以检查隧道接收端的 TCP 端口，仍不能据此声称 UDP 可用。

诊断的网络检查支持请求取消并共用 15 秒超时，结果即时返回，不修改入站告警或落地路由健康，也不使用、创建用户凭据。旧链路定时探测同样对原样 UDP 返回 `skipped: true`，不再因对应 TCP 端口关闭把落地节点判为故障，此时仍以心跳状态判断节点在线。

### 真实代理业务诊断（Linux + Xray / sing-box VLESS）

管理员调用 `POST /inbounds/:id/relays/:rid/diagnose/business`。此接口与前面的只读分层诊断分开，会短暂向正在运行的 Xray 添加专用身份，启动受控客户端并回收身份。支持新 Linux Agent 管理的 Xray VLESS，以及下述限定范围的 sing-box VLESS；旧 Agent、其他内核/协议及未完成部署的线路明确返回 `unsupported` 或 `not_ready`，不借用真实用户凭据。需先升级落地 Agent，使其上报 `relay-business-v1`。

正文可省略，或指定测试服务：

```json
{
  "tcpUrl": "https://www.gstatic.com/generate_204",
  "udpAddress": "1.1.1.1:53"
}
```

TCP 测试发送带随机标记的 HTTP(S) 请求，要求 2xx 响应并读取返回数据；HTTPS 使用正常证书校验。UDP 测试发送随机名称的 DNS 查询，校验回复 ID、问题名称、类型及响应码，不把任意 UDP 数据当成功。这里验证的是请求/回包，不是吞吐量压测。目标应选择节点实际允许访问的服务；目标服务故障或路由禁止该目标也会导致诊断失败。

受控 Xray 客户端只监听本机两个固定目标转发端口，只有一个指向线路入口的 VLESS 出站，没有直连回退或公开 SOCKS 入口。它使用当前分享地址/端口覆盖值，经实际中转进入原落地入站。TLS 使用入站证书作为额外信任材料，REALITY 使用该入站的客户端公钥信息；不关闭证书检查，也不复制服务端私钥到客户端。已在 Xray 26.3.27、26.4.15、26.5.9 实测普通 TCP、TLS、TLS + Vision、REALITY + Vision，以及 GOST 多跳 WS 隧道。

Xray 临时身份采用独立的 `#diag:` 命名空间和随机 UUID，只通过内核热接口存在于内存，不写入用户表、正式 NodeSpec 或正式内核配置。接口不返回 UUID 或密码，临时客户端文件权限为 0600，正常结束时删除，Agent 恢复创建 Xray 适配器时清理遗留目录。受控客户端限制本次发出的流量目标，不为该临时身份额外创建服务端用户 ACL；拥有主机 root 权限仍属于节点本身的信任边界。

面板发送绝对到期时间，诊断执行最多 15 秒；Agent 拒绝过期任务和明显超范围的时钟偏差，避免迟到命令重新获得完整有效期。正常完成、超时、取消或连接中断后，先停止客户端，再用独立清理上下文删除身份。面板请求取消还会发送按任务 ID 匹配的取消命令，支持取消先到、启动命令后到；网络不可达时不声称已经清理成功，Agent 仍受自身截止时间约束。单节点一次只执行一个诊断，并与配置应用互斥，忙时直接拒绝。

**Agent 异常退出的保障来自 Linux 进程生命周期，而非 Xray 原生用户到期字段。** 新 Agent 创建的 Xray 和诊断客户端使用 `PDEATHSIG=SIGKILL`，创建和等待子进程的 goroutine 始终锁定同一 OS 线程，避免 Go 调度器线程退出造成误杀。Agent 被 SIGKILL 等方式终止后，内核自动终止这些进程，内存身份和已建立的诊断连接随之失效；重启从不包含临时身份的正式配置恢复。面板断连不等于 Agent 退出，不会因此停止整个 Xray。此机制不把仅暂停 Agent 的 SIGSTOP 视为进程退出，也不是独立于 Agent 调度的原生单用户 TTL。

如果热删除无法确认，停止 Xray 并从正式配置重新启动，不把不确定状态标记为业务成功。上述 Agent 退出及清理失败的兜底会断开该 Xray 的现有连接，进程停止时也可能丢失尚未采集的内核计数；正常诊断不重启共享内核。Agent 应由 systemd 或容器重启策略恢复。相比留下永久有效的临时授权，这里明确选择停止提供该进程的服务。

`checkedAt` 是面板收到并检查本次结果的时间，重用幂等键会保留原采样时间；结果不更新生产健康状态，配置改变后应重新测试。结果包含 `proxy_tcp_business`、`proxy_udp_business` 和 `credential_cleanup` 检查。只有两种真实数据验证、正常身份清理均确认完成，面板才返回 `state: passed` 和 `businessVerified: true`；任意失败或矛盾结果均不通过。`cleanupVerified: true` 也可能出现在失败结果中，表示已经通过停止内核撤销身份，不代表本次业务或恢复过程完全正常。诊断覆盖专用身份及其实际路由，不替代每个客户套餐、限速、用户条件路由的专项验收。

Agent 阻止诊断用户计数进入持久上报队列及在线用户报告，面板入账再次排除该命名空间，避免未知身份或回退路径造成用户扣量。网卡、入站/出站物理计数仍反映这些真实网络数据，不应把它们当作客户计费用量。诊断开始和结果写入审计，保持原只读诊断与生产健康状态独立。

#### sing-box VLESS + TCP + REALITY/Vision

此适配要求 Linux、落地 Agent 声明 `relay-business-singbox-v2`、心跳上报稳定运行版本 **1.13.5 或更新**，且二进制包含 `with_v2ray_api`。仅允许 VLESS、TCP、REALITY 和 `xtls-rprx-vision` 的组合；入站 JSON 覆盖、共享回落和 PROXY 协议不在首批范围内。面板使用实际 `runningVersion` 与逐用户计量能力校验，未知版本、旧 Agent 和普通无逐用户统计构建均不能运行。

**运行诊断会在开始和结束时重启该 sing-box，现有连接会中断。** sing-box 没有公开的 VLESS 动态用户接口，因此不把诊断 UUID 写入正式 `singbox.json` 再 SIGHUP。Agent 复制当前已应用配置到权限受限的 `diagnostic-*` 目录，只在这个临时副本中增加随机 `#diag:` 用户和计数项。正式用户、路由与出站保留；正式 NodeSpec、用户表和重启配置不包含诊断身份。

临时服务端与固定目标客户端都受 Linux `PDEATHSIG=SIGKILL` 约束。租约绑定面板绝对截止时间和当前 Agent 会话，断线、超时和取消都会停止临时进程；停止操作等待进程退出后才确认凭据撤销。Agent 被 SIGKILL 时子进程由内核关闭；恢复时仅加载正式配置并删除遗留私有目录。v2 Agent 在临时服务端与客户端外各启动一个独立监督进程，在启动内核前设置绝对到期时间；即使仅 Agent 被 SIGSTOP 暂停，监督进程仍会杀死到期内核并等待退出。父进程死亡信号继续作为崩溃回收保障。面板拒绝仅声明 v1 的旧 Agent，更新后需等待能力同步。该机制不依赖 Agent 调度，但不保证整机或监督进程也被暂停时的实时到期；它仍不是 sing-box 原生单用户 TTL。Xray 保持原有回收机制。

测试从分享入口地址和端口出发，经真实中转完成 VLESS + REALITY/Vision 认证，然后检查 HTTP(S) 与 UDP DNS 往返；没有直连出站回退，HTTPS 证书验证保持开启。除了 `proxy_tcp_business`、`proxy_udp_business` 与 `credential_cleanup`，还必须提供 `proxy_authentication` 和 `proxy_transfer`，后者记录该临时身份独立的 `upBytes`、`downBytes`，两者均须大于零。页面分别展示认证、TCP、UDP、上下行计量、清理和恢复失败；任一证据缺失或恢复失败都不能显示业务通过。

Agent 在替换共享进程前采集正式用户计数，并在销毁临时进程前保留期间的正式用户增量，避免正常完成时丢失普通用户流量；诊断身份计数仅进入诊断结果，不进入客户扣量队列。异常终止仍可能丢失尚未采集的正常流量尾部。临时进程已停止但正式配置恢复失败时，`cleanupVerified` 可为 true，但整体结果仍为 failed，Agent 按原有恢复流程继续处理。

真实 sing-box 1.13.5 的测试覆盖中转后的 REALITY/Vision、受信 HTTPS、不受信证书拒绝、UDP 内容校验、错误入口、会话取消、租约到期、撤销后 UUID 重放拒绝、普通用户流量保留和 Agent SIGKILL 后重启。可设置 `POLARIS_SINGBOX_DIAGNOSTIC_BIN`，运行 `go test -race ./internal/core/singbox -run 'TestLiveSingbox|TestDiagnosticRefuses'`。测试二进制需包含 `with_v2ray_api,with_utls`。CI 使用固定提交的 1.13.5 源码单独构建并运行原生诊断竞态检查；通用内核测试允许缺少这些能力的官方构建跳过诊断，专用诊断变量指向不兼容构建时则明确失败。

常规测试覆盖来源归一化、IPv4 / IPv6 网段交集、规则事务失败、缺少 nft 时阻止启动、内核失败保留限制、无法停止旧监听时不移除保护，以及策略生命周期与旧编辑器兼容。

POLARIS_REALM_BIN=/path/to/realm go test ./internal/panel -run TestLiveRelayProxyProtocol -count=1
POLARIS_NFT_DOCKER_TEST=1 go test ./internal/agent -run TestLiveAccessFirewall -count=1 -timeout 180s

## 一次创建多个并行入口

无需先改变现有页面，管理员可调用新的批量接口：

| 方法与路径 | 用途 |
| --- | --- |
| `POST /inbounds/:id/relays/batch/preview` | 多入口预览与整批端口分配，不写入线路 |
| `POST /inbounds/:id/relays/batch` | 提交完整预览令牌，原子创建全部线路 |

```json
{
  "name": "香港落地",
  "mode": "tunnel",
  "transport": "ws",
  "entries": [
    {"nodeId": "上海入口节点ID"},
    {"nodeId": "广州入口节点ID"}
  ],
  "relays": [{"nodeId": "公共中间节点ID"}],
  "remark": "两条并行线路"
}
```

`entries` 按选择顺序填写 **1–16 个不同入口**，它们是并行替代路径，不会串在一起；`relays` 是各入口之后可选的公共中间节点，省略表示各入口直接转向落地。每条路径包含入口在内最多 3 个中转节点，落地入站由 URL 确定。入口不能等于落地或任何中间节点，公共中间节点之间也不能重复。

入口可填 `port`；中间节点和隧道接收端的端口建议省略，由系统在所有路径之间统一分配。公共中间节点上的每条路径使用独立端口，显式填写会复用的固定端口时整批拒绝，不能静默换端口。每条认证隧道也使用独立凭据，不能用另一条线路的密钥连接其接收端。

预览返回一个 `batchId`、整体 `planToken`、`expiresAt`、按选择顺序排列的 `entries` 预览与去重警告。每项预览包括 `chain`、入口地址/端口、完整监听端口、网络和警告；不返回可单独提交的路径令牌或明文凭据。名称由请求前缀、入口名称和短 ID 生成，预览显示最终名称。

检查后，向 `/relays/batch` 提交：

```json
{"planToken":"多入口预览返回的完整令牌"}
```

创建返回 `batchId` 和按选择顺序排列的 `chains`。所有线路、订阅入口、创建审计和幂等响应在同一个数据库事务内提交：任一路径端口被占、节点地址/入站变化、令牌失效或写入失败，全部回滚。预览和提交均检查节点权限；令牌绑定操作账号、目标入站，且不能与单入口接口混用。

同一个预览重复提交或跨面板实例并发提交，只创建一次。支持 `Idempotency-Key`；重试时返回首次成功的响应。SQLite 写事务及 PostgreSQL advisory lock 同时协调单入口与多入口创建。

每条链路保存共同的 `batchId`，仍由原来的线路列表、状态和诊断接口管理。可独立停用或删除某个入口；其他路径及其来源保护保持有效。整批创建遵循现有 `relayOnly` 发布策略，不会为仅中转入站补建直连入口；客户端刷新订阅后可选择多个入口。`batchId` 同时用于上文的整组查询、启停和删除接口；整组改路径尚未提供。

验证覆盖原样转发/认证隧道、公共节点端口冲突、事务回滚、跨实例并发重放、订阅和来源保护。设置 `POLARIS_GOST_BIN` 后运行 `TestLiveRelayBatch`，验证 TCP/WS 认证隧道下两个入口的 TCP 与 UDP 转发、跨线路密钥隔离，以及关闭一个入口后另一入口仍可使用。

### 诊断结果的展示边界

网络诊断响应包含 `kind: network`，真实业务诊断响应包含 `kind: business`。网络检查通过时，界面只显示“已执行的网络检查通过”，同时明确代理业务未测试；`proxy_business: not_tested` 不再显示为业务失败。真实业务的 `unsupported`、`not_ready` 以中性状态展示；实际执行未通过仍保留警告，只有服务端确认业务与临时凭据清理证据后才显示业务已验证。

线路列表提供 `businessDiagnostic: {supported, reason, scope, requiresRestart}`，由与真实业务诊断入口相同的校验函数生成。支持 Xray VLESS 和上述 sing-box VLESS TCP REALITY/Vision 组合，均要求落地 Agent 声明相应能力；sing-box 还校验已上报的运行版本与计量能力。页面在执行前明确提示 sing-box 重启影响。前端在不支持或线路未应用时禁用业务诊断按钮并展示原因，网络诊断和中转创建继续可用。列表后的配置/能力变化仍由执行接口再次校验，过期的可用状态不会绕过服务端限制。
