# 用户自带节点（多用户管理自己的 VPS）

> 状态：设计稿，待审批。目标是让门户注册用户能把自己的 VPS 接入面板自助管理：自己建节点、拿安装命令、管自己节点上的入站，节点只服务主人自己的订阅账号，与管理员的公共节点池完全隔离。
>
> 一句话方案：**给 Node 加归属（OwnerID）与审批状态（ReviewState），门户侧新增一组强制归属域的节点 API，接入流程复用现有「建记录 → 一次性令牌 → Enroll 换证书」；可用性由审批状态机把门，数量由「许可上限 × 套餐上限」双层配额把门。**

## 1. 角色

| 角色 | 域 | 说明 |
|---|---|---|
| **全局管理员** | 全部用户（含在线用户）+ 全部节点 + 全局设置 | 现有面板管理员；审批用户节点、处置用户并连带其节点（§7、D6） |
| **节点管理员** | 仅自己的节点 | 注册用户的定位：自助接入并管理自己的 VPS，在自己的节点上建入站、只服务自己的订阅账号；对他人的节点与全局设置无任何权限 |

## 2. 目标与非目标

### 目标

- 注册用户在用户中心（门户）自助添加自己的 VPS：建节点记录、复制安装命令、Agent 接入后在门户看到在线状态。
- 用户只能看、管自己的节点：列表、改名/地址/标签、删节点、管自己节点上的入站（第 3 批），其他用户与管理员节点一律不可见、不可达。
- 用户节点只服务主人自己的订阅账号，绝不混入公共订阅池（见 §8 隔离红线）。
- 两种接入模式都支持，管理员在设置里切换：**审批制**（接入后待管理员批准才可用）与**开放制**（接入即用）。
- 按高级功能分层收费：社区版（免费）每个用户最多管理 **3 台**自己的服务器；持许可证可由许可证放宽或不限（见 §5）。
- 管理员在管理端能看到全部用户节点及其归属人，能审批、停用、删除。

### 非目标（v1 刻意不做）

- 用户节点进入公共池 / 出售给其他用户 / 跨用户共享。
- 用户节点参与中转（RelayFor）、进公共状态页、被模板按标签批量绑定。
- 面板替用户节点代签 ACME 证书、提供 DDNS（地址由用户直填 IP 或自有域名）。
- 用户之间的节点转让、协作管理。
- 计费打通：用户节点的流量只计入主人自己账号的用量统计，不做单独账单。

## 3. 现状与复用点

- **节点无归属**：`store.Node` 没有 Owner 概念，节点全部由管理员经 `createNode` 建立；节点相关 API 默认管理员全权。
- **接入流程现成**：建节点时生成一次性令牌（TokenHash/TokenExpires），Agent 用令牌调 `Enroll` 换 mTLS 证书（令牌原子烧毁），后续走证书通道。用户自助接入只需把「建记录」这一步搬到门户并盖归属章，流程本体不动。
- **门户现成**：注册（邮箱注册、试用套餐、IP 日限）、登录会话、`portalUser(c)` 鉴权、用户中心页面框架都有，新增「我的节点」页签即可。
- **套餐即分组**：Plan 是 `Plan=true` 的 Group，已有 TrafficLimit / DeviceLimit / IPLimit / NodeIDs 等字段，加一个 NodeLimit 同构。
- **许可分层现成**：`internal/license` 有 Features 与 Limits 两套机制，`limitOK` 是统一的超限拦截口（402 + 升级提示）；社区版已有「插件固定 3 个」的免费限额先例（`CommunityPlugins = 3`）。

## 4. 数据模型（只增不删，符合迁移纪律）

| 变更 | 说明 |
|---|---|
| `Node.OwnerID`（string, index） | `""` = 管理员节点；非空 = 门户用户 ID。所有存量节点为 `""`，行为不变 |
| `Node.ReviewState`（string, size 16） | `""` = 不适用（管理员节点、存量节点，视为已通过）；`pending` 待审批；`approved` 已批准；`rejected` 已拒绝 |
| `Group.NodeLimit`（int） | 套餐字段：该套餐用户可拥有的节点上限；0 = 不额外限制（只受许可上限），>0 = 在许可上限内再收紧 |
| `license.Limits.UserNodes`（int） | 新增限额 kind `user_nodes`：**每个用户**可拥有的节点数上限，0 = 不限 |
| `license.CommunityUserNodes = 3` | 社区版（免费）默认值，与 CommunityPlugins 同范式 |

新设置键：`user_nodes_mode`（`off` / `approval` / `open`，默认 `approval`），进 editableSettings 并校验取值。

## 5. 社区版与专业版的区别与限制

区别只走许可的两条现成机制（限额 + 功能开关），不新造判定；功能深度不阉割——免费版限的是**量**和**自动化程度**，入站自助管理、改名、删除、重置接入两版一致，免费用户能完整用 3 台才有升级动力（与 licensing 的「引流」定位一致）。

| 维度 | 社区版（免费） | 专业版（许可证） | 机制 |
|---|---|---|---|
| 每用户自有节点上限 | **3 台** | 许可证签发值（0 = 不限） | 限额 `limits.userNodes`，社区默认 `CommunityUserNodes = 3`（与插件社区版 3 个同一范式） |
| 接入模式 | 只能审批制 | 可切开放制 | 功能开关 `FeatureUserNodesOpen`：无此功能时设置选 open 也不生效，生效模式强制 approval |
| 入站自助管理等功能深度 | 全部可用 | 全部可用 | 不区别 |

限制如何落地（全部收口到现有判定路径，不另起炉灶）：

- **数量**：门户建节点时数该用户已有节点（ReviewState != rejected，pending 也占额防刷建），达到有效上限返回 402 + 升级提示（复用 `limitOK` 的错误形态）。有效上限 = min(许可上限, 套餐 NodeLimit（>0 时才参与）)；无套餐只受许可上限；试用套餐想给 1 台，管理员把套餐 NodeLimit 设 1，不写死代码。
- **模式**：统一一个 `effectiveUserNodesMode()` 算生效模式 = 设置值 ∩ 许可（无 open 功能 → approval），门户与审批逻辑只读生效值，设置页标注「开放制需专业版」。
- **全局总量**：用户节点同时计入许可的全局 `LimitNodes`（与管理员节点合计），防总量失控。管理端建节点不受每用户配额限制（OwnerID 为空）。
- **到期/吊销降级**：`Evaluate` 已有降级路径，新限额与新功能自动跟随：降回社区版后上限变 3、开放制失效；存量节点继续运行（licensing 既定原则「绝不中断已有服务」），超限部分只是不能新增、不能编辑。
- **旧许可证兼容**：早于本功能的许可证没有 `userNodes` 字段，按插件的先例视为不限（祖父条款，不坑存量付费用户）；新签发许可证由授权服务（polaris-license）填值，签发端加该字段列入第 1 批的配套改动备注。

## 6. 模式与审批状态机

`user_nodes_mode` 三档：

| 模式 | 建节点 | 接入后状态 | 可用性 |
|---|---|---|---|
| `off` | 门户拒绝（功能关闭） | — | — |
| `approval`（默认） | 允许（配额内） | `pending` | 批准前不可用 |
| `open` | 允许（配额内） | `approved` | 立即可用 |

状态机（仅用户节点）：

- 建节点 → 按模式置 `pending` 或 `approved`；Agent 凭令牌 Enroll 不受审批影响（证书照常签发、节点可上线显示在线），**把门把在配置下发与绑定上**，不把门把在接入上——这样管理员审批时能看到这台机器的真实系统信息再决定。
- `pending` 的节点：不下发任何入站配置（渲染/同步路径对未批准的用户节点产出空配置）、不能被任何账号/分组绑定、在订阅里不可见。
- 管理员批准：`pending → approved`，触发一次配置同步。
- 管理员拒绝：`pending → rejected`，同时吊销证书（Revoked = true）断开 Agent；用户可删除后重新建。
- 管理员停用已批准节点：`approved → pending`（退回待审批即等效停用，复用同一把门），或直接删除。
- 模式从 approval 切 open 不追溯：存量 pending 仍需人工批准，避免一次切换放行全部积压。

## 7. 接口

### 门户（portal 会话鉴权，全部强制 OwnerID = 当前用户）

| 接口 | 说明 |
|---|---|
| `GET /portal/nodes` | 只列自己的节点（含审批状态、在线状态、系统信息摘要） |
| `POST /portal/nodes` | 建节点：校验模式 + 双层配额；只收 name/address/region/flag/labels 等安全字段，cores 用默认（Xray latest），不收 relay/trafficRate/probe 等管理字段；返回一次性安装命令 |
| `GET /portal/nodes/:id/install` | 令牌未消耗时重看安装命令；已接入后返回空（可走「重置接入」：吊销旧证书 + 发新令牌） |
| `PATCH /portal/nodes/:id` | 改自己的节点：仅 name/address/region/flag/labels |
| `DELETE /portal/nodes/:id` | 删自己的节点，走现有删节点级联（入站、绑定一并清） |

归属校验做成一个统一入口（`portalOwnedNode(c)`：按 ID 查 + OwnerID 比对，不属己一律 404，不泄露存在性），门户所有节点接口只能经它取节点，杜绝漏校验。

### 管理端（全局管理员，现有管理员鉴权）

全局管理员管全部：所有用户节点、所有注册用户（含在线用户）都在管理员视角内，用户只有自己那一域。

| 接口 | 说明 |
|---|---|
| `POST /nodes/:id/review` | body `{action: approve \| reject \| suspend}`，写审计日志 |
| 节点列表接口 | 响应加 `ownerId` / `ownerName` / `reviewState`，支持按归属与待审批筛选 |
| 用户管理 / 在线用户 | 每个用户带其自有节点数与待审批数，可直达该用户的节点与审批；管理员对用户的处置（禁用/删除）按 D6 连带其节点（禁用→吊销证书停用，删除→级联删节点） |

### 入站（第 3 批）

门户入站 CRUD 复用现有入站渲染/下发路径，但入口换成归属域版本：节点必须经 `portalOwnedNode` 取得、且 ReviewState = approved；入站能绑定的账号只能是主人自己的（见 §8）。

## 8. 隔离红线（本功能的安全底线，逐条要落测试）

1. **归属不可见**：门户任何接口按 ID 访问他人节点返回 404；列表永远带 OwnerID 过滤。
2. **不进公共池**：分组/套餐保存时校验 NodeIDs 不得包含用户节点（OwnerID 非空）；订阅渲染时用户节点只出现在主人自己的订阅里。
3. **绑定单向**：用户节点上的入站只能绑主人自己的订阅账号；管理员账号、其他用户账号一律拒。
4. **未批准即空气**：pending/rejected 的用户节点不下发配置、不可绑定、不出现在任何订阅与状态页。
5. **默认不上状态页**：用户节点 StatusHidden 默认 true，门户不可改。
6. **不参与中转**：用户节点不能作 RelayFor 的目标或来源，保存时校验拦截。
7. **Agent 通道不扩权**：Enroll 与 Agent 同步接口不因归属产生任何新权限；节点证书被吊销后同步通道立即失效（现有机制）。

## 9. 前端

- **门户「我的节点」**：节点卡片列表（状态、审批徽标、系统摘要）、添加节点表单、安装命令一键复制、待审批/被拒提示、删除与重置接入。配额用尽时显示上限与升级提示。
- **管理端节点列表**：加「归属」列（管理员 / 用户名）、审批状态徽标与筛选（全部 / 待审批）、行内批准/拒绝操作；设置页加「用户节点」卡：模式三档切换（off/approval/open）。
- **套餐编辑**：加 NodeLimit 输入（0 = 不额外限制）。

## 11. 风险与注意

- **越权面**：节点相关接口多，归属校验必须收口到统一入口（§7），且第 4 批要对全部节点 ID 入口做一遍审计式回归，不能靠逐页自觉。
- **滥用面**：开放注册 + 自助接入意味着任意注册用户能让一台机器连进面板。缓解：配额（免费 3 台）、默认审批制、pending 不下发配置、证书可随时吊销、注册侧已有邮箱验证与 IP 日限。残余风险：approved 节点跑的是用户自己的 VPS 与自己的账号，爆炸半径限于其本人。
- **许可降级**：许可证到期后用户节点超限部分按 §5 只冻新增/编辑，不停服。
- **用户注销/被删**：见决策 D6。
- **迁移纪律**：本功能全部是加列/加字段，无破坏性迁移，可正常走同步升级。
