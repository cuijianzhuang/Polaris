# 概览运维异常汇总

> 管理界面入口现已补齐，见[界面接入说明](operations-ui.md)；文中“仅后端/API”是首版交付范围。

在现有用户/流量/节点概览中补充真实线路诊断、网卡采样健康和支付交付异常。本轮只提供后端/API，不修改管理界面，不执行后台自动业务探测，也不改变线路路由、客户额度或告警策略。

## API 与权限

管理员会话读取 `GET /stats/overview` 时增加 `operational` 字段；也可通过 `GET /stats/operational` 独立读取同一结构。包含：

- `available`、`checkedAt`：本次汇总是否完整可用及查询时间。
- `relayBusiness`：受管中转线路总数，以及 `passed`、`failed`、`untested`、`stale`、`running`、`interrupted`、`unavailable`、`inactive` 数量；`freshForSeconds=900`。
- `sampling`：未撤销节点的 `healthy`、`stale`、`never`、`pending`、`inactive` 数量；`legacy` 独立统计缺少主机启动识别的旧格式采样，不表示采样一定失败。`staleAfterSeconds=120`。
- `delivery`：`paymentPending`、`paymentReview`、`refundPending`、`clusterPending` 数量。
- `issues`：资源 ID、节点 ID、名称、状态、固定原因代码和可用的检查时间；不返回原始 Agent 错误、支付错误、付款地址或用户身份。最多 200 条，`issueCount` 保留完整条数，超出时 `truncated=true`。按类别及资源 ID 稳定排序，未测试/停用的线路不加入异常明细。

`traffic:read` API 令牌继续能访问原有流量概览，但不返回新增 `operational` 字段，避免扩大权限至订单、退款和诊断；新增独立接口默认不开放给 API 令牌。节点管理员及匿名访问同样不能读取全局运维汇总。

读取使用一个只读数据库快照，PostgreSQL 使用可重复读。缺少任何必要表或查询失败时，主概览其他部分继续按原有行为返回，运维部分明确 `available=false`；不能把其中的零值解释为健康。独立接口返回 500。GET 不触发 Agent 命令，不创建探测、订单或状态记录。

## 真实诊断记录

已有 `POST /inbounds/:id/relays/:rid/diagnose/business` 在使用标准目标时记录最新尝试：TCP 为 `https://www.gstatic.com/generate_204`，UDP 为 `1.1.1.1:53`。显式传入同样目标也属于标准检查；其他自定义目标的检查仍返回原有结果，但不覆盖标准记录，避免自定义目标故障或成功改变全局汇总。

开始前先持久化 `running` 及唯一运行 ID，再向 Agent 发命令；无法保存状态时返回 500，不创建临时身份。结果仅按同一运行 ID 更新，旧请求晚返回不能覆盖更新的尝试。面板异常退出留下的 `running` 超过 30 秒后显示 `interrupted`，不假定成功。

记录仅包含结果状态、时间、固定检查代码和配置摘要，不包含临时身份、原始消息或测试 URL。只有服务端已验证的真实 TCP、UDP、凭据清理全部通过，才保留 `passed`。没有记录显示 `untested`；支持范围不足、缺少入口、节点离线/撤销/报错、心跳超过 90 秒或配置尚未应用显示 `unavailable`；停用线路或入站显示 `inactive`。这些状态不混计为已经证实的业务失败。

结果有效期为 15 分钟。入站、线路、实际分享地址/端口、SNI、相关节点地址/版本/能力及下发版本变化使旧结果显示 `stale`；配置重建也可能直接清除记录并回到 `untested`。未来异常时间不视为持续运行或长期有效。配置摘要包含保守的更新时间，因此只改部分元数据也可能要求重测。

每条线路仅保留最新标准尝试，不是完整诊断历史；原有开始/结束审计继续保留。记录跨普通面板重启保留，但不导入/导出备份；恢复备份时清除恢复前诊断记录。删除或重建线路同步清理记录，迟到结果不能重新创建它。

这项检查只证明专用身份当时访问标准目标的结果，不代表所有网站、每个客户路由或所有协议都可用。失败也可能来自标准目标阻断或不可用；汇总不自动摘除均衡成员，不改变生产健康状态。

## 采样与交付口径

采样沿用网卡账本已经成功提交的 `NetObservedAt`，不使用普通心跳冒充有效采样。在线节点没有样本为 `never`，距最后有效样本达到 2 分钟为 `stale`。待接入和离线节点单独统计，撤销节点不计入采样总数；采样缺失不表示流量为零，也不能证明已经漏计。模式字段与原因含义见服务器流量统计文档。

付款记录处于 `pending` 且超过 1 分钟才计入 `paymentPending`；`review` 立即计入人工对账；退款任务未完成且超过 1 分钟计入 `refundPending`。集群操作超过 1 分钟仍有待受理交付时按交付记录计数。这些是付款/退款/交付任务数量，不是待支付购物车数量，也不是互不重叠的订单总数。

另外汇总已有 `OperationalStatus` 中尚未恢复的失败，例如流量落盘、结算或扫描异常。只输出状态键及检查时间，不携带原始错误详情；删除或撤销节点不再展示其历史 Agent 队列故障。

## 验证

覆盖标准诊断记录、自定义目标隔离、旧结果晚返回、分享地址变化、结果过期、运行中断、停用/离线分类、线路删除、备份恢复、采样分类和交付阈值。验证异常明细截断不影响总数、数据库失败不伪装健康，以及流量令牌和节点管理员的权限边界。
