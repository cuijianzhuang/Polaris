# 探针大盘优化

界面层次参考 [CF-Server-Monitor](https://github.com/huilang-me/CF-Server-Monitor)：总览、筛选、紧凑资源卡片和网络质量小图。采用 Polaris 自有组件重新实现，不引入 Cloudflare 服务或额外 Agent。条形、环形和表格视图均保留现有身份验证与公开范围。

- 后台使用共享 React 展示组件；公开页为独立、内嵌的 HTML/JS，不需要加载后台应用。两者共用 `internal/panel/probe_assets/monitor.css`。Vite 按页面加载该样式，Go 通过 embed 打包公开页资源。
- 节点心跳超过 90 秒、缺少心跳或出现明显未来时间时，资源数据不纳入实时汇总。CPU=0、内存=0 和已知磁盘容量下的磁盘=0 都是有效值。前端以服务端快照时间加浏览器单调时钟推进，避免浏览器本机时间偏差影响判断。
- `probeTargets` 仅包含每节点的目标 ID、名称和运营商，不含目标地址。停用探测的节点使用空列表，不继承其他节点的目标。公开查询排除已隐藏和已撤销节点，流量与成本继续遵守原有公开开关。
- 小图的 `sparkLoss` 与 `spark` 共享 `sparkStart`，null 代表没有样本，100% 失败与没有样本分别显示；没有测量不当作 0 ms。最新延迟和一小时失败率分别使用各自的实际时间窗，过期测量不展示为实时成功。
- 历史端点额外返回 sent/lost，均值按成功样本数量、失败率按全部样本数量加权。图表补充时间轴中的缺口，但不填造测量值；时间轴上限 2017 个五分钟点，覆盖最多 7 天。
- 公开页只通过既有 `/status/data` 获取快照，详情展示其中的两小时网络数据，不新增匿名历史或管理接口。请求超时八秒、禁止重叠；隐藏标签页暂停轮询。失败保留最后快照并告警，资源逐步过期；状态页变为不可访问时清空旧快照。

采集仍沿用现有 Agent 心跳和每 30 秒的 TCP 探测，保存五分钟聚合，不改变内核、业务代理配置或用户流量计量。
