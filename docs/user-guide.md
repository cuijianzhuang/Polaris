## 1. 基本概念

| 名称 | 含义 | 示例 |
| --- | --- | --- |
| 主控 / 面板 | 管理节点、用户、配置与订阅的服务 | 管理员通过浏览器登录的后台 |
| 节点 | 实际承载代理连接的服务器 | 一台东京 VPS |
| Agent | 节点上的管理程序，负责同步配置和管理内核 | 主动连接主控的 `polaris-agent` |
| 内核 | 处理代理协议与流量的程序 | Xray、sing-box、mihomo、Hysteria2 |
| 入站 | 节点上一个协议、端口和传输方式的组合 | 某节点的 VLESS + TCP + REALITY 入站 |
| 入口 | 客户端连接某个入站的方式 | 直连地址、CDN 地址、中转地址 |
| 用户 | 拥有独立凭据、流量配额和有效期的账号 | 分配给某位订阅用户的账号 |
| 分组 | 批量分配入站、整台节点、等级和套餐速率 | 基础组、高级组 |
| 订阅 | 客户端拉取节点配置的专属链接 | `https://panel.example.com/sub/用户令牌` |

**节点在线不等于已经能连接代理。** 完整链路是：节点接入 → 内核就绪 → 入站下发成功 → 用户获得授权 → 客户端导入兼容配置。

后台地址、订阅地址和用户中心用途不同。假设主控域名为 `panel.example.com`、后台路径为 `/my-admin`：

| 用途 | 地址示例 |
| --- | --- |
| 管理后台 | `https://panel.example.com/my-admin/` |
| 用户订阅 / 订阅信息页 | `https://panel.example.com/sub/用户令牌` |
| 普通用户中心 | `https://panel.example.com/u` |

订阅和用户中心路径不需要加后台前缀；配置独立订阅域名后，应使用面板实际生成的链接。

## 2. 安装与部署

### 2.1 准备工作

一键安装适用于支持 systemd 的 Linux，架构为 amd64 或 arm64，需要 root 权限。主控与节点可以部署在同一台服务器，也可以分开部署。

安装前确认：

- 主控和节点能够访问所需的 GitHub 发布文件；节点能够连接主控。
- 主控域名已解析到正确的公网 IP；如果配置了 AAAA 记录，也要保证 IPv6 可达。
- 准备使用的端口未被其他服务占用，云安全组和系统防火墙规则一致。
- 主控默认使用 SQLite，基础部署无需先准备 PostgreSQL。

| 位置 | 端口 / 协议 | 用途 |
| --- | --- | --- |
| 主控 | `80/tcp`、`443/tcp` | 使用 Caddy 时的 HTTP 验证、跳转和 HTTPS 服务 |
| 主控 | `9443/tcp`，默认值 | Agent 的 mTLS 接入；Agent 应直接连接 |
| 主控 | `8080/tcp`，默认值 | 面板 HTTP；有反向代理时通常只供本机访问 |
| 节点 | 入站实际使用的 TCP / UDP 端口 | 客户端连接代理服务；Hysteria2、TUIC 等需关注 UDP |
| 节点 | `80/tcp`，按需 | 在节点上使用 ACME HTTP 验证申请证书 |

节点主动连接主控，接入本身不要求节点拥有公开的管理端口。NAT 后的节点也能接入，但要向公网客户端提供代理服务，仍需要可达地址或端口映射。

### 2.2 一键安装主控

在主控服务器上以 root 执行，替换示例域名：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/cuijianzhuang/Polaris/main/scripts/install-panel.sh) install --community --domain panel.example.com
```

专业版将 `--community` 改为 `--pro`。没有域名时可去掉 `--domain panel.example.com`，使用 IP + HTTP 临时测试；正式使用可再运行：

```bash
polaris set-domain panel.example.com
```

在终端里运行时，脚本会先让你选择版本和数据库：

| 数据库 | 适合 |
|---|---|
| SQLite（默认） | 单个主控、几千用户以内。免安装，数据就是 `/var/lib/polaris/polaris.db` 一个文件 |
| PostgreSQL（本机） | 用户、节点很多或流量记录量大。脚本自动安装 PostgreSQL 并建库，主控通过本机 socket 免密码连接 |
| PostgreSQL（已有） | 云数据库或另一台服务器，准备运行多个主控实例时选它。输入 `postgres://用户:密码@主机:5432/库名` |

选择 PostgreSQL 时还会询问是否使用 Redis（可选，只在运行多个主控实例时需要）。无人值守安装用参数指定：`--db sqlite|local|postgres://…`、`--redis local|redis://…`，不指定时使用 SQLite。之后随时可以用 `polaris migrate` 切换，见[从 SQLite 切换到 PostgreSQL](#db-migrate)。

脚本会生成密钥和后台路径，配置 systemd 服务，并在使用域名时安装 Caddy。安装完成后：

1. 保存输出的后台地址、管理员账号和初始密码。
2. 打开**完整后台地址**登录；仅访问域名根路径可能得到 404。
3. 在「系统 → 设置」修改密码并配置两步验证。
4. 备份 `/etc/polaris/polaris.env`，尤其是 `POLARIS_SECRET_KEY`。

查看信息和诊断：

```bash
polaris info
polaris status
polaris doctor
```

常用安装参数：`--version TAG` 指定发布版本，`--port N` 指定面板端口，`--agent-port N` 指定 Agent 接入端口，`--admin-path PATH` 指定后台路径，`--no-caddy` 使用自备反向代理，`--mirror URL` 指定 GitHub 下载前缀。完整参数见 `polaris help`。

`9443` 不应经过普通 HTTP 反代或 CDN。若主控网站使用 CDN，应另外为 Agent 提供能够直达主控的地址，并检查 `POLARIS_AGENT_HOSTS` 和面板生成的节点安装配置。

### 2.3 Docker 部署

需要 Docker Engine 和 Docker Compose。先获取仓库：

```bash
git clone https://github.com/cuijianzhuang/Polaris.git
cd Polaris
cp deploy/polaris.env.example deploy/polaris.env
openssl rand -hex 32
```

将生成的随机值填写到 `deploy/polaris.env` 的 `POLARIS_SECRET_KEY`，同时修改：

- `POLARIS_ADMIN_PATH`：自定义后台路径，例如 `/my-admin`。
- `POLARIS_PUBLIC_URL`：完整的外部地址，例如 `https://panel.example.com`。
- `POLARIS_AGENT_HOSTS`：Agent 能直接连接的主控域名或 IP。
- 按需设置 `POLARIS_INITIAL_ADMIN_USERNAME` 和 `POLARIS_INITIAL_ADMIN_PASSWORD`；它们只用于首次创建管理员。

妥善保存该文件和密钥。仓库的 Compose 文件默认**从源码构建社区版**：

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 polaris
```

未指定初始管理员密码时，从首次启动日志中读取生成的登录信息；不要将这段日志公开。

如果使用发布镜像，编辑 `docker-compose.yml`：删除 `build: .`，把 `image` 改为 `ghcr.io/cuijianzhuang/polaris:latest` 或 `ghcr.io/cuijianzhuang/polaris:latest-pro`，然后运行 `docker compose pull` 和 `docker compose up -d`。需要固定版本时使用对应发布标签。

默认 Compose 将面板映射到主机的 `127.0.0.1:8080`，将 Agent 端口映射到 `9443`，数据保存在 `polaris-data` 命名卷。Compose 的 `environment` 会覆盖环境文件中的监听地址和数据目录，这是容器部署所需的设置。

在主机上配置 Caddy 或 Nginx 终止 HTTPS。[Caddy 示例](../deploy/Caddyfile)：

```caddyfile
panel.example.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8080
}
```

如果反向代理也运行在容器中，使用双方共享网络上的服务名和端口，不能把代理容器自己的 `127.0.0.1` 当作 Polaris。完成后用完整后台地址验证登录。

### 2.4 首次登录检查

确认后台可用、浏览器证书正常，且「许可证」显示的构建版本符合预期。检查「系统 → 设置」中的访问地址；后续生成的订阅和节点安装命令应使用实际可达的主控地址。

记下四项信息：后台地址、管理员账号、环境文件位置、备份位置。后续维护需要这些信息。

## 3. 首次配置：从空面板到可用订阅

先用一个节点、一个入站和一个测试用户完成连接，再增加协议和批量模板，便于定位问题。

### 3.1 添加一个节点

1. 打开「节点 → 节点列表」，点击「添加节点」。
2. 填写名称，例如 `tokyo-1`；设置公网地址或节点域名。节点域名优先用于订阅，两者都留空时使用 Agent 检测到的公网 IP。
3. 选择需要安装的内核和默认内核。根据客户端选择；例如 REALITY 可选 Xray 或 sing-box，具体版本限制见[兼容性](#compatibility)。
4. 点击「创建并生成安装命令」。
5. 在节点服务器以 root 执行面板生成的**完整命令**。其中包含一次性注册令牌，不要转发给其他人。
6. 等待安装窗口显示节点已上线，再检查内核下载 / 安装状态。

注册令牌有效期为 24 小时且只能使用一次。令牌失效时，应从面板重新获取安装命令，不要反复使用旧令牌。

在主控本机添加节点也可运行：

```bash
polaris node
```

**完成标志**：节点显示在线，能够上报 Agent 版本和状态；内核安装完成后再进行下一步。

### 3.2 创建一个入站

在「入站与转发 → 入站」新增入站，选择刚才的节点。以下以 VLESS + TCP + REALITY 为例，客户端需要支持该组合：

| 字段 | 填写方式 |
| --- | --- |
| 节点、内核 | 选择已上线节点和兼容的内核版本 |
| 标识 / 名称 | 使用便于识别的标识，例如 `tokyo-reality` |
| 监听地址 | 需要外部直连时使用可对外监听的地址；`127.0.0.1` 只适用于本机回源等场景 |
| 端口 | 选择未被占用的端口，并放行对应 TCP 流量 |
| 协议、传输、安全 | VLESS、TCP、REALITY；按界面能力提示设置 Vision |
| REALITY 目标站点 | 填写节点可达、满足能力要求的目标地址和端口 |
| SNI / Server Names | 必须与目标站点证书匹配，可使用界面扫描功能辅助选择 |

**允许 UDP 443**：选择 VLESS + TCP + TLS/REALITY 和 `xtls-rprx-vision` 后，可在「Xray 订阅客户端」中打开「允许 UDP 443」。默认关闭；开启后，VLESS 分享链接（包括链接订阅和用户中心复制链接）使用 `xtls-rprx-vision-udp443`，让支持此选项的 Xray 客户端代理 UDP 443，例如 QUIC / HTTP/3。保存后需要在客户端更新订阅。服务端流控仍为 `xtls-rprx-vision`；sing-box、mihomo 等原生订阅不追加该后缀，UDP 行为由对应客户端配置决定。此开关不修改节点监听端口或防火墙规则。入站模板中也可以配置此选项。

REALITY 私钥、公钥和 shortId 由面板生成。不要把目标站点的 SNI、主控域名和节点地址混为同一个字段。REALITY 目标需要支持 TLS 1.3 和 h2；新版本 Xray 还有额外客户端要求。

**挑选目标站点**：REALITY 字段旁的「扫描」按钮会打开目标扫描器。它检查 TLS 1.3、HTTP/2 和 SNI 对应的证书，并展示 X25519MLKEM768 等兼容性信息。可以输入域名、IP 或 CIDR；每段最多展开 256 个地址，一次总量最多 512 个。没有 SNI 的 IP 会先读取证书，再连接同一 IP 带 SNI 重新握手。点击「使用」会保留拨号目标并填入实际验证的 SNI。节点在线且 Agent 支持新版命令时由节点发起，延迟包含最终 TCP 与 TLS 握手；节点离线或 Agent 较旧时明确标注面板验证，恢复或升级后应从节点复测。

**从 Shodan 发现候选**：手头没有合适的候选时，可以点扫描器里的「从 Shodan 发现」：

1. 第一次使用时填入 Shodan API Key。Key 加密保存在面板里，页面和接口都不会显示原文；保存和更换需要二次验证。界面会显示套餐和剩余查询额度。
2. 选国家 / 地区（建议选离节点近的）和页数，也可填写 ASN（例如 `AS64500`）或网段（例如 `203.0.113.0/24`），点「发现并验证」。默认查询是 `port:443 ssl.version:tlsv1.3 ssl.alpn:h2`；自定义查询中已有相应过滤条件时优先使用查询内条件。
3. 面板保留 Shodan 返回的 IP/端口，将证书域名作为独立 SNI 实测，结果展示实际连接地址及索引中的 ASN、组织和国家。相同证书的不同 IP 分别验证，点击「使用」会同时填入目标地址和通过验证的 SNI。
4. 部分页查询失败时保留已有候选并提示原因，界面显示实际读取页数，完成后刷新查询额度。基础检测只覆盖 TLS、h2 和证书，HTTP 首页、CDN 和长期稳定性需另外核对；同 ASN 不代表同机房。

Shodan 发现按网段筛选时只查询索引，随后连接返回的候选进行复核。每页最多 100 个候选，Shodan 对带过滤条件的搜索每页扣 1 个查询额度，一次最多 3 页。免费账号通常不支持过滤条件，需要会员或 API 套餐。

本轮需同步升级面板和 Agent，以启用节点侧新版验证；旧 Agent 仍可连接面板，但扫描会标注为面板验证。完整方案及后续 HTTP/CDN、CSV 导入和复测规划见 [REALITY 扫描器设计](design/reality-scanner.md)。

保存后查看节点的应用结果。如果提示端口冲突、协议不支持或内核校验失败，先解决错误，再交付订阅。

也可以在「入站与转发 → 入站模板」中按“选模板 → 选节点 → 预览并生成”操作。预览中要检查端口分配、内核改派和跳过原因。

**完成标志**：入站启用，内核正常运行，节点没有配置应用错误，外部连接路径和端口已放行。

### 3.3 创建用户并授权

1. 打开「用户」，创建一个测试用户。
2. 设置用户名、流量配额和有效期。
3. 在「节点授权」中选择刚才的节点，或只选择刚创建的入站。
4. 保存，复制用户的订阅链接。
5. 打开用户详情中的「订阅诊断」，点击「检查订阅」，确认目标客户端格式包含预期节点。

创建入站并不会自动授权给所有用户。分组、等级和单独授权的关系见[用户与套餐](#users)。

### 3.4 导入并验证

在浏览器打开订阅链接，检查用户状态、用量和可用节点。安装兼容客户端，导入订阅，选择节点连接并访问一个测试网站。

随后回到面板，观察用户近期在线状态和流量变化。流量由 Agent 上报，可能不会立即刷新。出现“订阅能下载但连接失败”时，按[排查表](#troubleshooting)检查实际代理端口、内核状态和客户端兼容性。

## 4. 客户端使用

本节适用于已拿到订阅链接的普通用户，无需登录管理后台。

### 4.1 导入订阅

1. 从管理员处获取自己的订阅链接。
2. 在浏览器中打开，确认状态正常、尚未到期且有可用节点。
3. 先安装要使用的客户端，再点击信息页上的对应导入按钮。
4. 如果浏览器没有唤起客户端，在客户端中选择“添加订阅 / 从 URL 导入”，粘贴链接。
5. 更新订阅，选择节点并启用连接。

客户端名称和按钮随版本不同会有差异。信息页提供二维码和单节点链接；长期使用优先导入订阅，便于获取管理员更新后的地址与端口。

### 4.2 选择订阅格式

Polaris 会根据客户端请求自动选择格式，也可以使用 `format` 参数明确指定：

| 客户端 / 配置类型 | 参数 |
| --- | --- |
| 通用代理链接 | `?format=links` |
| Clash / mihomo | `?format=clash` |
| sing-box | `?format=singbox` |
| Surge | `?format=surge` |
| Loon | `?format=loon` |
| Quantumult X | `?format=quanx` |

例如：`https://panel.example.com/sub/你的令牌?format=clash`。已有查询参数时用 `&format=clash` 追加。请使用自己的完整订阅地址，表中的地址只是格式示例。

某些协议不能输出给所有客户端。一个格式中的节点数少于另一个格式，不一定是授权丢失；管理员可通过「订阅诊断」查看原因。

### 4.3 更新、设备更换与链接泄露

- 管理员改端口、节点地址或协议后，先在客户端更新订阅，再重新连接。
- 设备达到限制时联系管理员检查 HWID 记录；IP 数限制与设备数限制是两个不同规则。
- 订阅链接包含访问令牌，不要公开截图、上传到公开仓库或发送给无关人员。
- 如果链接泄露，请在用户中心重置或联系管理员处理。**重置会同时更换订阅令牌、UUID 和密码，旧链接及已导入的旧节点配置失效，需要重新导入。**

## 5. 用户中心与 Telegram 绑定

普通用户中心位于主控或订阅站点的 `/u`，通过 Telegram 或邮箱验证码登录，不使用管理员密码。前提是管理员已在「订阅 → 订阅设置」开启「用户中心」、启用 Telegram 机器人，且 Telegram 账号已绑定对应用户。

绑定与登录步骤：

1. 浏览器打开自己的订阅链接，点击「Telegram 机器人绑定」。也可以在机器人私聊中发送 `/bind 你的订阅链接`。
2. 按机器人提示完成绑定。
3. 打开 `/u`，点击「使用 Telegram 登录」。
4. 网页显示数字后，在机器人消息中点击相同数字，再返回网页。

用户中心可查看用量、到期时间、套餐速率和订阅，并自助重置订阅链接；商店自动创建的账号还可以修改用户名。解绑 Telegram 或重置订阅后，原有用户中心会话失效，需要重新登录。

机器人常用用户命令：

| 命令 | 用途 |
| --- | --- |
| `/me` | 查看流量与到期时间 |
| `/sub` | 获取订阅链接与二维码 |
| `/nodes` | 查看自己可用的节点 |
| `/unbind` | 解除绑定 |
| `/help` | 查看可用命令 |

普通用户的 Telegram 绑定不会赋予管理后台权限。管理员尚未启用机器人时，仍可直接使用订阅链接，但无法通过 Telegram 登录用户中心。

### 邮箱登录与注册

配置了邮件（「设置 → 邮件」，见[邮件通知](#mail)）后，用户中心登录页会多出「邮箱登录」：

1. 输入邮箱，点「发送验证码」。只有已绑定这个邮箱的账号（或开启了注册时的新邮箱）才会真的收到邮件，页面的提示对谁都一样，不会暴露某个邮箱有没有账号。
2. 输入邮件里的 6 位验证码登录。验证码 10 分钟内有效，只能用一次，输错 5 次作废；同一邮箱 60 秒内只能发一次、每天最多 10 次，同一 IP 也有频率限制。
3. 用邮箱登录的会话在更换邮箱或重置订阅链接后失效。

已登录的用户（包括用 Telegram 登录的）可以在用户中心点「绑定邮箱 / 更换邮箱」，同样用验证码确认；一个邮箱只能绑定一个账号。管理员也可以直接在用户编辑页填写邮箱。

**邮箱注册**：在「订阅 → 订阅设置」开启用户中心后，打开「允许邮箱注册」：

- 没有账号的邮箱验证后自动创建账号（用户名取邮箱 @ 前的部分加随机后缀，可在用户中心自行修改），并直接登录。
- 「试用套餐」：选了就给新账号开通这个套餐；不选则账号没有可用服务（已到期状态），需要先在网页商店购买。
- 「允许的邮箱域名」限制可注册的邮箱后缀；「每个 IP 每天最多注册」默认 3 个。
- 注册会写审计日志，通知 Telegram 管理员（及管理员邮箱），并发出 `user.registered` 事件。
- 开放注册建议同时限制域名、送较少的试用流量，并关注注册通知。


### 工单

在「用户 → 工单 → 工单设置」打开「开启工单」后：

- **用户提交**：用户中心出现「🎫 工单」入口（有新回复时显示条数），可以新建工单、查看来回消息、继续回复或关闭；也可以在 Telegram 机器人里发 `/ticket 问题描述` 新建，`/reply 工单号 内容` 回复。用户必须先登录用户中心或绑定机器人。
- **管理员处理**：「工单」页按「待回复 / 已回复 / 已关闭」筛选，可按标题、用户名或 `#编号` 搜索。打开工单即可回复，或「回复并关闭」；也可以关闭、重新打开、删除。用户新建或回复工单时，Telegram 管理员（及管理员邮箱）会收到通知。
- **通知用户**：管理员回复后，用户在 Telegram（已绑定时）和邮件（填了邮箱且配置了邮件时）里收到回复内容。
- **规则**：每人同时未关闭的工单默认最多 3 个；已回复的工单用户 7 天没再回复会自动关闭（都可在设置里修改）。用户回复已关闭的工单会重新打开它。工单事件也会发到 Webhook：`ticket.created`、`ticket.replied`、`ticket.closed`。

## 6. 节点与内核管理

「节点 → 节点列表」查看连接状态、资源使用、流量、授权用户和配置结果；「节点 → 内核」集中管理内核。

### 地址、默认内核与版本

- **公网地址 / 节点域名**决定客户端连接地址，不是后台登录地址。域名必须解析到实际入口。
- **默认内核**用于新入站的默认选择，不会把已有入站自动迁移到另一个内核。
- 同一节点可以运行多个内核；创建入站时选择对应内核，避免争用相同监听地址、端口和协议。
- 历史内核版本保存在节点上，可切换版本或回退。新内核启动失败时 Agent 会尝试恢复旧版本及配置，并上报原因。
- 内核、Agent 和主控是三个不同组件，升级其中一个不代表另外两个已经升级。

主控升级后，可按节点页提示升级 Agent。Agent 升级会重启内核，现有连接可能短暂中断，建议先选一个节点验证。

### 状态与配置下发

配置保存后，查看节点是否已应用新配置，而不只看“保存成功”。节点离线时无法立即应用变更；上线后会重新同步。排查应用失败先看内核日志、端口冲突和协议支持情况，必要时回滚到已成功应用的配置。

Agent 的数据默认位于 `/var/lib/polaris-agent`，内核位于 `cores/{type}/{version}/`。日常配置应在面板中修改，Agent 管理的生成配置可能在下一次同步时被覆盖。

### 流量与授权

用户详情新增「流量来源」：按节点和结算小时查看原始流量、实际倍率、倍率后流量及账户扣量，支持 24 小时 / 7 天 / 30 天筛选。历史缺失字段显示「未记录」，离线补报按结算时间显示。遇到“未使用却有流量”，参照[流量来源排查说明](design/user-traffic-attribution.md)保留数据并定位来源。

节点流量倍率用于用户结算，例如倍率为 2 时，同样的实际用量会按两倍结算。服务器月流量用于观察服务商配额，应根据服务商采用的收发统计方式设置，不能直接等同于某个用户的套餐流量。

节点详情可查看哪些用户有权限使用本节点，并进行整台绑定或解绑。解绑整台节点后，通过分组、等级或单独入站获得的权限可能仍然有效。

### 服务商 API（搬瓦工）

搬瓦工（BandwagonHost）的 VPS 可以在节点详情的「服务商 API」卡片里接入 KiwiVM API：

1. 登录 KiwiVM 控制面板，在左侧「API」页面生成 API Key，同一页能看到 VEID；
2. 在节点详情点「接入」，填入 VEID 和 API Key，点「检查并保存」。面板会先调用一次接口，确认能读到数据才保存。

接入后卡片显示：服务商统计的本月流量和额度（已乘计费倍率）、下次重置时间、VPS 状态（运行中 / 已暂停、CPU 是否受限）、套餐、机房、系统、内存、硬盘和 IP。主控每 15 分钟读取一次，点「刷新」会立即读取，同时读取实时负载、可用内存和硬盘用量。

「同步节点流量」默认开启。开启后，节点的「服务器月流量」「每月重置日」和「本周期已用」都按服务商的数据校准，超过提醒阈值或额度时照常发提醒。服务商的统计是计费依据，比面板从网卡上统计的数值更准，也包含节点接入面板之前的用量。关闭后只查看，不修改节点设置。

- 面板只调用只读接口（`getServiceInfo`、`getLiveServiceInfo`），不会开关机、重装或修改 VPS；
- API Key 加密保存，接口和页面都不会返回明文；修改设置时留空表示沿用原来的 Key；
- 移除设置不会改动节点已有的流量额度和重置日；
- 读取失败（Key 被重置、接口限流等）时卡片会显示原因，下一轮会自动重试。

### 探针与三网延迟

「节点 → 探针」把所有节点排成卡片：在线状态、CPU / 内存、实时网速、运行时长和负载、本月服务器流量，以及到各探测目标的延迟。每个目标一行，右边是最近一次的延迟和近 1 小时丢包率，中间是近 2 小时走势；离线或超时的目标标红。点卡片可查看 6 小时到 7 天的延迟和丢包曲线，以及平均、最低、最高延迟。

**怎么测**：每个在线节点每 30 秒对每个启用的目标发起一次 TCP 连接，记录耗时（新版 Agent 先解析域名，只计连接时间）；失败或 15 秒内没连上算丢包。数据按 5 分钟汇总，保留 7 天。用的是节点已有的探测命令，旧版 Agent 也能参与。

**探测目标**：首次打开时自动添加上海电信、联通、移动三个目标。在「探测目标」里可以增删改，最多 20 个。添加时默认从 [Zstatic 节点目录](https://www.zstaticcdn.com/) 选择：先选省级或市级，再依次下拉选择省份、城市（市级）和运营商，自动填写名称及地址。运营商只列出该地区实际存在的节点；切换上级地区后会重新选择下级地区，避免沿用上一地区的地址。省级可选 IPv4、IPv6、双栈；市级按来源目录使用 IPv4，并保留各节点公布的端口。

目录为随面板发布的内置快照，选择器显示来源更新时间，包含 31 个省级地区、93 个省级运营商地址（含 IPv4、IPv6、双栈共 279 个选项）和 223 个市级地址。只会保存并探测选中的目标，仍受 20 个目标上限约束。需要指定其他地址时，将「目标来源」切换为「自定义」，填写名称、运营商和任意 `主机:端口`；已有自定义目标编辑时保留原值，已知目录地址编辑时会恢复对应下拉选择。保存前可以选一个节点「试测」一次。修改目标地址会清空它的历史数据。这些第三方地址可能调整或失效，长期显示超时时请换一个。

**公开状态页**：在「探针 → 设置」开启后，任何人打开 `https://订阅域名/status` 都能看到节点在线状态、资源占用和三网延迟，页面每 15 秒刷新。公开页不显示 IP、域名和 Agent 版本；默认也不显示服务器流量，可在设置里打开。不想公开的节点在节点详情里关掉「在公开状态页显示」。全局公开开关默认关闭；节点的显示开关默认打开，升级前已有节点也按此规则显示，无需手动切换。可以设置页面标题和顶部公告。关闭时该地址和其他未知路径一样由伪装站点响应。

### 节点地图

「节点 → 节点地图」把所有节点画在世界地图上：绿色为在线，红色为离线或配置应用失败，黄色为待接入或同步中。点击标记查看地址、CPU / 内存和跳转链接；支持滚轮、拖动、双指缩放。地图是内置矢量图，不依赖外部地图服务，离线或内网环境也能使用。

节点位置按以下顺序确定：

1. 节点设置里填写的「位置（纬度 / 经度）」，两项需同时填写，留空则清除；
2. 「地区」或「名称」中包含的常见城市名（中英文均可，如“香港”“Tokyo”“洛杉矶”“fra”）；
3. 「国家代码」（如 `JP`）对应国家的中心位置。

三者都无法确定的节点会列在地图下方的“未定位的节点”中。同一城市的多个节点会在标记处围成一圈，放大后散开。

## 7. 入站、模板与证书

### 入站与入口

入站定义实际代理服务，入口定义订阅里使用哪个地址连接它。同一入站可配置直连、CDN 或中转入口，每个入口可以生成一个订阅节点。未配置入口时默认按直连生成。

编辑入站时重点核对：节点与内核、协议、传输、安全方式、监听端口、证书 / SNI，以及授权关系。界面置灰的组合表示当前内核或版本不支持。

批量修改端口后，检查结果中是否有因冲突跳过的入站，更新云安全组，并通知用户更新订阅。入站端口限速是所有用户共享的端口上限，与专业版的客户独立限速不同。

### 使用入站模板

内置模板包括 REALITY 直连、Hy2 + TUIC、CDN WS 备用和全协议等。操作顺序：

1. 选择模板。
2. 选择目标节点和必要的 CDN 配置档。
3. 预览内核分配、端口冲突处理和跳过原因。
4. 对 REALITY 入站，在预览页逐节点点击「从此节点检测目标」。默认要求节点检测通过；需要自定义目标时，回到选节点步骤展开「按节点设置 REALITY 目标」。检测未通过可调整目标，或跳过该节点重新预览。
5. 确认生成后，在页面查看「等待节点应用」「节点已应用」「节点离线」或「应用失败」状态；可只重试失败节点。
6. 为用户或分组授权生成的入站。

预览固定本次端口、随机路径和生成的代理密钥，10 分钟内有效。修改选项、模板内容或相关节点配置后，需重新预览；重复确认同一计划不会重复创建入站。REALITY 检测必须由目标节点完成，节点离线或 Agent 不支持时应先恢复节点或升级 Agent；基础检测覆盖 TLS 1.3、HTTP/2 和 SNI 证书校验，不代表完整的 REALITY 连接或长期稳定性验证。

模板卡片的「应用记录」展示最近 20 次生成记录，保留 30 天；节点状态每 4 秒刷新。离线节点上线后会自动接收配置。「只重试失败节点」保留已生成的入站；写入失败且原预览已过期时，请重新选择失败节点预览。

模板可以绑定节点标签，用于新节点自动套用。模板修改后，可在「同步」中查看逐字段的修改前后值并勾选同步项。手动修改默认只保护对应字段；若要覆盖，打开「允许选择手动修改过的字段」，再勾选需要更新的内容。历史版本留下的整组覆盖标记仍会保护整组配置，密钥值不会出现在差异中。

编辑模板时可为条目命名、复制、上移和下移；复制会生成独立条目标识及标签后缀。列表支持按名称、说明、协议搜索，以及 REALITY、CDN、Hy2/TUIC 等场景筛选。内置模板请另存为自定义模板后修改。保存时会校验端口区间、变量、协议组合、证书策略、重复标识及授权引用，并指出具体错误条目。

### TLS 与证书

在「域名与证书 → 证书」管理证书，在「系统 → 设置」配置 ACME 邮箱等选项。常用方式：

| 方式 | 前提与用途 |
| --- | --- |
| ACME HTTP 验证 | 域名解析到节点，节点 80 端口可达；验证时 Agent 临时响应挑战 |
| ACME DNS 验证 | 配置所需 DNS 服务商凭据，可申请泛域名证书，无需开放节点 80 端口 |
| 上传证书 | 已持有匹配域名的证书和私钥，按界面导入 |

TLS 入站应选择正确证书，并让 SNI 与证书域名匹配。不选证书时，面板可能生成自签证书并让客户端跳过验证；正式使用应配置可信证书，而不是依赖跳过验证解决错误。

节点入站证书与主控网站的 HTTPS 证书分别管理。为主控安装 Caddy，不代表所有节点的 TLS 入站已经获得证书。

ACME 证书在剩余有效期不足约三分之一时自动续期，并下发到使用它的节点。应持续保留验证条件，并查看续期告警。IP 证书采用短有效期方案，更需要保持续期可用。

### 同端口回落

Xray 的 VLESS / Trojan + TCP + TLS / REALITY 入站可按支持情况配置回落。子入站应在同一节点、监听本机地址并关闭 TLS，由父入站按路径或 ALPN 转交连接。订阅会使用父入站端口与 TLS 参数。此项适合已熟悉协议的管理员，首次配置可先使用独立端口。

## 8. 用户、授权与套餐

### 8.1 创建和调整用户

在「用户」中设置用户名、备注、配额、有效期和授权。用户名用于管理，每位用户的代理 UUID / 密码由系统维护，无需将后台密码交给用户。

| 设置 | 行为 |
| --- | --- |
| 总流量配额 | 控制套餐流量；留空或 0 表示不限，按界面提示填写 |
| 固定到期日 | 到指定日期结束；留空为永不到期 |
| 首次使用后 N 天 | 在产生第一笔流量后开始计时，不是创建账号或首次打开订阅时 |
| 流量重置 | 支持不重置、每天、每周固定日、每月固定日和按周期滚动 |
| 自动续订 | 到期后顺延指定天数并清零流量，可设置最多续订次数；不代表已经完成支付 |
| IP 数限制 | 按内核可提供的在线 IP 信息执行，相关临时封禁与豁免见设置 |
| HWID 设备数 | 根据兼容客户端拉取订阅时上报的设备 ID 计数，不等同于同时在线连接数 |

续期和重置流量是不同操作。用户连接中断时先确认是到期、超额、禁用、IP 封禁还是设备限制，再调整对应项目。

### 8.2 授权方式

有效授权取以下来源的**并集**：

| 来源 | 范围 |
| --- | --- |
| 用户直接绑定节点 | 该节点全部入站，包括以后新增的入站 |
| 用户直接授权入站 | 指定入站 |
| 分组授权入站 | 组内用户可使用指定入站 |
| 分组绑定节点 | 组内用户可使用这些节点全部入站 |
| 分组等级 | 开放节点等级在 `1` 到分组等级之间的节点 |

节点等级为 `0` 时不通过等级开放，需要节点或入站的显式授权。显式授权可以独立于等级生效。

例如，高级组等级为 2，可使用等级为 1 和 2 的节点；等级为 0 的节点仍需单独授权。如果用户同时直接绑定了某节点，降低分组等级也不会移除这份直接授权。

撤销访问时要检查所有授权来源。「订阅诊断」可以显示入站是否被包含、授权来源以及被排除的原因。

### 8.3 套餐（分级售卖）

在「用户 → 套餐」里像机场一样定义套餐。套餐是一种特殊的分组：

- **可用服务器**：用节点等级决定（例如 Lv.1 普通线路、Lv.2 IPLC、Lv.3 原生 IP），也可另外授权整个节点。套餐页底部的「节点 × 套餐」表能直接看出每个套餐能用哪些节点。
- **限额**：流量、时长（0 为不限期）、流量重置周期、设备数、IP 数和限速（限速为专业版）。
- **到期后**：停用账号，或自动降级到另一个套餐（常见做法是降级到不限期的「免费版」）。
- **售价**：只用于展示，支付插件可以读取。

一个用户同时只有一个套餐，普通分组和单独授权不受影响。给用户开通套餐的方式：

| 操作 | 效果 |
| --- | --- |
| 开通 / 换套餐 | 从今天开始计时，**已用流量清零**，流量、到期、设备数、IP 数设为套餐的值，个人限速改为跟随套餐 |
| 续费同一套餐 | 到期时间在原到期日基础上顺延；账号仍正常时保留已用流量，已到期或已超额时清零 |
| 到期 | 按套餐设置停用，或降级到指定套餐并从今天重新计时 |

入口：用户详情的「开通 / 续费套餐…」，或勾选多个用户后点「开通套餐」。新建 / 编辑用户时选择套餐只会预填限额（可再修改），不清零流量。修改套餐后，已开通用户的可用节点和限速立即生效，流量和到期时间在下次开通或续费时更新。删除套餐时用户保留当前流量和到期时间，但失去套餐里的节点。

支付等插件用 `users:plan` 令牌调用 `POST /users/:id/plan` 开通 / 续费，详见 [API 令牌](plugins/api-tokens.md)。

### 8.4 在 Telegram 机器人售卖套餐

在「用户 → 售卖」里开店，用户在机器人里用 `/buy`（或菜单「🛒 购买套餐」）自助购买：

社区版通过**兑换码**售卖；Telegram Stars、易支付、USDT 自动收款属于专业版功能「在线收款」（`shop_payments`；签发为“全部功能”的许可证自动包含）。社区版的机器人商店照常列出在售套餐，套餐卡片会引导用户用兑换码开通。许可证到期后，已付款的易支付 / USDT 订单仍会照常到账开通，未付款订单只能取消。

1. **支付设置**：打开「开放购买」，按需配置付款方式：
   - **Telegram Stars**（专业版）：电报内置，不需要商户号；收入在 Telegram 账户里，通过 Fragment 提现。
   - **易支付 / EPay**（专业版）：填写网关地址、商户 ID、商户密钥和支付方式（`alipay,wxpay`）。网关回调地址为 `面板地址/pay/epay/notify`，付款后买家跳回 `面板地址/pay/return` 再自动打开机器人；请确认面板能从公网访问（设置 `POLARIS_PUBLIC_URL`），并在易支付商户后台把**面板域名**加入授权域名，否则会提示「支付返回域名未通过审核」。
   - **USDT**（专业版）：支持 TRON (TRC20)、BNB Smart Chain (BEP20)、Polygon、Arbitrum 四个网络，在设置里勾选要接受的网络。
     - TRON 填 T 开头的收款地址，建议填 TronGrid API Key；三个 EVM 网络共用一个 0x 收款地址。请用自己掌握私钥的钱包，不要用交易所充值地址。
     - 买家下单时自选网络，付款页（机器人和网页商店）显示网络、收款地址、精确金额和地址二维码。
     - 每笔订单金额会多 0.0001–0.05 USDT 的尾数（各网络分开计算），面板每 30 秒查询链上到账并按金额对账。EVM 网络等待足够的区块确认（BEP20 15 个、Polygon 64 个、Arbitrum 20 个）后才开通。
     - EVM 网络默认使用公共 RPC；被限流时可以在「自定义 RPC 节点」里填自己的节点。
   - **兑换码**：在「兑换码」里按套餐批量生成，在自己的渠道售出，用户发送 `/redeem 兑换码` 兑换。
2. **套餐**：编辑套餐，打开「在 Telegram 机器人售卖」，填写各付款方式的价格（留空表示不用这种方式）。
3. **条款与售后**：填写购买条款和售后联系方式，用户通过 `/terms`、`/paysupport` 查看。Telegram 要求用 Stars 收款的机器人提供这两项。

在「支付设置」中，**Telegram Stars、易支付 / EPay、USDT-TRC20、兑换码**各有独立开关。易支付内的支付宝、微信、QQ 钱包及自定义渠道也能分别关闭；先在「支付方式」中填写商户实际开通的渠道，下方会显示对应开关。

关闭渠道会同时移除机器人和网页商店的新付款入口，旧按钮及直接请求也会检查开关。收款地址、密钥、渠道列表和未使用的兑换码都会保留，重新开启即可继续使用；关闭兑换码期间不消耗兑换码。升级时沿用现有渠道的可用状态。

开关不停止真实到账处理：关闭 Stars 后拒绝新的预结算，但已扣款通知仍会开通；易支付回调和 USDT 链上核验继续处理已有订单。已经发出的外部付款链接、收款地址不能通过面板开关撤回，实际到账后仍核验开通。

规则：

- 已绑定账号的用户购买会续费（同一套餐顺延）或换套餐（清零已用流量）；没有账号的用户付款后自动创建账号（用户名为前缀 + Telegram ID）、绑定并收到订阅链接。可以关闭「自动建号」，只允许已绑定用户购买。
- 自动创建的账号可以自己修改用户名：在机器人里发 `/rename 新用户名`（或「📊 我的流量 → ✏️ 修改用户名」），或在用户中心点「修改用户名」。用户名为 3–32 位字母、数字或 `_ . -`，不能和已有用户重名，7 天内只能改一次；订阅链接和节点不受影响。管理员创建的账号不能自助改名。可在「支付设置」里关闭「自助改名」。
- 每笔付款只开通一次：支付平台的交易号唯一记录，重复回调、重复消息都不会重复开通。
- 新订单冻结购买时的流量、有效期、重置规则、设备/IP 限制和流量包额度；修改商品不会改变这些订单的交付权益。节点访问、限速和到期降级仍跟随套餐实时策略；删除套餐后相关付款会进入待人工处理，避免交付无法使用的套餐。历史订单没有快照，仍按原有规则处理。
- 订单默认 30 分钟有效。Stars 订单过期后会在付款前被拒绝；易支付仍处理可信的迟到回调。USDT 在订单有效期结束后额外核验 3 小时；取消、付款成功都不会立即释放这段时间内的金额预留。多实例通过数据库唯一约束分配尾数。
- 新 USDT 订单保存原收款地址，修改地址或关闭渠道后仍会核验旧地址的在途付款；升级前订单未保存地址，请在旧订单处理完毕后再换地址。超过核验窗口的转账请凭交易哈希联系管理员人工对账。
- 「订单」页可以搜索、筛选，查看近 30 天收入；对没收到回调的订单可以「手动开通」，对 Stars 订单可以「退款」（退回 Stars，不会自动收回套餐）。
- 没付款的订单可以随时继续支付或取消：商店和「我的订单」里有「⏳ 未付款订单」入口，每个订单都有「💳 继续支付」和「❌ 取消」（需要确认）；付款消息里也带「取消订单」按钮。Stars 在当前消息展示付款卡片，点击「继续支付」打开 Telegram 原生付款窗口，不再反复发送原生发票；同一买家、绑定账号、商品、权益快照及价格的未过期 Stars 订单会复用，保留原截止时间。付款链接保存在数据库中，机器人重启后仍可继续；更换机器人时会重新生成。
- 关闭 Telegram 付款窗口不会通知面板，也不会取消订单。要关闭订单，请在付款卡片或未付款订单里点击「取消订单」并确认，页面会明确显示「订单已取消」。取消后的订单不再占用 5 个未付款名额，旧 Stars 付款入口会在预结算时被拒绝；如取消前已实际扣款，延迟到达的可信付款仍正常开通。升级前发送的原生发票会保留在聊天历史中，取消后同样无法继续付款。
- 易支付继续支付时可以换支付宝 / 微信等方式，USDT 会重发原订单的转账信息；如果取消后仍然付款，到账后照样开通。管理员也可以在「商店 → 订单」里取消待支付订单，或手动开通已取消的订单。
- 用户在机器人里用「📋 我的订单」（`/orders`）查看订单。付款成功、开通失败都会通知 Telegram 管理员，并发出 `order.paid` / `order.failed` 事件。

#### 网页商店

在「商店 → 支付设置」打开「网页商店」后，用户可以在 `面板地址/u/shop` 购买，不依赖 Telegram。需要先在「订阅设置」里开启用户中心。

- 登录了用户中心（Telegram 登录）的用户：购买会续费或更换自己的套餐，也可以加购流量包；用户中心首页会显示「🛒 购买 / 续费」入口。
- 没登录的用户：可以直接购买新账号（需开启「自动建号」），付款后订单页会显示用户名和订阅链接，并提供「绑定 Telegram」按钮，绑定后就能登录用户中心续费。
- 付款方式与机器人一致：易支付、USDT（专业版「在线收款」）；没有在线收款时，页面只提供兑换码。
- 浏览器用一个随机凭据（Cookie）识别订单。订单页会显示订单号和订单凭据（以及带凭据的链接）；换浏览器或设备时，在商店页的「查询订单」输入订单号和凭据即可找回订单和账号。
- 易支付付款后会回到订单页，页面会自动刷新付款状态；订单可以取消。后台订单列表里网页订单带「网页」标签。

#### 优惠券

在「售卖 → 优惠券」新建优惠码，买家下单时按优惠价付款（需要在线收款才有付款环节；100% 优惠券不经过付款）。

- **优惠方式**：按比例（如减 20%，即八折；100 表示免费），或按币种固定减免（人民币、USDT、Stars 分别填写）。优惠后不低于该币种的最小金额（¥0.01、0.01 USDT、1 Stars）；减到 0 时直接免费开通，订单付款方式显示「优惠券（免费）」。
- **适用范围**：可用于全部套餐或指定套餐，也可以勾选「可用于流量包」。
- **次数**：「总次数」限制所有人一共能用几次（未付款且未过期的订单先占名额）；「每人次数」默认 1，按账号、Telegram 或浏览器识别同一买家。已付款的订单一定计数，即使同时付款超过了总次数也照常开通；退款和取消不返还次数。
- **有效期**：可设开始和结束时间，也可以随时停用。批量生成时填前缀和数量，生成后可复制或导出。
- **使用**：网页商店页面有「优惠码」输入框，点「使用」后各商品价格会变成优惠价，再选付款方式下单；机器人里发送 `/coupon 优惠码`（或在商店点「🏷 优惠码」查看说明），30 分钟内打开套餐或流量包时价格按钮显示「原价 → 优惠价」，下单后优惠码自动清除；`/coupon off` 取消。
- 订单列表里用了优惠券的订单带「券」标签，订单详情显示优惠码和原价；每个优惠券的「使用记录」列出用它付款的订单。`order.paid` 事件附带 `coupon` 和 `original_amount`。

### 8.5 套餐增值（专业版）：流量包与套餐节点倍率

需要许可证功能「套餐增值」（`plan_addons`；签发为“全部功能”的许可证自动包含）。

**流量包**：在「用户 → 售卖 → 流量包」里新建，例如「加油包 50G」，填写流量、各付款方式的价格，可限定适用套餐。

- 用户流量不够时，在机器人「🛒 购买套餐 → 📦 加购流量包」里购买，不改变套餐和到期时间。
- 流量包**只在当前流量周期内有效**：加到流量配额里，下次流量重置、到期自动续订或开始新套餐周期（开通 / 换套餐）时失效；续费同一套餐（周期延续）时保留。
- 不限流量的账号不能购买；管理员直接修改用户流量配额后，流量包记录清零（以管理员设置为准）。
- 也可以在「兑换码」里选择「流量包」批量生成兑换码，已绑定账号的用户发送 `/redeem 兑换码` 加上流量（没有账号的用户不能兑换流量包码，码不会被消耗）。
- 插件可以用 `users:plan` 令牌调用 `POST /users/:id/pack {packId}`（支持 `Idempotency-Key`）。

**套餐专属节点倍率**：编辑套餐时，在「套餐专属节点倍率」里为可用节点填写倍率，例如 IPLC 节点默认 ×2，「专业版」用户只按 ×0.5 扣流量。留空表示使用节点自己的倍率。结算流量和订阅里的节点名称（`{rate}`）都会使用用户实际适用的倍率。

### 8.6 按节点配额

用户详情支持节点流量包和节点上限：

- **节点流量包**只在指定节点使用，优先于总流量扣除；总流量用完后，仍可使用剩余节点包。重置总流量不会自动补回节点包。
- **节点上限**限制一个流量周期在该节点最多使用多少，达到上限后只停止该节点的使用。
- 两者均需结合节点流量倍率理解实际扣量。

### 8.7 客户独立限速（专业版）

可以按用户设置上下行 Mbps，也可以让用户跟随分组套餐。限速按**每个节点上该用户的连接合计**执行，不是跨所有节点共享一个总速率。

当前界面明确提示 Hysteria2 入站不支持客户独立限速。需要此能力时，选择支持的协议并通过实际连接验证。入站端口共享限速也不能替代每用户限速。

### 8.8 批量操作与设备维护

批量创建、导入导出、绑定 / 解绑节点、续期、启停和重置流量前，先检查筛选条件和已选用户数量。对单个用户验证后再批量处理。

设备达到 HWID 上限时，可在用户详情的「设备」中核对并移除已不用的记录。重置订阅令牌会同时改变代理凭据，不能把它当作单纯的“清空设备”操作。

## 9. 订阅设置与订阅转换

### 基础订阅设置

进入「订阅 → 订阅设置」，可以配置订阅域名、标题、更新间隔、客服链接、公告、信息节点和不同客户端的规则模板，也可统一停用订阅。

配置独立订阅域名时，按以下顺序操作：

1. 将域名解析到提供订阅服务的主控或反向代理。
2. 为该域名配置 HTTPS 和回源。
3. 在面板的订阅设置中填写完整地址。
4. 从用户页重新复制订阅，在浏览器和客户端分别验证。

一键安装的主控可使用 `polaris set-sub-domain sub.example.com` 配置 Caddy 站点，然后在订阅设置中填写该域名。建议保留默认开启的「订阅域名只开放订阅」，让该域名仅提供订阅和用户中心，管理后台仍使用原后台地址。旧域名如果下线，已保存旧地址的客户端不会自动知道新地址，需要重新分发。

模板影响客户端的规则和策略组，不会自动为用户授予新的入站权限。修改模板后先用测试用户更新订阅，确认客户端可以加载。

### 订阅诊断

用户详情中的「检查订阅」会显示账号问题、各格式节点数量、入站授权来源和是否包含。排查顺序建议为：

1. 用户是否正常、未到期且有剩余流量。
2. 是否有有效授权，相关入站是否启用。
3. 入站地址和协议是否能输出给当前客户端。
4. 全局订阅是否被停用，域名和反向代理是否正常。

### 订阅转换（专业版）

「订阅 → 订阅转换」用于引入外部订阅源或手动节点，再通过订阅组与面板用户节点合并。

1. 添加订阅源，填写 URL 或节点内容，刷新并检查解析结果。
2. 创建订阅组，选择要合并的来源和面板用户节点。
3. 设置过滤、重命名、排序、去重和规则方案。
4. 预览并复制生成的订阅组链接，在目标客户端验证。

支持的源格式包括 Base64、Clash、sing-box 和 SIP008。规则方案可使用内置方案或自定义 ini URL，也可配置第三方 subconverter。外部订阅有自己的有效期、流量和可用性，需独立检查；使用第三方转换服务会向该服务传递相关订阅信息，应选择可信服务。

<a id="networking"></a>

## 10. 域名、CDN、中转与路由

这些功能可在基础连接正常后逐步启用，每次变更后检查客户端连接和节点应用结果。

| 功能 | 入口与操作要点 |
| --- | --- |
| DNS 服务商 | 「域名与证书 → 域名与 DDNS」添加 Cloudflare 或自定义 Webhook 服务商；凭据按所需范围授权 |
| 域名绑定与 DDNS（专业版） | 绑定域名和节点，选择 A / AAAA 等记录；启用节点 DDNS 后，公网 IP 变化会触发更新 |
| CDN 入口 | 为支持 CDN 的协议组合添加 CDN 配置档和入口，核对域名、Host、路径、SNI、端口及回源证书 |
| 端口转发 | 「入站与转发 → 端口转发」配置来源、目标和转发方式，检查两端网络和端口 |
| 链式代理 | 「链路与路由」配置中转 / 落地关系、出站与 detour，先确认每一段可达 |
| 一键中转接口 | 选择已有落地入站与 1–3 个中转节点，预览后生成原样转发或 TCP / WS 认证隧道；当前仅提供后端接口，见[配置说明](design/relay-one-click.md) |
| 路由与负载均衡 | 设置全局或节点规则、出口组和探测策略；节点 / 内核支持的策略不同 |

DNS 服务商管理属于基础功能，自动域名绑定和 DDNS 需要专业版授权。DDNS 更新域名解析，不会修改云安全组，也不能保证客户端 DNS 缓存立即刷新。

普通 HTTP CDN 不适用于任意代理协议。REALITY 直连、Hysteria2 / TUIC 的 UDP 流量，以及 Agent 的 mTLS 接入不能直接套用普通 HTTP 回源配置。应依据入站界面显示的 CDN 能力选择组合。

链路探测失败时，先验证每一跳的目标地址、协议、认证和端口；避免出口经由自身形成循环。内核 DNS 与规则设置也应与客户端规则区分：前者控制节点行为，后者由订阅下发给客户端。

入站支持 `relayOnly` 发布策略：开启后订阅和分享只使用中转入口，即使线路停用或删除也不会回退发布直连；开关不修改防火墙。后端还提供线路分层诊断，分别检查下发、入口 TCP / TLS、逐跳端口及落地出口，并明确代理业务和 UDP 尚未验证。当前通过[一键中转接口](design/relay-one-click.md)配置，页面保持不变。

### 出站与路由

「链路与路由 → 出站与路由」按节点（或全局）管理出站和路由规则。规则按优先级从小到大匹配，第一条命中的规则决定出口。

**geosite / geoip 分类浏览**：条件选 geosite 或 geoip 时，值输入框旁有「浏览」按钮，打开内置的分类列表：

- 分类名来自 v2fly（Xray 自带的数据，sing-box 的规则集也由它生成），两个内核通用。geosite 约 1500 个分类，geoip 约 250 个。
- 列表上方有常用分类，可直接点选；也可以搜索分类名。
- geosite 分类点「查看」可列出其中的域名。带属性的分类（如 `google@cn`）只匹配标了该属性的部分，点分类下的 `@属性` 即可选用。
- 在搜索框输入一个域名（如 `chat.openai.com`），会列出包含它的所有分类，方便确认规则会不会命中。
- sing-box 的 geoip 规则集只有国家代码和 `private`，其他 geoip 分类（如 `telegram`、`cloudflare`）标有「仅 Xray」，在 sing-box 节点上不生效。

分类数据随面板版本内置，查看时不需要联网。节点上实际生效的是内核自带或下载的数据文件，个别新分类可能要等内核数据更新后才可用。

**均衡组之间回退**：先在同一节点创建普通出站，再从末级向主级创建均衡组，例如 `emergency → backup → primary`。编辑 `primary`，在「兜底出站 / 均衡组」选择 `backup`；编辑 `backup`，选择 `emergency`；路由规则或入站出口选择 `primary`。

主组全部不可用才会使用备用组；各组保留自己的均衡策略，主组恢复后新连接回切。界面显示完整回退路径，已被引用的组需要先解除引用才能删除或改名。支持 Xray / mihomo；sing-box 暂不支持组间兜底。Xray 末级可选 `block`，在所有线路故障时拒绝连接；选 `direct` 表示允许节点直接联网。切换取决于健康探测周期，既有会话不迁移。修改后需更新节点 Agent 才能使用新的配置渲染逻辑。详见[均衡器回退设计](design/balancer-fallback.md)。

**WARP 出站**：「出站与路由」里选中节点后点「+ WARP」：

1. 面板向 Cloudflare 注册一个免费 WARP 设备，自动生成一个 WireGuard 出站（默认标签 `warp`）。WireGuard 私钥在面板生成，不会发给 Cloudflare；有 WARP+ 许可证可以一并填入。
2. 勾选哪些流量走 WARP：AI 服务（OpenAI、Claude、Gemini、Perplexity）、流媒体、Google / YouTube、TikTok / Spotify，也可以用分类浏览器挑其他 geosite 分类，或填额外的域名。面板会添加一条「WARP 分流」路由规则（优先级 25），之后可在路由规则里修改或删除。
3. 都不勾选时只添加出站，可以自己写规则，或把它加进负载均衡组、作为其他出站的下一跳。

走 WARP 的流量出口是 Cloudflare 的 IP，常用于访问对机房 IP 有限制的 AI 和流媒体服务。注册由面板服务器发起，面板需要能访问 `api.cloudflareclient.com`；节点则需要能连通 Cloudflare 的 WARP 端点（UDP 2408）。只有 Hysteria2 内核的节点不能使用 WireGuard 出站。每个节点建议单独注册，不要共用同一个 WARP 设备。

## 11. Telegram、登录与审计

### Telegram 管理与告警

进入「系统 → Telegram 机器人」：

1. 从 BotFather 创建机器人，填写 Bot Token 并启用。
2. 保存后检查机器人运行状态。
3. 点击「绑定管理员」，生成一次性绑定码，在机器人私聊中发送 `/bind 绑定码`。
4. 选择超级管理员或节点管理员，并为节点管理员指定可管理节点。
5. 使用「发送测试消息」验证，再设置告警、流量 / 到期提醒和每日报告。

超级管理员拥有完整管理范围；节点管理员只查看和操作分配的节点。不要把管理员绑定码当作用户订阅绑定链接发给普通用户。机器人仅在私聊中处理管理操作。

告警与普通用户自助功能可用于基础工作流；Telegram 中的高级管理菜单需要专业版相应授权。每日报告时间使用服务器本地时间。

<a id="mail"></a>

### 邮件通知（SMTP）

在「设置 → 邮件」填写 SMTP 服务器后，面板可以发邮件：

- **给用户**：在用户编辑页「Telegram 与邮箱」里填写邮箱（自动转小写，同一邮箱只能属于一个用户；批量导入导出的字段名是 `mail`）。填了邮箱的用户会收到和 Telegram 相同的提醒——流量提醒、到期提醒、已停用、已到期、已恢复——以及订单开通通知；没绑 Telegram 的用户也能收到。自定义提醒模板（「Telegram → 提醒文案」）同样用于邮件，以纯文本发送。提醒阈值在 Telegram 页设置，两边共用，每个周期只提醒一次。可以关闭「给用户发提醒邮件」。
- **给管理员**：填写「管理员收件地址」并开启「给管理员发通知邮件」后，发给 Telegram 管理员的通知（新订单、开通失败、备份失败、升级结果、节点告警等）也会抄送一份。通知过多时可单独关闭此开关，保留收件地址；用户邮件提醒、邮箱登录验证码、手动测试邮件和 Telegram 通知按各自设置工作。升级时默认开启，延续已有通知行为，关闭并保存后停止后续管理员邮件发送。
- 邮件标题带站点名称前缀，提醒和订单使用统一品牌卡片，验证码单独突出显示有效期。正文按配置提供用户中心、订阅按钮、备用链接和客服入口，适配手机与深色模式，同时保留完整纯文本版本。邮件采用内联样式排版，无需加载远程图片或字体。邮件按顺序在后台发送，失败只记录日志，不影响其他功能。

常见配置：

| 服务 | 服务器 | 加密方式 | 用户名 / 密码 |
| --- | --- | --- | --- |
| QQ 邮箱 | `smtp.qq.com` | SSL/TLS（465） | 完整邮箱 / 授权码（邮箱设置里开启 SMTP 后生成） |
| 163 邮箱 | `smtp.163.com` | SSL/TLS（465） | 完整邮箱 / 授权码 |
| Gmail | `smtp.gmail.com` | STARTTLS（587） | 完整邮箱 / 应用专用密码（需开启两步验证） |
| 阿里云邮件推送 | `smtpdm.aliyun.com` | SSL/TLS（465） | 发信地址 / SMTP 密码 |

填好后在下方输入一个收件地址，点「发送测试邮件」：使用表单里还没保存的值，密码留空时用已保存的。发件地址通常必须与登录账号相同（或已在服务商处验证）。大量发信建议使用邮件推送服务，并为发信域名配置 SPF / DKIM，避免进垃圾箱。「不加密」只适合本机或内网的邮件中继：这时用户名和密码会明文传输。

### 登录与账号保护

在「系统 → 设置」配置密码、两步验证和第三方登录：

- GitHub OAuth 的回调地址应复制界面显示值。先用原账号登录并完成绑定，再测试 GitHub 登录。
- OIDC / OAuth2 按身份提供方要求配置客户端信息、回调和账号映射，保存前核对域名与后台路径。
- Telegram 网页登录通过数字确认；仅确认自己发起的登录请求。
- 敏感操作可能要求再次验证密码或两步验证码。

修改密码会使其他会话失效。连续 5 次登录失败会触发约 15 分钟账号锁定。遗失密码或两步验证设备时，在一键安装的主控服务器执行：

```bash
polaris reset-password
polaris reset-2fa
```

Docker 部署重置密码可使用 `docker compose exec polaris polaris admin reset-password`，关闭两步验证使用同一命令入口的 `reset-2fa`。操作完成后保存新密码并重新配置两步验证。

### API 令牌

在侧边栏一级菜单「扩展 → API 令牌」创建令牌，供脚本、发卡网和插件调用接口；「系统 → 设置 → 账号安全」中也保留同一管理入口：

- 请求头带 `Authorization: Bearer plt_…`。令牌**只显示一次**，数据库里只保存哈希值。
- 令牌只能访问勾选的权限范围。订单服务可选“仅续期用户”或“仅增加用户流量”；“查看用户”和“读取订阅”会涉及代理凭据，应按需批准。修改设置、管理员、令牌本身等接口一律拒绝。
- 支付类对接使用续期 / 加流量接口，并带上 `Idempotency-Key`。同一调用者、操作、用户和 key 在 24 小时内对相同内容返回已提交结果；不同内容返回 409。响应头 `Idempotent-Replayed: true` 表示重放。超过保留期仍需支付服务的长期订单去重。
- 令牌可以读取按自身权限过滤的 `GET /openapi.json`；具体范围、事务语义和旧版缓存升级说明见 [API 令牌与订单接口](plugins/api-tokens.md)。

```bash
# 续费 30 天，并重置已用流量
curl -X POST "$PANEL/api/v1/users/$USER_ID/renew" -H "Authorization: Bearer $TOKEN" \
  -H "Idempotency-Key: order-1001" -H "Content-Type: application/json" -d '{"days":30,"resetTraffic":true}'
# 增加 100 GB 流量
curl -X POST "$PANEL/api/v1/users/$USER_ID/add-traffic" -H "Authorization: Bearer $TOKEN" \
  -H "Idempotency-Key: order-1002" -H "Content-Type: application/json" -d '{"gb":100}'
```

`$PANEL` 包含后台路径，例如 `https://panel.example.com/x7k2`。令牌的操作会记录在审计日志里，操作人显示为 `token:名称`。

### Webhook

在「系统 → 设置 → Webhook」把事件推送到外部服务：

- **JSON 格式**（插件、自建服务）：面板发送 POST 请求，请求体为 `{"id","type","created_at","data"}`，`data` 里带用户（`user`）或节点（`node`）信息。请求头包括 `X-Polaris-Event`（事件类型）、`X-Polaris-Delivery`（投递编号），以及签名 `X-Polaris-Signature: t=<时间戳>,v1=<签名>`。签名为 `HMAC-SHA256(签名密钥, "<时间戳>.<请求体>")` 的十六进制。签名密钥只在创建时显示一次。
- **机器人格式**：Discord、Slack、企业微信、钉钉、飞书，发送一行文本消息。钉钉和飞书开启「加签」时填写加签密钥。
- 事件按类型订阅，比如 `user.created`、`user.expired`、`node.offline`；也可以订阅一整组（`user.*`）。都不勾选表示接收全部事件。
- 接收方返回 2xx 即算成功。失败后分别在 1 分钟、5 分钟、30 分钟、2 小时、12 小时后重试，共 6 次。「记录」里可以查看最近 7 天的投递内容和错误，并手动重发。

校验签名的示例（Node.js）：

```js
const [t, v1] = req.headers['x-polaris-signature'].replace('t=', '').split(',v1=')
const ok = crypto.createHmac('sha256', SECRET).update(`${t}.${rawBody}`).digest('hex') === v1
```

### 审计日志

在「系统 → 审计日志」查看配置变更、操作者和相关记录。发生意外修改时，结合时间、节点配置结果和服务日志定位原因。向外部反馈时应先脱敏，尤其是用户名、IP、订阅令牌和凭据。

## 12. 统计与监控

建议日常检查：

| 页面 | 关注内容 |
| --- | --- |
| 仪表盘 | 节点状态、整体流量和需要处理的问题 |
| 统计 | 按天流量、用户 / 节点排行、入站 / 出站统计与月报 |

## 13. 升级、备份与迁移

<a id="backup"></a>

### 13.1 备份

在「系统 → 设置 → 备份与恢复」设置自动备份时间、保留份数和备份口令，保存后创建一次备份并下载到服务器之外。计划时间使用服务器本地时间。

备份包含面板数据和内部 CA。在线导出在同一数据库读快照中完成，避免备份期间的付款或流量结算使不同表的数据对不上；PostgreSQL 使用只读 REPEATABLE READ 事务。两种备份的恢复条件不同：

| 备份类型 | 恢复条件 |
| --- | --- |
| 未加密备份 | 目标面板必须使用相同的 `POLARIS_SECRET_KEY` |
| 设置口令的加密备份 | 附带恢复所需密钥，可迁移到新服务器；必须保存备份口令 |

丢失加密备份口令无法恢复。请将口令与备份分开保存，并备份环境文件、反向代理配置和必要的外部服务配置。

一键安装的主控也可执行：

```bash
polaris backup
```

交互终端会询问备份口令；完成后按输出位置取走文件。未加密文件通常为 `.tar.gz`，加密文件为 `.tar.gz.enc`。不要在服务运行时直接复制正在写入的 SQLite 数据库代替受支持的备份流程。

**备份存储位置**：默认保存在本机数据目录（`<数据目录>/backups`）。在「备份存储位置」选「S3 对象存储」后，备份直接存到 S3 兼容的对象存储（AWS S3、Cloudflare R2、MinIO、Backblaze B2 等），社区版也能用：

1. 填写端点（AWS 留空；R2 为 `https://<账户 ID>.r2.cloudflarestorage.com`）、区域（R2 填 `auto`）、存储桶、路径前缀和访问密钥。
2. MinIO 等自建服务通常需要打开「路径风格地址」（默认打开）；只支持 `存储桶.端点` 形式的服务请关闭。
3. 点「测试连接」：面板会写入、读取、列出并删除一个测试文件。通过后再「保存设置」。

存到 S3 后，备份列表、下载、删除、保留份数清理和「恢复」都直接操作存储桶；恢复前的快照也存进存储桶（存储桶不可用时退回本机目录）。命令行 `polaris backup` / `polaris restore` 仍只处理本机文件。访问密钥只需要该存储桶（或前缀）的读、写、列出和删除权限。

专业版可以把备份推送到 Telegram、WebDAV 或 S3。配置后创建备份并检查目标位置，不能只凭“设置已保存”判断推送成功。备份存储已选 S3 时，不再重复推送到 S3。

### 13.2 升级

推荐顺序：备份 → 阅读发布说明 → 升级主控 → 检查登录与订阅 → 逐步升级 Agent → 按需要升级内核。

在「系统 → 设置 → 版本与更新」启用自动升级后，按服务器本地时间在所选小时的整点检查并发起升级，例如选择 `04:00`。已有小时设置继续使用对应整点，默认是 `04:00`。

一键安装：

```bash
polaris check-update
polaris backup
polaris update
polaris doctor
```

升级会保留配置和数据。需要固定版本时使用 `polaris update --version TAG`，将 `TAG` 替换为实际发布标签；回退前先确认该版本与现有数据兼容。

Docker 使用发布镜像时，更新所用标签后运行 `docker compose pull` 和 `docker compose up -d`；使用源码构建时，获取目标版本源码后运行 `docker compose up -d --build`。保留数据卷，`docker compose down -v` 会删除命名卷中的数据，不应用于常规升级。

### 13.3 恢复与迁移

恢复会用备份内容替换目标面板数据，应先备份目标端现有数据，并安排维护时间。

同机恢复可在「备份与恢复」选择文件，或在一键安装环境中执行：

```bash
polaris restore /path/to/polaris-backup.tar.gz.enc
```

将示例路径替换为真实备份文件；加密文件会要求输入口令。恢复后重新登录，检查管理员、用户、节点、订阅和证书。

迁移到新服务器：

1. 在旧主控创建加密备份并下载，保存口令与环境配置。
2. 如果迁移涉及专业版实例绑定，先按[许可证管理](#license)处理停用和重新激活。
3. 在新服务器安装兼容版本，配置外部地址、HTTPS 和 Agent 接入端口。
4. 恢复备份，确认数据完整。
5. 切换域名解析或节点连接地址，避免新旧主控同时作为同一批节点的活动主控。
6. 检查节点重连、用户订阅、客户端连接、流量上报和定时备份。

备份保留内部 CA，因此保留原连接域名且让它指向新主控时，已接入节点通常无需重装。**如果主控域名或 Agent 接入地址变化，必须同步更新节点的连接配置**；恢复数据库不会自动改掉每台节点保存的主控地址。

数据库支持 SQLite / PostgreSQL 间的备份恢复；外部 PostgreSQL 连接、DNS、云安全组和反向代理仍需在目标环境单独配置。

<a id="db-migrate"></a>

### 从 SQLite 切换到 PostgreSQL

主控数据量大，或准备运行多个主控实例时，可以把数据库换成 PostgreSQL（12 及以上）。数据目录里的 CA 证书等文件不变，`secret_key` 也保持不变。

一键安装的主控执行一条命令即可（面板会停止约一分钟）：

```bash
polaris migrate local                                   # 在本机安装 PostgreSQL 并迁移过去
polaris migrate 'postgres://用户:密码@主机:5432/polaris'  # 迁移到已有的空数据库
polaris migrate sqlite                                  # 换回 SQLite
```

命令会停止面板，在一个事务里复制全部数据并逐表核对行数，然后改好配置并重新启动。任何一步失败，面板都会用原数据库重新启动，数据不变。原数据库不会被删除，确认正常后可以自行清理。SQLite 不限制文本长度，超出 PostgreSQL 列长度的内容（例如超长备注）会被截断，命令结束时会列出受影响的列。

Docker 或手动部署时，先停止主控，再用面板程序执行 `migrate -to DSN`（Docker 容器里是 `polaris migrate -to DSN`，手动部署是 `polaris-server migrate -to DSN`，需加载与服务相同的环境配置；目标库已有数据时加 `-replace` 才会覆盖），然后把 `POLARIS_DB_DSN` 改成同一个地址并启动。

PostgreSQL 地址可以写成 `postgres://` / `postgresql://` URL，也可以写成 `host=… user=… dbname=…` 形式。每个主控实例最多使用 20 个数据库连接。

<a id="multi-instance"></a>

### 多个主控实例（高可用）

几台服务器上的主控连同一个 PostgreSQL，前面放负载均衡，任意一台宕机，后台、订阅和节点都不受影响。

**要求**
- 数据库必须是 PostgreSQL（SQLite 只能单实例）。Redis 可选，配置后在线 IP、限流计数、告警去重也会在实例间共享。
- 每台的 `POLARIS_SECRET_KEY`、`POLARIS_DB_DSN`、`POLARIS_PUBLIC_URL` 必须相同；`POLARIS_AGENT_HOSTS` 写负载均衡对外的域名或 IP。
- 内部 CA 证书存在数据库里，新加的实例不用复制数据目录。

**新增一台**：在新服务器上一键安装时选「PostgreSQL（已有）」并填同一个数据库地址，装好后把 `/etc/polaris/polaris.env` 里的 `POLARIS_SECRET_KEY`、`POLARIS_PUBLIC_URL`、`POLARIS_AGENT_HOSTS` 改成和第一台一样，再 `polaris restart`。

**负载均衡**
| 端口 | 方式 | 说明 |
|---|---|---|
| 后台 / 订阅（443 或面板端口） | HTTP(S) 七层，任意分发 | 不需要会话保持；后台实时推送用 WebSocket，代理需支持 |
| 节点接入（默认 9443） | **TCP 四层透传** | 节点使用双向 TLS 和长连接，不能在负载均衡上解开 TLS |

**各实例如何分工**
- 实例之间自动选出一台「主实例」，它负责全部定时任务（流量结算、到期处理、提醒、备份、证书续期、DDNS 等）和 Telegram 机器人收消息；主实例停止或宕机后，其他实例 15 秒内接管。每台都能发 Telegram 通知。
- 节点连在哪台都可以。在任何一台后台改配置、重启内核、看日志，都会转发给节点所连的那台执行；节点在线状态、安装进度、限速状态在每台后台都能看到。
- 登录码（Telegram 登录、GitHub / SSO 登录、订阅转换回调）在任何一台生成，都能在另一台使用，且只能用一次。设置修改会立刻同步到所有实例。

**备份**：多实例部署请把「备份存储位置」设为 S3（见 [13.1 备份](#backup)），这样任何一台后台都能看到、下载和恢复全部备份；定时备份只在主实例上生成。备份存在本机时，每台只能看到自己机器上的备份。在任何一台恢复备份后，执行恢复的实例重启并导入数据，其他实例随后自动重启，重新加载 CA、设置和缓存。

**升级**：在任何一台后台（或 Telegram）点「升级面板」，所有运行中的实例都会各自升级自己的机器（每台都需要先装好在线升级组件：`polaris update --force`，只需一次）。自动升级也一样。升级结果每台各发一条 Telegram 通知，开头带主机名。

**集群卡片**：「设置 → 版本与更新」页下方的「集群」卡片列出各实例的主机名、版本、启动时间和最后在线时间，并标出主实例；只有一台时不显示。版本不一致时会提示（通常是升级还没完成，或某台升级失败）。离线超过 1 天的实例自动从列表移除。

**仍按实例分开的**：节点 agent 安装包缓存、Geo 文件保存在各自的数据目录，只是缓存，不需要共享。

<a id="license"></a>

## 14. 专业版与许可证

专业版功能包括客户独立限速、订阅转换、DDNS 与域名绑定、Telegram 管理菜单、备份推送、自定义 Logo 和专属主题。启用某项功能取决于程序构建和许可证授权范围。

- **自定义 Logo**：激活后在「设置 → 外观 → 自定义 Logo」上传（PNG / JPG / WebP / GIF / SVG，不超过 256 KB），显示在侧边栏、登录页和浏览器标签页图标；可随时恢复默认。
- **专属主题**：激活后在「设置 → 外观 → 专属主题」选择「黑金」。专属主题自带配色，选中后主题模式和主题色不再生效；仅保存在当前浏览器。许可证失效后自动恢复默认主题和默认 Logo。

激活步骤：

1. 确认已安装专业版。使用一键安装时可运行 `polaris switch pro`；Docker 使用对应 `-pro` 镜像标签。
2. 打开「许可证」，查看构建类型、实例、套餐和用量。
3. 输入从许可证提供方获得的激活码联网激活，或按页面提示导入离线许可证。
4. 检查功能是否解锁，并核对到期日、更新期限和数量上限。

到期、吊销或版本超出更新期限时，许可证页面会提示原因。已生效配置按许可机制保留，后续高级操作受当前授权限制；不要把继续运行理解为仍可新增或修改全部专业版配置。

联网许可证在面板启动时校验一次，此后每 6 小时加 0–30 分钟随机延迟校验；失败后依次在 5 分钟、30 分钟后重试，再失败则每 2 小时重试。可点击「立即校验」更新授权，连续点击有 30 秒冷却。

授权服务器暂时不可达时保留 14 天宽限期；超过后暂停用户、节点、配置等管理修改，已有代理、订阅与流量上报继续运行。登录、许可证校验/激活/导入和面板升级等恢复入口保留。联网校验成功或导入有效离线许可证后恢复管理。重复导入在线许可证不会重置宽限期。

页面只展示最近通信状态与时间，不显示或允许修改授权服务器地址；异常时检查网络或联系服务提供方。未发生联网授权请求时显示“尚未校验”，不代表服务故障。

需要更换实例时，先在旧面板停用许可证，再到新面板激活；旧面板无法操作时联系许可证提供方处理解绑。升级安装可能存在针对已有高级配置的试用期，新安装是否有试用以页面显示为准。

<a id="plugins"></a>

## 15. 扩展与插件

插件是**独立运行的外部服务**（任意语言），通过受限的 API 令牌和签名 Webhook 与面板对接，用来做支付商城、通知渠道、用户同步等。开发文档、SDK 和示例见 [polaris-plugins](https://github.com/cuijianzhuang/polaris-plugins)。

管理入口：「扩展 → 插件」。

1. **安装**：点「安装插件」，填入插件地址（可以是内网或 `127.0.0.1`）和插件作者给的安装码（如有）。面板读取插件清单，列出它申请的权限和订阅的事件，确认后需要二次验证（sudo）。面板为插件创建专用令牌和 Webhook，并把凭据直接交给插件。
2. **手动配对**：插件不支持自动安装时，面板只显示一次令牌和密钥，复制到插件里；插件开始应答健康检查后自动变为「在线」。
3. **配置**：按插件声明生成表单；密钥类字段保存后不再显示，留空表示保持原值。保存后面板会通知插件。
4. **页面与入口**：插件声明的后台页面出现在「扩展」里，在面板内嵌显示；声明的用户入口（如「购买 / 续期」）出现在用户中心。
5. **健康与升级**：面板每分钟检查插件是否在线，状态变化会发 `system.plugin_offline` / `system.plugin_online` 事件。插件升级后点「刷新清单」；新增权限或事件需要重新确认。
6. **停用与卸载**：停用后不再投递事件，页面和入口隐藏；卸载会吊销令牌并删除关联 Webhook。

安全提示：插件拥有它被授予的权限，安装前请核对权限列表（尤其是 `users:write`、`subs:read`）；插件只能使用自己的令牌，拿不到管理员会话。社区版最多同时安装 3 个插件，激活专业版后按授权上限（0 为不限）。

<a id="troubleshooting"></a>

## 16. 故障排查

先确认故障发生在哪一层：**后台访问、Agent 接入、内核应用、订阅生成、客户端连接**。不要同时修改多个环节。

| 现象 | 优先检查 | 处理方向 |
| --- | --- | --- |
| 访问域名返回 404 | 是否使用完整后台路径，是否误用了独立订阅域名 | 一键安装执行 `polaris info`；使用实际管理地址 |
| 登录失败或账号锁定 | 用户名、密码、两步验证、服务器时间、失败次数 | 等待锁定期或通过服务器管理命令重置 |
| 页面可开但数据不刷新 | WebSocket、反向代理、会话是否失效 | 检查代理对 WebSocket 的支持，重新登录并查看日志 |
| Agent 无法上线 | 主控地址、`9443/tcp`、安全组、DNS、CDN、注册令牌 | 保证 Agent 直连主控 mTLS 地址；失效令牌重新获取 |
| 节点在线但内核安装失败 | 发布文件下载、版本 / 架构、磁盘空间、校验错误 | 查 Agent 日志；使用有效版本和可信下载来源，不跳过校验 |
| 入站保存后应用失败 | 端口占用、协议组合、证书、内核版本 | 查看节点应用错误，修正后同步；必要时回滚 |
| 订阅没有节点 | 用户状态、授权、入站启用、格式兼容、全局停用 | 打开用户详情的「订阅诊断」查看具体原因 |
| 只有某个客户端缺少节点 | 该客户端是否支持协议及参数 | 比较诊断中的格式节点数，选择兼容协议 / 内核版本 |
| 能更新订阅，但连接超时 | 节点域名、公网端口、TCP / UDP、安全组、内核状态 | 从客户端网络检查真正的代理入口；更新订阅 |
| TLS / REALITY 握手失败 | SNI、证书域名、目标站点、时间、客户端版本 | 使用匹配证书或 REALITY 扫描结果，检查能力提示 |
| Hysteria2 / TUIC 无法连接 | UDP 是否可达、是否错误套用 HTTP CDN | 放行正确 UDP 端口，核对客户端与服务端配置 |
| 用量不增长或数值不同 | 上报延迟、流量倍率、内核统计能力 | 检查 Agent 状态与统计日志；区分用户结算和网卡统计 |
| 用户无故失效 | 到期、超额、禁用、IP 封禁、设备上限、令牌重置 | 调整实际触发的规则，重置令牌后重新分发订阅 |
| 证书续期失败 | DNS、80 端口占用、DNS 凭据权限、节点在线状态 | 修复验证条件后重试，检查续期结果 |
| Telegram 无法登录 | 机器人运行、账号绑定、数字确认是否过期 | 先验证机器人连通性，再重新发起登录 |
| 备份无法恢复 | 文件完整性、加密口令、原始密钥和版本 | 加密备份提供正确口令；未加密备份使用相同密钥 |
| 专业版功能仍锁定 | 构建类型、许可证功能范围、实例和更新期限 | 确认使用专业版程序，检查许可证页告警 |

一键安装的主控可收集：

```bash
polaris doctor
polaris status
polaris log
```

节点服务日志可用 `journalctl -u polaris-agent -n 100 --no-pager` 查看。Docker 主控使用 `docker compose ps` 和 `docker compose logs --tail=100 polaris`。

反馈问题时附上主控、Agent、内核和客户端版本，说明安装方式、错误时间、复现步骤与脱敏日志。不要公开管理员密码、订阅链接、注册令牌、私钥或完整备份。

<a id="compatibility"></a>

## 17. 兼容性与功能边界

- **客户端与内核组合**：面板按版本能力校验选项，并按订阅格式过滤不兼容节点。导入成功不等于客户端支持每一种协议参数。
- **Xray REALITY**：当前代码将 Xray 26.9.8 起的 REALITY 标记为需要 X25519MLKEM768 客户端能力，并提示 sing-box / Clash / mihomo 格式会跳过相关节点。需要兼容这些客户端时，按界面建议选择 sing-box 内核，或评估兼容的 Xray 版本；后续版本以能力提示为准。
- **Hysteria2**：使用 sing-box 或 Hysteria2 官方服务端；面板未开放 Xray 的 Hysteria2 入站。客户独立限速当前不支持 Hysteria2 入站。
- **sing-box 统计**：官方构建若未包含 `with_v2ray_api`，Agent 会跳过其按用户流量统计。需要此统计时使用包含该标签的兼容构建；可放到节点 `cores/singbox/<版本>/sing-box` 对应位置，或使用可信的自托管下载来源，并保留校验流程。
- **sing-box 出口组**：不支持面板中的轮询 / 随机负载均衡组合，按能力提示选择支持的策略。
- **HWID**：依赖 Happ、v2RayTun 等客户端在订阅请求中上报设备 ID，不能作为所有客户端的通用设备识别机制。
- **一键导入**：需要对应客户端已经安装，并且浏览器允许唤起应用；失败时使用 URL 手动导入。
- **Happ 路由头**：由支持该响应头的客户端使用，其他客户端不会自动获得相同效果。
- **规则模板**：使用 Go `text/template`，自定义模板需验证渲染后的目标客户端配置。

<a id="configuration"></a>

## 18. 配置与命令参考

### 环境变量

主控支持 `POLARIS_*` 环境变量，也可使用 `--config config.yaml` 指定配置文件。完整示例见 [deploy/polaris.env.example](../deploy/polaris.env.example)。

| 变量 | 用途 / 默认值 |
| --- | --- |
| `POLARIS_SECRET_KEY` | 必填，敏感字段加密与会话签名；至少 16 位随机字符，建议 `openssl rand -hex 32`；生成后持久保存，重启时复用 |
| `POLARIS_ADMIN_PATH` | 后台和管理 API 前缀，默认 `/` |
| `POLARIS_PUBLIC_URL` | 生成订阅、安装链接等使用的外部地址，包含 `http://` 或 `https://` |
| `POLARIS_LISTEN` | 面板 HTTP 监听，默认 `:8080` |
| `POLARIS_AGENT_LISTEN` | Agent mTLS 监听，默认 `:9443` |
| `POLARIS_AGENT_HOSTS` | Agent 使用的主控域名或 IP，写入服务端证书 |
| `POLARIS_DATA_DIR` | 数据目录，程序默认 `./data`；一键安装通常为 `/var/lib/polaris`，Docker 为 `/data` |
| `POLARIS_DB_DSN` | 设置 PostgreSQL DSN；未设置时使用数据目录中的 SQLite。从 SQLite 迁移见 `polaris migrate` |
| `POLARIS_REDIS_URL` | 可选。多个主控实例共享在线 IP（IP 数限制、在线设备）、订阅 / 网页商店限流和告警去重；单实例无需配置。Redis 不可用时自动退回各实例本机内存。流量计费不使用 Redis |
| `POLARIS_INITIAL_ADMIN_USERNAME` | 首次创建管理员的用户名 |
| `POLARIS_INITIAL_ADMIN_PASSWORD` | 首次创建管理员的密码；留空时生成并记录到启动日志 |
| `POLARIS_DECOY` | 非后台路径的处理，默认返回 404，也可反代到指定站点 |
| `POLARIS_SUB_RATE_LIMIT` | 每 IP 每分钟订阅请求限制，默认 30 |
| `POLARIS_TRUSTED_PROXIES` | 信任的反向代理 IP / CIDR，逗号分隔；默认本机与内网地址，部署时建议明确指定 |
| `POLARIS_LICENSE_SERVER` | 覆盖联网授权服务地址，按许可证提供方要求设置 |

一键安装环境修改配置文件后用 `polaris restart` 重启。Docker 修改环境文件后使用 `docker compose up -d` 重新创建受影响容器；只重启旧容器不会重新读取 Compose 的环境文件。

手动运行编译后的主控时，先在当前进程中加载配置环境，再执行 `./bin/polaris`。确保数据目录可写，且与其他实例不共用同一正在使用的数据库。切勿为已有数据库在每次启动时生成新的 `POLARIS_SECRET_KEY`。

### 一键安装命令速查

以下命令在服务器终端中执行。`polaris` 和 `polaris-ctl` 是管理工具，`polaris-server` 是主控程序。

| 命令 | 说明 |
| --- | --- |
| `polaris` | 打开交互式菜单 |
| `polaris start` / `polaris stop` / `polaris restart` | 管理主控进程 |
| `polaris info` / `polaris status` / `polaris log` | 查看信息、状态或日志 |
| `polaris doctor` | 系统诊断 |
| `polaris set-domain panel.example.com` | 配置主控域名和 HTTPS |
| `polaris set-sub-domain sub.example.com` | 配置独立订阅站点，还需在后台设置订阅域名 |
| `polaris set-path /my-admin` | 修改后台路径，之后使用新地址登录 |
| `polaris set-port 8443` | 修改面板 HTTP 端口，不等同于配置 HTTPS |
| `polaris set-url https://panel.example.com` | 修改生成链接使用的外部地址 |
| `polaris node` | 在主控本机安装节点 |
| `polaris check-update` / `polaris update` | 检查 / 升级主控 |
| `polaris switch community` / `polaris switch pro` | 切换版本类型，保留数据与配置 |
| `polaris backup` / `polaris restore FILE` | 创建 / 恢复备份；恢复会替换目标数据 |
| `polaris migrate sqlite\|local\|DSN` | 切换数据库并迁移全部数据（`local` 为本机自动安装的 PostgreSQL） |
| `polaris reset-password` / `polaris reset-2fa` | 重置管理员密码 / 关闭两步验证 |
| `polaris help` | 查看当前安装版本支持的全部命令 |

管理命令与安装方式相关。Docker 使用 Compose 和容器内的 `polaris` 程序；手动部署的 `polaris-server admin …`、`backup`、`restore` 等命令必须加载与服务相同的环境配置。
